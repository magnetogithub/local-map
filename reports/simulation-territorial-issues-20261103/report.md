# 국가 행동과 영토 변경 문제 분석 보고서

작성일: 2026년 11월 3일  
대상 프로젝트: Pax Local  
검토 기준: 사용자 제보 화면 4개, 로컬 실행 로그, 현재 활성 카탈로그, 관련 코드, 격리 재현  
산출물: 본 보고서와 [재현 및 로그 근거](evidence.json)

## 1 결론과 권고 방향

데이터 정리와 프롬프트 강화가 모두 필요하다. 데이터는 지역과 현재 세계 상태를 식별할 근거를 제공하고, GPT는 그 근거를 조회하면서 사용자의 표현과 세계 상황을 해석해야 한다. 여기에 군사 진격과 조약 양도를 구분하는 실행 도구와 결과 검증이 함께 갖춰져야 한다.

추천하는 구조는 **검증된 지역 데이터와 공간 조회 도구를 이용해 GPT가 능동적으로 판단하고, 호스트가 실제 지도 변경을 검증하는 방식**이다. 모든 세부 영토에 사람이 지명을 붙이거나 모든 이름을 지도에 표시하는 작업을 선행 조건으로 삼을 필요는 없다. 기존 영토 ID는 유지하고, 실제 지명과 행정 계층, 상대적 위치, 현재 소유권과 통제 상태를 조회할 수 있게 만드는 것이 우선이다.

이번 사례에서는 서로 다른 문제가 이어졌다. 청진은 도시 단위 검색 경로가 없어 찾지 못했다. 함경북도 점령은 도급 지역과 현재 전선을 찾았기 때문에 지도에 반영됐다. 함경북도 양도는 조회 이후 실행 조건을 만족시키지 못한 채 지도 변경 없는 부분 성공으로 확정됐다. 내몽골 반환은 지역 조회에는 성공했지만 결과 제출 검증을 두 번 통과하지 못했다.

따라서 수정은 다음 네 축으로 진행하는 것이 적절하다.

1. 지명과 행정구역 소속 정보를 정리하고 데이터의 지원 범위와 불완전성을 노출한다.
2. GPT가 모호한 공간 표현과 작전 의도를 해석하고 필요한 정보를 능동적으로 조회하도록 한다.
3. 군사 진격, 철수, 해방, 조약 양도를 각각의 조건으로 실행할 수 있게 한다.
4. 사건 서술, 행동 결과, 실제 영토 변경, 화면 표시가 일치하는지 검증한다.

## 2 라벨링과 프롬프트의 역할

여기서 라벨링은 세 가지로 구분해야 한다. 세부 영토의 고유 ID, 실제 지명을 검색하는 이름과 별칭, 지도 위에 보이는 글자는 서로 다른 기능이다.

| 항목 | 필요한 정도 | 권고 |
|---|---|---|
| 모든 세부 영토의 안정적인 고유 ID | 필수이며 현재 존재함 | 기존 ID와 게임 상태 연결을 보존 |
| 실제 지명의 표준 이름과 한영 별칭 | 필수 | 청진, Chongjin City, 내몽골, Inner Mongolia 등을 동일한 지리 개체로 연결 |
| 행정 계층과 실제 영토 ID의 연결 | 필수 | 국가, 도급 구역, 시군구, 세부 영토의 검증된 소속을 제공 |
| 생성된 모든 세부 영토의 개별 지명 | 선택 | 실제 지명이 없는 조각에 이름을 만들어 붙이지 않음 |
| 지도 화면의 모든 지명 상시 표시 | 선택 | 확대 수준과 선택 상태에 따라 필요한 이름만 표시 |
| 프롬프트의 지리 해석과 도구 사용 지침 | 필수 | 지명 검색, 상대적 공간 해석, 작업 선택과 재조회에 사용 |
| 프롬프트만으로 미확정 소속과 영토 ID 추정 | 채택하지 않음 | 지도 변경에는 검증된 카탈로그 참조와 현재 상태를 사용 |

보고서에서 권고하는 우선순위는 **기초 식별 데이터와 작업별 도구를 먼저 정리하고, 그 도구를 활용하는 GPT의 능동적인 판단을 강화하는 것**이다. 능동적 판단은 최종 기능의 핵심이며, 데이터 정리는 그 판단을 안정적으로 실행하기 위한 기반이다.

## 4 제보 사례와 실제 처리 흐름

화면의 사건 내용과 순서, 로그의 결과 유형을 기준으로 다음과 같이 대응했다. 로그 자체에는 각 요청의 원문 전체가 없다는 점을 전제로 한다.

| 사례 | 화면에서 확인한 내용 | 대응 로그 | 판단 |

| A 청진 요청 | 청진과 Chongjin을 찾지 못해 지리 검증 대기, 지도 변경 0건 | turn.1.0, 검색 실패 후 delayed, 영토 효과 0건 | 도시 검색 지원 누락 |

### 로그에서 확인한 단계

- turn.1.0: find_frontier_territories 실패, find_region 두 번 실패, verifiedFrontierLookups 0, territorialEffects 0, delayed.
- turn.2.1: find_frontier_territories 성공, verifiedFrontierLookups 1, territorialEffects 1, succeeded.
- turn.3.2: 초기 지역 조회 실패 뒤 find_region과 resolve_region 성공. 첫 제출은 INVALID_SCHEMA. 이후 지역 참조와 이름의 동시 지정 오류, REGION_COUNTRY_SCOPE 발생. 최종 결과는 partially_succeeded이며 영토 효과는 0건.
- turn.4.3: 초기 조회 실패 뒤 find_region과 resolve_region 성공. 이후 제출 검증이 두 번 INVALID_SCHEMA로 실패.
- REPAIR_FAILED는 공급자 코드가 첫 제출 실패 후 보정된 제출도 실패했을 때 반환한다.

사례 B의 영토 효과 1건은 영토 1개라는 의미가 아니다. 하나의 효과에 여러 영토 ID가 들어갈 수 있으며, 화면의 7개 영토 점령과 양립한다.

## 5 현재 시스템의 처리 구조

~~~mermaid
flowchart TD
  A["플레이어 행동과 현재 세계 맥락"] --> B["GPT의 사건 및 공간 해석"]
  B --> C["지명과 지역 조회"]
  B --> D["현재 전선 조회"]
  C --> E["TurnResolution 제출"]
  D --> E
  E --> F["참조와 인과관계 및 영토 효과 검증"]
  F --> G["원자적 턴 반영"]
  G --> H["사건 뉴스와 행동 결과"]
  G --> I["소유권과 통제권 변화"]
  I --> J["지도 색상과 점령 전선"]
~~~

현재는 점령, 해방, 소유권 양도에 모두 전선 선택 결과를 요구한다. 반면 영토 효과가 없는 resolution은 그 전선 검증을 거치지 않는다. 이 조합 때문에 실행이 어려운 양도가 지도 변경 없는 사건 기록으로 축소될 수 있다.

지도는 사건 제목의 종전이라는 단어를 읽어 점령선을 지우지 않는다. 현재 ownerCountryId와 controllerCountryId를 이용한다. 소유국과 통제국이 다르면 점령으로 표시하고, 이 점령 상태를 포함한 서로 다른 통제국의 경계에 금색 점선을 표시한다.

## 6 문제별 원인과 영향

### F01 청진을 검색할 수 있는 하위 지역 인덱스가 없다

**확인 사항**

현재 지역 인덱스는 catalog.administrativeParents를 기준으로 생성된다. 북한은 도급 행정구역 11개와 미분류 구역 1개가 검색 대상이다. 실제 검색 함수를 실행한 결과는 다음과 같다.

| 검색어 | 결과 |
|---|---|
| 청진 | 없음 |
| Chongjin | 없음 |
| Chongjin City | 없음 |
| 함경북도 | 1개 지역, 소속 영토 16개 |
| North Hamgyong | 같은 지역, 소속 영토 16개 |

원본 북한 ADM2 파일에는 Chongjin City가 존재한다. 원본 feature ID는 82179303B21659587132529다. 따라서 이 사례는 한글 별칭 하나만 추가해서 해결할 수 있는 문제가 아니다. 도시 개체를 런타임 영토 ID에 연결하는 경로가 필요하다.

**영향과 수정 방향**

청진 지시를 함경북도 전체로 바꾸면 사용자가 지정한 범위가 달라진다. 원본 시군구 개체와 현재 세부 영토의 검증 가능한 소속을 연결하고, 청진과 영문 표기를 같은 개체로 검색하도록 해야 한다. 도시와 세부 영토가 정확히 일치하지 않으면 실제 지원 범위와 근사 여부를 반환해야 한다.

근거: [지역 인덱스](../../src/lib/simulation/operational-region.server.ts), [북한 원본](../../data/raw/prompt19/PRK/normalized-adm2.geojson), evidence.json의 searchProbes와 sourceChongjin.

### F02 내몽골의 한국어 이름과 별칭이 부족하다

**확인 사항**

내몽골 검색은 결과가 없지만 Inner Mongolia 검색은 48개 영토를 포함하는 지역 하나를 반환한다. 해당 레코드는 nameKo도 Inner Mongolia이며 aliases에는 같은 영문 이름만 들어 있다. Nei Mongol과 Neimenggu도 현재 검색에서는 결과가 없다.

**영향과 수정 방향**

GPT가 다른 표기를 추론해 재검색하면 지역을 찾을 수 있다. 실제 내몽골 요청에서도 재조회 후 지역 조회는 성공했다. 그러나 동일 지역에 접근하기 위해 불필요한 호출이 늘고, 지역을 찾지 못한 것으로 잘못 결론 낼 가능성이 생긴다.

검증된 지역별 이름과 별칭을 관리하고 검색 정규화를 적용한다. GPT는 의미를 해석하고 표기 후보를 제안하되, 최종 지역 참조는 검색 도구에서 받아야 한다. 동명이거나 여러 후보가 있으면 현재 국가와 사건 맥락을 함께 사용한다.

근거: [지역 이름과 검색 구현](../../src/lib/simulation/operational-region.server.ts), evidence.json의 searchProbes.

### F03 행정구역 소속 데이터의 불완전성이 도구에 충분히 드러나지 않는다

**확인 사항**

현재 중국 계층 자료의 요약은 원본 세부 개체 2864개 중 1663개 소속 확정, 1201개 미확정이다. 이는 원본 개체 수이며 런타임 영토 수와 같은 단위가 아니다. 원본 자료의 정책은 미확정 개체를 기존 미분류 구역으로 유지하도록 명시한다.

현재 런타임에서 중국과 몽골 사이의 양의 길이 인접 관계는 36쌍이다. 그 중국 측 영토 29개는 모두 CHN administrative parent unconfirmed / source-free baseline land에 속한다. Inner Mongolia로 검색되는 48개 영토에서는 몽골과의 양의 길이 인접 관계가 0개다.

따라서 중국과 몽골의 국경 연결 전체가 없다고 판단해서는 안 된다. 현재 내몽골 이름으로 확인되는 영토 집합과, 중국·몽골 국경에 있는 미분류 영토 집합 사이에 행정 소속 정보의 공백이 있다. 이 관측만으로 해당 국경 영토 29개를 모두 내몽골로 배정할 수도 없다.

**영향과 수정 방향**

지역 검색이 성공해도 사용자가 말한 행정구역 전체를 표현한다는 보장은 별도로 필요하다. 현재 RegionRecord와 find_region 응답에는 이런 완전성 상태가 없다.

지역 도구에 소속 검증 범위, 미확정 여부, 시점과 출처를 제공해야 한다. 행정구역 전체 양도를 요청받으면 전체 범위를 검증할 수 있는지 먼저 확인해야 한다. 불완전한 집합을 전체 지역으로 서술하거나, GPT의 지식과 중심점만으로 미확정 영토의 소속을 채워서는 안 된다. 소속 보완은 검증 가능한 원본 계층과 경계 근거를 확보하는 별도 데이터 작업이다.

근거: [중국 계층 자료](../../data/source-locks/chn-2020/CHN-hierarchy.json), [지역 계약](../../src/lib/simulation/catalog-region.ts), evidence.json의 hierarchyInspection과 frontierReproduction.adjacency.

### F04 조약에 따른 양도에도 군사 진격의 전선과 거리 제한을 적용한다

**확인 사항**

operational-frontier는 transfer에서도 양도국 소유의 영토를 수령국 통제 영토와 연결된 접경에서 선택한다. 이후 near, limited, deeper의 거리, 폭, 면적 제한을 적용한다. 효과 검증기는 양도에도 frontierScope와 조회 결과 전체의 정확한 일치를 요구하고, 도 전체의 regionRefs로 교체하는 것을 거부한다.

격리된 메모리 세계에서 함경북도 16개 영토 중 5개에 중국 통제를 적용한 뒤 북한에서 중국으로 양도를 조회한 결과는 다음과 같다.

| 범위 | 선택 영토 수 | 전체 16개와 일치 | 기존 점령 영토 중 포함 수 |
|---|---:|---|---:|
| near | 1 | 아니오 | 0 |
| limited | 5 | 아니오 | 1 |
| deeper | 11 | 아니오 | 1 |

이 재현의 초기 점령은 5개다. 사용자 화면의 7개 점령을 그대로 복원한 결과가 아니며, 같은 규칙의 구조적 문제를 확인하기 위한 별도 재현이다.

내몽골 48개 영토를 중국에서 몽골로 양도하는 조회는 세 범위 모두 NO_CURRENT_LAND_FRONTIER를 반환했다. F03의 행정 소속 공백과 현재 도구의 접경 조건이 함께 작용한다.

**영향과 수정 방향**

도 전체의 조약 양도와 현재 점령지의 귀속 확정이 군사 진격용 선택으로 대체된다. 범위를 키워도 요청한 전체와 일치하지 않을 수 있고, 이미 점령한 영토를 양도 집합에서 놓칠 수도 있다.

조약 양도에는 별도 범위 선택과 검증을 제공해야 한다. 지정된 지역 또는 명시된 영토 집합 전체에 대해 현재 소유권, 당사자, 권한, 카탈로그와 revision, 합계 상한을 확인한다. 수령국과의 접경이나 진격 거리를 일괄 요구하지 않는다. 군사 진격의 물리적 제한과 512개 영토 상한은 필요한 경로에 계속 유지한다.

### F05 양도 당사자와 지리 분류 기준이 혼동되기 쉽다

**확인 사항**

현재 transfer의 actorCountryId는 영토를 넘기는 현재 소유국이고 targetCountryId는 수령국이다. 지역 조회는 이 actorCountryId를 지역의 원본 국가 분류와도 대조한다. 점령에서는 actor가 진격국이므로 같은 필드의 실제 역할이 작업마다 달라진다.

함경북도 양도 로그에는 REGION_COUNTRY_SCOPE가 기록돼 있다. 전체 인수를 저장하지 않았으므로 실제로 어느 국가가 잘못 들어갔는지는 확정할 수 없다.

또한 한 번 다른 국가에 양도된 지역은 원본 지리 분류와 현재 소유국이 달라진다. 이를 다시 양도할 때 현재 양도국을 원본 지역 조회 국가로 그대로 사용하면 합법적인 게임 상태에서도 지역 조회가 막힐 수 있다.

**수정 방향**

플레이어 또는 사건의 제안자, 현재 양도국, 수령국, 지역의 원본 분류 국가를 구분한다. 예를 들어 함경북도의 북한에서 중국으로의 최초 양도는 양도국 PRK, 수령국 CHN이다. 내몽골의 중국에서 몽골로의 반환은 양도국 CHN, 수령국 MNG다.

반환이라는 단어만으로 해방 효과를 선택해서는 안 된다. 현재 소유권을 유지하면서 점령 통제만 되돌리는 경우와 소유권 자체를 다른 국가로 넘기는 경우를 현재 상태로 구별한다.

지역 reference와 regionQuery를 동시에 제출한 오류도 실제 로그에 있었다. 검증된 참조를 받은 후에는 그 참조를 사용하는 일관된 도구 흐름과 입력 계약을 제공해야 한다.

### F06 디버그 지시와 필수 지도 변경의 일치를 강제하지 않는다

**확인 사항**

디버그 모드는 서버의 개발 환경 및 PAX_SIMULATION_DEBUG_MODE 설정과 정확한 DEBUG_WORLD_EFFECT 접두어 조건을 사용한다. 화면의 접두어만으로 실제 서버 플래그 활성화를 확정할 수는 없다.

현재 지침은 표시된 디버그 행동의 결과와 대응 효과를 생성하라고 요구하지만, 디버그 예외는 주로 서사적 권한 존재 조건을 면제한다. 지역 조회와 전선 범위 검증은 그대로 남는다. 프롬프트의 성공 지시가 실행 불가능한 공간 계약을 해결하지는 못한다.

실제 검증기에 즉시 영토 이전 완료를 서술하는 디버그 진단 입력을 제출했을 때, worldEffects가 비어 있어도 succeeded와 partially_succeeded 모두 통과했다. 이는 제보 턴의 실제 결과를 재생한 것이 아니라 검증기의 공백을 확인한 별도 진단이다. 실제 함경북도 양도 턴에서 관측한 상태는 partially_succeeded와 영토 효과 0건이다.

청진 요청처럼 기술적인 조회 실패가 delayed 결과로 확정되면 날짜가 진행되고 해당 행동은 resolved가 된다. 현재 계획 코드가 이런 결과를 유효한 턴으로 처리한다.

**영향과 수정 방향**

기술적 처리 실패가 세계 안에서 발생한 협상 지연이나 부분 성공으로 기록될 수 있다. 사용자는 디버그로 즉시 결과를 지정해도 조약 체결만 성공한 것으로 읽게 된다.

의도 해석 단계에서 실제 이전 완료, 조약 서명, 향후 이행 예정 등을 구조적으로 구분하고, 필요한 영토 효과와 대응시키는 검증이 필요하다. 필수 이전 효과가 빠진 결과는 수정 대상이어야 한다. 해결할 수 없는 기술적 선행 조건은 commit 전에 명확한 실패로 반환해 날짜와 행동을 보존하는 정책을 권고한다.

일반 플레이에서 실제 협상만 성사되거나 군사 시도가 지연되는 판정은 허용해야 한다. 모든 성공 사건에 무조건 지도 효과를 요구하는 규칙은 적절하지 않다.

### F07 종전과 점령 해소 및 영토 귀속이 별도 상태다

**확인 사항**

현재 전쟁 화면의 projection은 dataAvailable false이며 전쟁 도메인 연결 예정 상태다. 시뮬레이션 사실에는 conflict-or-war 종류가 있지만, 전쟁 화면에 연결된 명시적 전쟁 종료 및 정산 흐름은 확인되지 않는다.

지도 점령 여부는 소유국과 통제국의 차이로 계산한다. 따라서 종전 사건만 추가하면 기존 점령 표시가 유지될 수 있다. 이는 게임의 상태 모델상 가능한 결과다. 다만 즉시 양도까지 성립했다고 판정했다면 소유권 변경이 추가로 필요하다.

| 사건의 의미 | 관련 영토의 기대 상태 |
|---|---|
| 종전 또는 휴전만 성립 | 별도 조건이 없으면 기존 소유권과 통제권을 자동 변경하지 않음 |
| 철군 및 원상회복 | 합의된 대상의 통제를 기존 소유국으로 되돌림 |
| 함경북도를 중국에 즉시 양도 | 검증된 대상의 소유국과 통제국을 중국으로 정산 |
| 양도 조약 서명과 추후 이행 | 서명과 이행 시점을 구분하고 후속 조건 또는 예정 사건을 기록 |

**수정 방향**

종전, 철수, 점령지 반환, 영토 양도, 이행 예정의 의미를 분리한다. 기존 사실과 사건에서 결정된 조건을 실제 상태 효과로 연결하고, 전쟁 화면도 그 상태를 읽도록 한다. 지도에서 점선만 숨기는 처리는 소유권 문제를 남기므로 피해야 한다.

### F08 실제 오류 원인과 재시도 가능 여부가 사용자에게 전달되지 않는다

**확인 사항**

컨텍스트 검증기는 JSON 파싱, 카탈로그와 전선 검증, 지역 처리 중 발생한 예외를 INVALID_SCHEMA와 경로 $로 묶는다. 서버 로그는 검증 이슈의 code와 path만 기록하므로 원래 message가 사라진다. REPAIR_FAILED 메시지에도 코드와 경로 요약만 남는다.

클라이언트 상태 변환은 turn.failed의 errorCode만 보존하고 message와 retryable을 저장하지 않는다. 실제 상태 변환 진단에서도 두 정보가 모두 사라졌다. 화면의 Retry 표시 조건은 서버의 retryable false를 사용하지 않고 실패 또는 취소 상태를 기준으로 계산한다.

**수정 방향**

구문 오류, 지역 미지원, 데이터 범위 불완전, 국가 역할 불일치, 효과 누락, 전선 부재를 구별해야 한다. 개발 로그에는 비밀값과 원문 전체 대신 안전한 구조화 사유를 남기고, 사용자에게는 해석 가능한 한국어 원인을 제공한다. 서버가 정한 재시도 가능 여부와 입력 수정 필요 여부를 화면에 전달한다.

현재 내몽골 제출의 정확한 실패 필드는 로그만으로 특정할 수 없다. 확인 가능한 결론은 지역 조회 이후 제출 검증이 두 번 실패했다는 점이며, F03~F05는 별도 재현과 코드로 확인한 구조적 장애다.

### F09 실패한 요청 아래에 직전 확정 턴 결과가 계속 표시된다

**확인 사항**

서버 세션은 resolution.ready가 발생해 commit할 때 report를 갱신한다. 실패 시 기존 report를 유지하며, 화면은 그 report가 있으면 계속 표시한다. 내몽골 실패 화면의 2020-03-01부터 2020-03-31 결과는 직전 함경북도 관련 턴이다.

**수정 방향**

마지막 확정 결과를 보존하는 동작은 유용하다. 표시 제목을 마지막 확정 턴 결과로 바꾸고, 이번 실패한 요청은 반영되지 않았다는 안내와 요청 내용을 별도 표시해야 한다. 실패 결과와 이전 결과의 관계를 명확히 설명한다.

## 7 모호한 표현을 처리하는 방식

지역 이름만 정확히 맞춰야 하는 게임으로 설계하면 실제 플레이를 충분히 지원하지 못한다. GPT가 표현을 공간적 의도로 해석하고, 조회 도구가 그 의도에 맞는 기존 영토와 경계를 반환하게 해야 한다.

| 표현 | GPT가 해석할 내용 | 도구가 확인할 내용 |
|---|---|---|
| 북한 북부 | 국가 내부의 북쪽 영역인지 북쪽 접경 작전인지, 앞선 전황과의 관계 | 해당 국가의 공간 범위, 상대적 북쪽 위치, 현재 통제와 접근 가능한 전선 |
| 휴전선 경계 또는 인근 | 시나리오 기준 휴전선인지 최근 합의된 선인지 | 버전이 있는 기준선 또는 그 근사, 양측 영토와 거리 범위 |
| 현재 전선에서 더 진격 | 최근 작전의 행위국과 상대국, 진격 정도 | 현재 통제선, 이미 점령한 영토, 인접성과 물리적 제한 |
| 함경북도 전체 양도 | 정확한 행정구역 전체의 소유권 이전 | 지역 소속의 완전성, 현재 소유국, 수령국, 권한과 효과 상한 |
| 점령한 땅을 반환 | 어떤 전쟁과 당사자의 점령인지, 통제 복귀인지 소유권 이전인지 | 해당 점령 집합의 현재 owner와 controller 및 합의 대상 |
| 몽골에게 내몽골 반환 | 현재 중국 소유 지역을 몽골에 넘기는 의미 | 현재 소유권과 지역 참조, transfer의 당사자와 전체 범위 |

### 국가의 북부와 전선의 북쪽을 구분한다

현재 도구의 direction north는 현재 전선의 어느 부분을 우선할지 정하는 값이다. 이 값 하나가 국가 전체의 북부라는 지리적 범위를 표현하지는 않는다.

상대적 위치에는 기준 공간이 필요하다. 국가 전체, 특정 도, 현재 전선, 초기 접경선 중 어디를 기준으로 하는지 해석 결과에 포함해야 한다. 북부를 정하는 세부 기준도 명시적인 호스트 정책으로 제공하고, 카탈로그의 해상도에 따른 근사임을 설명한다. 프롬프트에서 고정 위도나 임의의 영토 비율을 만들게 해서는 안 된다.

### 휴전선과 현재 전선의 기준을 보존한다

점령 후에는 초기 접경선과 현재 통제선이 달라질 수 있다. 휴전선은 시나리오의 참조선 또는 새로 체결된 합의선을 가리킬 수 있고, 현재 전선은 지금의 통제 관계를 가리킨다.

실제 휴전선의 검증된 별도 자료가 없을 때 초기 국가 접경을 정확한 역사적 휴전선이라고 단정해서는 안 된다. 도구는 기준의 출처, 시나리오 시점과 근사 여부를 반환해야 한다.

### 모호할 때의 기본 동작

맥락이 한 해석을 충분히 뒷받침하고 소규모 범위를 정할 수 있으면 GPT가 해석을 선택해 진행한다. 결과에는 선택한 기준과 범위를 짧게 밝힌다. 의미가 모호하다는 이유만으로 매번 사용자에게 되묻는 흐름은 피한다.

서로 다른 국가나 현저히 다른 규모의 결과가 가능하고 맥락으로 구별할 수 없으면, 사용자에게 필요한 확인을 요청하거나 해당 행동을 명확한 사유와 함께 보류한다. 반면 원본 소속 누락이나 도구 계약 오류는 해석의 모호함과 구분해 기술적 선행 조건으로 표시해야 한다.

## 8 GPT가 스스로 사건과 작전 범위를 판단하는 방식

GPT가 플레이어의 문장을 지도 명령으로 일대일 변환하는 구조로 제한될 필요는 없다. 시간 진행 중 국가의 목표, 기존 전황, 활성 사실, 예정된 결과와 상대국 반응을 바탕으로 사건을 전개할 수 있다.

예를 들어 플레이어가 북한 침공이라는 큰 의도를 제시했다면, 세부 진격 지점과 일부 점령, 철수, 협상 가능성을 맥락 안에서 판단할 수 있다. 다른 국가도 기존 상태와 사건의 원인 관계 안에서 대응할 수 있다. 이때 플레이어가 하지 않은 별도의 결정을 임의로 만들어내는 것은 구분해야 한다.

권고하는 판단 흐름은 다음과 같다.

1. 현재 사실과 목표, 최근 사건, 예정 결과를 읽는다.
2. 진격, 철수, 협상, 조약 체결, 이행 등 가능한 전개를 판단한다.
3. 영토 변경이 필요한 전개라면 공간적 의도와 작업 종류를 정한다.
4. 지역과 현재 세계 상태를 조회하고, 필요한 경우 후보 범위를 비교한다.
5. 군사적 성공 가능성과 정치적 성립 여부를 지리 검증과 별도로 판정한다.
6. 날짜가 있는 원인 사건과 그 결과에 대응하는 상태 효과를 제출한다.
7. 호스트는 범위와 인과관계, 현재 상태를 검증한 뒤 한 턴으로 반영한다.

지리 도구가 반환한 영토는 변경 가능한 후보이며, 군사적 승리나 조약 성립을 보장하지 않는다. 반대로 도구가 실패했다는 사실만으로 전쟁에서 패배했다고 서술해서도 안 된다.

프롬프트에는 관련 조회의 우선순위, 이미 확인한 정보의 재사용, 오류에 맞춘 입력 보정, 정당한 대체 해석의 범위를 넣어야 한다. 도구 한계가 있는 상황에서 같은 요청을 반복하거나 목표를 조용히 다른 지역으로 바꾸는 동작은 막아야 한다.

### 데이터 계층

기존 영토 ID를 바탕으로 지리 개체, 표준 이름, 별칭, 행정 계층, 영토 소속, 근거와 지원 범위를 관리한다. 원본 분류와 현재 소유국 및 통제국은 분리한다. 모호한 표현을 위해 상대 위치와 기존 경계 참조를 조회할 수 있게 한다.

지역 데이터는 현재 활성 카탈로그와 실제 사용 시나리오부터 보완한다. 전 세계 미세 경계를 한꺼번에 재생성하거나 근거 없는 행정 소속을 붙이는 작업은 요구하지 않는다.

### 공간 의도와 조회 계층

GPT는 이름이 있는 지역뿐 아니라 방향, 경계 인근, 현재 전선, 기존 점령 집합과 그 교집합을 표현할 수 있어야 한다. 도구는 실제 영토를 결정하고 카탈로그, 세계 revision, 선택 정책, 데이터 완전성, 근사 여부와 조건을 반환한다.

이 공간 의도는 앞으로 추가할 계약이며 현재 구현돼 있다는 의미는 아니다. 모델이 임의의 좌표와 다각형, 최종 영토 ID를 생성하는 경로는 열지 않는다.

### 작업별 실행 계층

- 군사 진격은 현재 전선과 연결된 제한된 범위를 사용한다.
- 철수와 통제 복귀는 합의된 현재 점령 집합을 사용한다.
- 소유권 양도는 검증된 지역 또는 합의된 영토 집합의 현재 소유권을 검사한다.
- 종전은 전쟁 상태와 합의 조건을 변경하며 영토 정산은 해당 조건에 따라 별도로 수행한다.

작업 종류별 선택 결과에는 호스트가 다시 검증할 수 있는 근거가 필요하다. 기존 frontierScope를 무조건 제거해 검증을 우회하는 방식은 채택하지 않는다.

### 결과 검증과 표시 계층

즉시 이전 완료와 같은 결과에는 필요한 상태 효과가 포함돼야 한다. 반영 후에는 실제 세계 변경과 선택 범위를 기준으로 점령 면적, 영토 수, 소유권 이전을 표시한다. 서명만 성립한 경우에는 이행 전 상태임을 명시한다.

기존 원자적 commit, revision 검사, 카탈로그 일치 검사, 인과관계 검사, 권한 범위, undo와 redo를 유지한다. 기술 실패에 따른 반영 중단과 정상적인 게임 내 지연은 구분한다.

## 10 수정 우선순위

P1은 현재 제보된 행동 흐름을 안정화하기 위해 먼저 처리할 항목이고, P2는 같은 수정 범위에서 이어서 개선할 항목이다. 순서는 조사와 작은 검증 단위로 진행하는 것을 전제로 한다.

| 순서 | 우선순위 | 작업 | 완료 기준 |
|---|---|---|---|
| 1 | P1 | 오류 사유와 작업 추적 정보 보존 | 정확한 실패 단계와 수정 가능한 조건이 로그와 화면에 표시됨 |
| 2 | P1 | 양도 전용 선택과 검증 도입 | 접경 진격 규칙과 독립적으로 합의된 전체 집합을 검증 |
| 3 | P1 | 양도국과 수령국 및 원본 분류 분리 | 함경북도 양도와 양도 후 재양도가 같은 역할 규칙으로 동작 |
| 4 | P1 | 지역 소속 완전성 표시 | 전체 지역을 지원하는지 확인하고 불완전한 집합의 전체 양도를 막음 |
| 5 | P1 | 의도와 필수 효과의 결과 검증 | 즉시 이전 완료 서술에 실제 이전이 빠지면 수정 또는 명확한 실패 |
| 6 | P1 | 공간 의도와 GPT 조회 흐름 강화 | 북부, 기준선 인근, 현재 전선, 기존 점령 집합을 구분해 조회 |
| 7 | P2 | 청진 하위 지역과 내몽골 별칭 지원 | 한영 이름이 같은 검증된 지역을 반환 |
| 8 | P2 | 종전 및 정산과 전쟁 화면 연결 | 종전, 철수, 양도, 이행 예정이 상태와 화면에서 구분됨 |
| 9 | P2 | 이전 report와 현재 실패 구분 및 Retry 정책 반영 | 마지막 확정 결과와 이번 요청의 미반영 상태가 명확함 |

데이터와 프롬프트는 이 순서 안에서 함께 조정해야 한다. 예를 들어 공간 의도 프롬프트를 강화하려면 도구가 해당 의도와 지원 범위를 표현할 수 있어야 한다. 실제 데이터 누락이 확인된 지역은 작업 도구 개선과 별도로 근거를 확보해 소속을 보완한다.

| NPC가 자율적으로 전개한 사건 | 기존 사실과 원인 관계를 갖추고 필요한 효과를 검증 |
| 점령 후 함경북도 전체 양도 | 검증된 전체 합의 범위를 이전하고 점령 표시를 정산 |
| 현재 점령한 일부만 귀속 확정 | 기존 점령 집합과 정확히 일치하고 다른 영토를 추가하지 않음 |
| 내몽골을 몽골에 양도 | 전선 접경 여부와 독립적으로 범위를 검증하며 불완전성은 명시 |
| 다른 나라로 양도된 지역 재양도 | 원본 분류와 현재 소유국이 달라도 올바르게 처리 |
| 종전만 성립 | 별도 영토 조항 없이 소유권을 자동 이전하지 않음 |
| 서명 후 추후 이행 | 서명과 이행 사건 및 날짜를 구분 |
| 디버그 즉시 이전 결과에서 효과 누락 | 완료 판정을 거부하고 수정 또는 명확한 실패 |
| 일반 협상 성공과 군사 실패 | 필요한 경우 지도 효과 0건도 정상적인 게임 결과로 허용 |
| 512개 초과, stale revision, 잘못된 참조 | 조용히 잘라 반영하지 않고 원자적으로 거부 |
| 반환 실패 화면 | 구체적 원인과 재시도 조건, 마지막 확정 report를 구분 |
| 이전 완료 후 undo와 redo | 사건, 날짜, 소유권, 통제권, 지도 표시가 함께 복원 |

기존 테스트를 이번에 새로 작성하지는 않았다. 위 표는 앞으로 구현 변경을 검증할 인수 조건이다. 결정적인 범위 선택과 상태 변경은 도구 및 호스트 테스트로 검증하고, 여러 표현을 해석하는 능력은 별도의 GPT 평가 시나리오로 검증하는 것이 적절하다.

## 12 이번 분석에서 수행한 검증

다음 기존 테스트를 실행해 5개 파일, 54개 테스트가 모두 통과했다. Vitest가 보고한 실행 시간은 8.44초다.

~~~powershell
npm.cmd test -- src/lib/simulation/operational-region.test.ts src/lib/simulation/operational-frontier.test.ts src/lib/simulation/operational-territorial-runtime.test.ts src/lib/simulation/server/operational-provider.test.ts src/components/game/GameActionOverlay.test.tsx
~~~

기존 테스트 통과는 이번 문제의 해결을 의미하지 않는다. 하위 지역 검색 누락, 조약 양도의 전체 범위, 미확정 행정 소속, 디버그 필수 효과 누락 등은 별도의 격리 진단에서 계속 재현됐다.

격리 진단에서는 저장소의 TypeScript 모듈을 메모리에서 변환해 실제 함수들을 호출했다. server-only는 기존 Vitest 설정과 같은 빈 모듈에 연결했다. 현재 카탈로그를 읽고, 초기 소유국과 통제국을 원본 국가로 둔 별도 세계를 메모리에 만들어 전선 선택을 검사했다.

확인된 주요 결과는 다음과 같다.

- 청진 계열 검색 0건, 함경북도 한영 검색은 같은 지역 1건과 16개 영토.
- 내몽골 한국어 검색 0건, 영문 검색은 지역 1건과 48개 영토.
- 함경북도 격리 양도 선택은 1개, 5개, 11개로 전체 16개와 불일치.
- 내몽골 격리 양도 선택은 세 범위 모두 NO_CURRENT_LAND_FRONTIER.
- 중국과 몽골의 전체 인접 관계는 36쌍이며 중국 측 29개 영토는 행정 소속 미확정.
- 지도 이전 완료를 서술하는 진단 resolution이 영토 효과 없이도 성공과 부분 성공 상태로 검증 통과.
- 클라이언트 실패 상태에서 상세 메시지와 retryable 정보가 사라짐.

## 13 분석의 한계와 보존 사항

이 보고서에서 마지막 내몽골 제출의 정확한 위반 필드를 단정하지 않는다. 로그가 상세 message와 전체 도구 인수 및 제출 값을 보존하지 않아 해당 값은 확인할 수 없었다. 실제 서버의 디버그 활성화 플래그도 별도로 읽지 않았다.

사용자 게임의 전체 snapshot과 모든 undo 이력을 직접 추출하거나 변경하지 않았다. 사용자 화면의 점령 7개와 격리 재현의 점령 5개를 혼동하지 않았다. 현재 지역 인덱스의 48개 영토가 역사적 또는 법적 내몽골 전체와 일치한다고 인증하지 않는다.

이번 작업은 보고서와 근거 파일 작성에 한정했다. 애플리케이션 소스, 테스트 소스, 활성 카탈로그 포인터와 지도 자료를 수정하지 않았고, 서버 재시작과 실제 AI API 호출, 배포, 세계 데이터 재생성을 하지 않았다.

향후 카탈로그 또는 소속 자료를 변경할 때도 기존 영토 ID와 세션의 카탈로그 참조, 현재 소유권과 통제권, 전체 undo 및 redo 이력을 보존하는 절차가 필요하다. 현재 상태를 원본 국가의 초기 소유권으로 재구성해서는 안 된다.

## 14 근거 파일 안내

[evidence.json](evidence.json)은 다음 항목을 포함한다.

- 현재 카탈로그 참조와 핵심 소스 파일 해시.
- 실제 지역 검색 결과와 청진 원본 개체.
- 함경북도 양도 및 내몽골 반환의 격리 재현 결과.
- 중국과 몽골 접경의 행정 소속 분류와 중국 계층 자료 요약.
- 영토 효과 누락에 대한 실제 검증기 진단.
- 클라이언트 오류 정보 유실 진단.
- 관련 서버 로그 19건의 정리된 payload와 원본 행 번호.
- 기존 테스트 실행 명령과 통과 결과.

설계 변경 시 함께 참고할 기존 계약은 [GPT 턴 런타임 ADR](../../docs/simulation/gpt-turn-runtime-v1.md)이다. 모델의 임시 서술과 확정 상태를 구분하고, 호스트 검증과 한 턴 단위 원자적 반영을 유지한다는 원칙을 보존해야 한다.
