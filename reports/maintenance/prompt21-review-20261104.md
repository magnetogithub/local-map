발견한 P2 문제는 [run-verification.mjs](../../scripts/workspaces/run-verification.mjs)의 성공 판정이다. 기존 코드는 `it.skip` 하나를 수집했을 때 total 1·passed 0·pending 1이어도 `passed`와 종료 0을 반환했다. 수집 수가 양수이고 통과 수와 같으며 pending·todo가 모두 0일 때만 성공하도록 보완했다. 같은 skip 사례와 todo 사례가 수정 후 각각 `failed`·종료 1로 거부됐다. 임시 probe는 제거했고 소스·명령·실행 결과·hash는 로컬 근거에 보존했다.

전선·원본·설치 검증에서는 실제 전선의 소비 입력 5,828개와 고유 보호 파일 308개의 SHA-256·크기가 모두 같았다. KOR·PRK·CHN의 원본 전선 결과는 실행 3·통과 3·누락 0이며 commit·undo·redo마다 선택 밖 객체 보존이 기록돼 있다. 해당 결과는 전체 소비 입력의 identity를 확인해 재사용했다. 이번 재검증의 새 턴 실행 수로 합산하지 않는다.

두 작업트리의 LFS payload는 각각 42개·1,329,106,273바이트가 oid·크기와 일치했다. 직접 의존성 각각 27개가 lockfile 버전과 같고, 두 lockfile의 hash도 같다. node_modules는 symlink가 아닌 독립 디렉터리이며 직접 패키지 파일의 inode 공유도 없었다. LFS filter가 없는 역사적 `.lfs.txt` 영수증은 일반 추적 파일로 구별했다.

메인 변경 연습은 실제 B2 커밋의 검증 이름 중복 거부 규칙, 준비 브랜치의 정상 fast-forward, H1의 `HANDOFF_REVALIDATION`과 H2의 양쪽 `accepted-unassigned` 결과를 원본 로그와 대조했다. 원래 준비 자료 154바이트와 hash는 유지됐다. 이 검증에서는 기존 연습 근거를 재사용했다.

수정 후 동시 실행의 configured Vite cache 쓰기 관측은 0이었다. 실제 module-cache·OS 임시 파일·결과 쓰기의 관측 경로와 호출자를 격리 근거로 삼았다. 이번 변경은 개발 검사 도구의 성공 판정이며 관련 검사는 위 표에 기록했다. 기존 Next build·API·브라우저 근거와 이번 실행 결과는 분리해 관리한다.

현재 병렬 작업 가능 범위는 메인 공통 개선과, 실제 대상국 지정 후 국가 준비 공간의 원본·계층·이름 자료 준비다. 대상국은 여전히 null이다. 국가 adapter·증분 발행 일반화, 전역 조립·활성 전환, 신규 국가 실제 플레이 검증은 전체 계획의 후속 4~6번이다.
