# 세부 프로빈스 객체 독립성과 국가 추가 작업 병렬성 분석

작성일: 2026년 11월 3일  
대상: 현재 활성 카탈로그의 한국 KOR, 북한 PRK, 중국 CHN  
근거: 실제 카탈로그와 새 메모리 게임의 진단, 관련 코드, 기존 테스트  
관련 자료: [실제 데이터 진단](evidence.json), [테스트와 추가 검증](verification.json), [재현 코드](audit.cjs)

## 1 핵심 결론

**세 나라의 세부 영토는 개별 상태 객체로 정상 동작한다.** 각 영토에는 고유 ID와 독립적인 소유국 및 통제국이 있다. 실제 카탈로그에서 한 영토만 점령하거나 해방하고 소유권을 이전해도 같은 행정 부모의 다른 영토는 변경되지 않았다. 실제 전선 조회를 거친 턴의 반영, undo, redo도 세 나라 각각에서 확인했다.

**국가 추가 작업은 준비와 후보 생성 단계까지 병렬화할 수 있다. 최종 통합과 활성화는 순차 처리해야 한다.** 세계 카탈로그, 전역 번호, 공유 국경, 타일, 활성 포인터와 서버 세션이 공용이기 때문이다.

다만 현재는 네 번째 국가부터 같은 CLI에 국가 코드만 바꿔 추가할 수 있는 범용 파이프라인이 완성돼 있지 않다. 한국·북한 생성 경로와 중국 증분 추가 경로에 각각 고정 조건이 남아 있다. 다음 국가를 추가하면서 이 통합 경로를 일반화해야 한다.

권고하는 운영 방식은 다음과 같다.

- 일반 기능 개발과 국가별 원본 조사·정규화·adapter 개발을 파일과 실행 환경별로 분리해 진행한다.
- 국가별 작업은 검증된 후보와 기준 카탈로그 정보를 제출한다.
- 한 통합 담당자가 최신 카탈로그에 후보를 하나씩 반영하고 공유 경계와 표시 자료를 재검증한다.
- 실행 중 게임 보존, 최종 포인터 변경, 서버 전환과 실제 앱 확인은 한 경로에서 수행한다.

기존 [국가 지정형 개발 지침](../../prompts/COUNTRY_MICRO_BOUNDARY_GUIDE.txt)도 국가별 조사와 adapter의 소유권을 분리하고 최종 catalog, 포인터, 공용 코드, build, 서버와 브라우저 작업은 한 담당자가 순차 소유하도록 정하고 있다.

## 2 프로빈스의 의미와 현재 규모

이 분석에서 독립 객체는 실제 게임의 변경 단위인 operational territory cell을 뜻한다. 원본 시군구 한 개, 도급 행정 부모, 화면에 보이는 경계선과 항상 일대일 관계인 것은 아니다. 원본 한 구역이 게임 정합 과정에서 여러 영토로 나뉠 수 있고, 도급 부모는 여러 영토를 묶어 조회하는 역할을 한다.

현재 활성 버전은 catalog-v3-prompt19-incremental-CHN-95ea496a8aa66910a9a7이다. 전체 247개 국가, 8005개 영토, 26273개 edge를 포함하며 fineCountries는 CHN, KOR, PRK다.

| 국가 | 독립 영토 객체 | fine로 분류된 셀 | 별도 fallback 셀 | 도급 행정 부모 |
|---|---:|---:|---:|---:|
| 한국 | 322 | 289 | 33 | 17 |
| 북한 | 194 | 192 | 2 | 11 |
| 중국 | 3320 | 3313 | 7 | 31 |

fine와 fallback 수는 현재 provenance의 분류다. 셀 수가 원본 행정구역 수 또는 법적 행정구역 개수라는 의미는 아니다. fallback도 런타임에서는 다른 영토와 같은 독립 상태 객체다.

## 3 실제 독립 객체 검증

### 3.1 데이터 모델

[TerritoryEntityV3](../../src/lib/world/territory-entity-v3.ts)는 다음 정보를 가진 불변 객체다.

- id: 영토 고유 ID.
- sourceCountryId: 원본 지리 분류 국가.
- ownerCountryId: 현재 소유국.
- controllerCountryId: 현재 통제국.

원본 분류와 현재 소유 및 통제는 분리돼 있다. 점령은 통제국을 바꾸고, 소유권 양도는 지정된 영토의 소유국과 필요 시 통제국을 바꾼다.

WorldStateV3의 territoriesById는 영토 ID를 개별 객체에 연결한다. transitionWorldStateV3는 변경한 객체를 새로 만들고, 건드리지 않은 객체의 참조는 유지한다. 실제 세계 8005개 영토의 ID는 모두 고유했고 객체 참조도 8005개로 서로 달랐으며 모두 불변 상태였다.

따라서 여러 영토가 같은 도에 속한다고 해서 소유권이나 통제권을 같은 객체 하나에 저장하는 구조는 아니다.

### 3.2 형상과 소속 연결

세 나라의 전체 상세 자료를 각각 확인했다.

| 검사 | 한국 | 북한 | 중국 |
|---|---|---|---|
| 상세 feature 수와 영토 수 일치 | 322 대 322 | 194 대 194 | 3320 대 3320 |
| 상세 feature와 메타데이터의 일대일 대응 | 통과 | 통과 | 통과 |
| 모든 셀의 등록된 행정 부모 연결 | 통과 | 통과 | 통과 |
| 모든 셀의 이전 seed 부모 연결 | 통과 | 통과 | 통과 |
| 실제 파일의 hash와 byte length 검사 | 통과 | 통과 | 통과 |

형상은 불변 카탈로그에 있고 변경 가능한 소유·통제 상태는 세계 객체에 있다. 상세 feature의 숫자 ID는 카탈로그 내부 ordinal이며 영구적인 영토 ID와 메타데이터로 연결된다.

여기서 소속 연결 통과는 **등록된 부모와 셀 사이의 내부 참조가 일관적이라는 의미**다. 모든 부모가 공식 행정 소속으로 확정됐다는 뜻은 아니다.

### 3.3 세 나라에서 개별 영토 하나만 변경

각 나라에서 공식 행정 부모로 등록된 같은 묶음 안의 두 셀을 골라 한 셀만 변경했다. 실제 생산용 새 게임 데이터를 사용하되, 모든 변경은 별도의 메모리 안에서만 수행했다.

| 검사 | 한국 | 북한 | 중국 |
|---|---|---|---|
| 점령 대상 1개만 변경 | 통과 | 통과 | 통과 |
| 점령 시 기존 소유국 유지 | 통과 | 통과 | 통과 |
| 같은 행정 부모의 다른 셀 유지 | 통과 | 통과 | 통과 |
| 다른 8004개 셀의 객체 참조 유지 | 통과 | 통과 | 통과 |
| 해방 시 기존 소유국의 통제로 복귀 | 통과 | 통과 | 통과 |
| 양도 시 해당 셀 소유·통제 변경 | 통과 | 통과 | 통과 |
| 원본 국가와 영토 ID 보존 | 통과 | 통과 | 통과 |
| 저장 직렬화와 복원 후 내용 일치 | 통과 | 통과 | 통과 |
| 점령 표시 생성 및 양도 후 해제 | 통과 | 통과 | 통과 |

이 검사는 호스트 planner와 실제 상태 전이를 확인하기 위해 개발용 권한 예외를 사용했다. 일반 플레이에서 필요한 정치적 권한이나 AI의 판정이 자동으로 성립한다는 뜻은 아니다.

### 3.4 실제 전선 선택과 턴 반영 및 이력

실제 카탈로그의 전선 선택기를 사용하고, 반환된 범위 전체를 실제 턴 계획과 런타임에 반영했다. 전선 결과를 가짜 resolver로 바꾸지 않았다.

| 진입 방향 | 선택 영토 | 실제 변경 영토 | 나머지 유지 | undo와 redo |
|---|---:|---:|---|---|
| 북한에서 한국으로 | 1 | 1 | 통과 | 통과 |
| 한국에서 북한으로 | 1 | 1 | 통과 | 통과 |
| 북한에서 중국으로 | 1 | 1 | 통과 | 통과 |

세 경우 모두 near 범위에서 성공했다. commit 알림은 각 1회였고 상태 delta도 정확히 선택한 한 셀만 포함했다. undo 후 세계 내용은 이전 상태와 같았고 redo 후 반영 상태와 같았다.

세부 국가 간 양의 길이 인접 관계는 한국·북한 13쌍, 중국·북한 38쌍이며 확인한 인접 관계는 양방향이었다. 이는 셀 쌍 수로, 국경 구간이나 edge 개수와 같은 단위가 아니다.

## 4 독립 객체가 동작해도 남아 있는 제한

### 지역 이름과 행정 의미는 별도 보완이 필요하다

기존 보고서에서 확인한 청진 검색 누락, 내몽골 별칭 부족, 양도와 군사 전선 선택의 결합은 여전히 남아 있다. 이는 개별 셀 상태를 변경할 수 없어서 발생한 문제와는 구분해야 한다.

특히 중국은 다음 수를 구분해야 한다.

- 원본 소속 미확정 단위: 1201개.
- 현재 런타임에서 행정 부모 미확정 묶음에 속한 셀: 1375개.
- 원본 fine가 아닌 별도 fallback 셀: 7개.

1375개는 미확정 fine 셀과 fallback을 함께 포함한다. 이 셀들도 독립적인 점령·소유권 상태를 가질 수 있으나, 특정 도 전체의 일부라고 확정하는 일은 추가 근거가 필요하다. 표시용 광역 묶음이 있다고 해서 공식 행정 소속이 확정되는 것도 아니다.

### 독립 객체와 전체 게임 도메인의 완성은 구분해야 한다

현재 핵심 영토 객체는 ID, 원본 국가, 소유국, 통제국을 가진다. 세부 영토별 인구나 산업, 군부대 등 다른 기능의 완성 여부까지 이 검사로 입증하지는 않는다.

또한 세계 상태와 턴 commit은 공용이다. 셀별 상태가 독립적이어도 서로 다른 국가의 두 턴을 같은 세계 revision 위에 동시에 확정하는 구조는 아니다. 개발 작업의 병렬성과 실제 게임 상태 변경의 동시성은 다른 문제다.

### 카탈로그 내부 번호는 국가 추가 시 달라질 수 있다

packager는 전역 ID 순서를 정렬한 후 cellOrdinal과 부모 ordinal, edge ordinal을 다시 배정한다. 다른 나라를 추가해도 기존 영토의 논리적 ID는 보존하는 것이 원칙이지만 숫자 ordinal까지 그대로라는 보장은 없다.

기존 영토의 물리적 형상, 원본 소속과 lineage를 보존하면서 국경 정합을 위해 공선상 노드를 추가하는 경우도 있다. 이런 표현상의 변경과 실제 영토 변화는 별도로 검증해야 한다.

국가별 개발 결과는 영토의 안정적인 ID로 비교하고, ordinal은 최종 통합 카탈로그에서 다시 연결해야 한다.

## 5 현재 국가 추가 파이프라인의 확장성

현재 구현을 임의 국가를 처리하는 범용 생성기로 볼 수는 없다.

| 위치 | 현재 제약 | 다음 국가 추가에 미치는 영향 |
|---|---|---|
| prompt19-country-core | KOR와 PRK enum | 제3국 입력을 그대로 받지 않음 |
| prompt19-country-files | KOR와 PRK 출력 범위 제한 | 국가 문자열만 바꾼 출력 생성 불가 |
| prepare-prompt19-country | 과거 coarse 기준선과 handoff 검사 | 현재 3개 fine 국가가 있는 기준선에 그대로 재사용 불가 |
| chn-2020 incremental-coordinator | CHN source 및 고정 baseline 경로 | 중국 추가 전용이며 후속 국가용 자동 증분 도구가 아님 |
| prepare-prompt19-mixed-world | incremental country가 CHN인지 검사 | 다른 국가의 증분 입력을 거부 |
| 같은 packager의 fine 국가 목록 | KOR, PRK 또는 CHN, KOR, PRK로 고정 | 네 번째 국가의 source-lock 집합을 그대로 받아들이지 않음 |

이 제약은 [국가 지정형 개발 지침](../../prompts/COUNTRY_MICRO_BOUNDARY_GUIDE.txt)에 이미 경고돼 있다. 다음 국가의 원본과 계층을 조사·채택한 뒤 필요한 adapter와 공용 증분 경로를 구현해야 한다.

필요한 일반화는 국가 코드 제한을 아무 문자열이나 허용하도록 없애는 작업이 아니다. 실제 등록된 adapter와 source-lock, 검증기, 대상국 목록을 사용하도록 바꾸고 현재 활성 fine 국가의 보존을 증명해야 한다.

| 국가 adapter와 원본 계층 작성 | 높음 | 공용 helper 변경 소유권 조정 |
| 로컬 geometry 후보 생성 | 조건부 가능 | 동일한 불변 기준선, 독립 출력 경로와 메모리 한도 |
| 국가별 독립 검증 | 가능 | 정확한 후보와 코드 hash에 연결 |
| 공유 국경의 최종 노딩과 topology | 통합 단계 필요 | 이웃 국가의 변경을 함께 반영 |
| 전역 카탈로그 및 타일 조립 | 통합 담당자 소유 | 최종 전역 ID 순서와 참조 재계산 |
| current 변경 및 앱 전환 | 순차 처리 | 최신 기준선 확인과 게임 보존 |

병렬 가능한 범위가 넓지만, 서로 다른 전체 세계 후보를 단순히 파일 단위로 합칠 수 있다는 의미는 아니다.

## 7 두 국가를 동시에 준비할 때 필요한 통합 절차

두 작업이 현재 B0를 기준으로 시작했다고 가정한다.

~~~mermaid
flowchart LR
  B0["활성 기준선 B0"] --> A["국가 A 원본과 후보 준비"]
  B0 --> B["국가 B 원본과 후보 준비"]
  A --> I1["A를 통합하고 검증"]
  I1 --> B1["새 기준선 B1"]
  B --> R["B의 후보를 B1에 다시 연결"]
  B1 --> R
  R --> I2["공유 경계와 전체 보존 검증"]
  I2 --> B2["A와 B를 포함하는 B2"]
~~~

A가 먼저 반영되면 B가 제출한 전체 세계 B0 기반 산출물은 오래된 기준선을 가진다. B의 원본과 정규화 자료는 재사용할 수 있지만, 현재 B1에서 B만 교체하는 방식으로 다시 조립해야 한다. B0 기반 전체 세계로 current를 바꾸면 A의 추가 내용이 빠질 수 있다.

### 서로 이웃하지 않는 국가

국가 내부 원본 처리와 후보 생성은 대부분 독립적이다. 최종 전역 번호와 타일, 표시 바인딩을 최신 기준선에서 재계산하고 비대상국 보존을 확인한다.

### 서로 국경을 공유하는 국가

국가 내부 자료는 따로 준비할 수 있다. 최종 공유 국경은 두 작업이 함께 사용하는 경계와 노드를 기준으로 정합해야 한다. 각 작업이 상대국의 옛 coarse 경계만 보고 만든 topology를 최종 결과로 합치면 미세 틈, 중복선, 불일치하는 adjacency가 생길 수 있다.

같은 공통 partition에서 양측 경계를 조립하고, 공유 경계의 양의 길이 인접, 양측 incidence, 기존 영토 보존을 함께 검증한다. 직접 이웃이 아니더라도 동일한 제3국 경계나 전역 산출물에 영향을 주면 통합 단계에서 다시 확인한다.

## 8 현재 병렬 발행을 막는 구체적 공용 지점

### 8.1 활성 포인터는 한 개이며 배타적 발행 잠금은 없다

[packager의 publishPointer](../../scripts/prepare-prompt19-mixed-world.mjs)는 기존 fine 국가 보존과 baseline pointer hash를 검사하고 임시 파일을 만든 뒤 rename한다. 오래된 기준선을 탐지하고 불완전한 포인터 노출을 줄이는 보호가 있다.

그러나 검사와 rename을 하나의 교차 프로세스 배타 구간으로 묶지는 않는다. 다음 순서가 코드상 가능하다.

1. A가 B0 기준 검사를 통과한다.
2. B도 B0 기준 검사를 통과한다.
3. A가 새 포인터를 current로 rename한다.
4. B가 이미 통과한 검사를 근거로 자신의 포인터를 rename한다.

파일 rename의 원자성은 여러 발행자의 논리적 충돌까지 막는 compare-and-swap과 같은 기능이 아니다. 이 분석에서는 실제 current를 대상으로 경쟁 발행을 실행하지 않았다. 소스상 배타 잠금이 없으므로 병렬 발행 안전성을 보장할 수 없다는 판단이다.

현재는 한 담당자가 최종 발행을 맡는 것이 적절하다. 자동화할 때는 기준선 재확인, 게임 보존, 최종 검사와 포인터 교체를 하나의 배타 발행 구간으로 묶어야 한다.

### 8.2 같은 content 경로의 동시 생성은 별도 보호가 필요하다

산출물은 content-key 경로와 배타 파일 생성으로 기존 내용을 덮어쓰지 않도록 한다. 이는 좋은 보호다. 다만 같은 후보를 두 작업이 동시에 만들면 경로가 충돌할 수 있고, 한 작업이 아직 작성 중인 디렉터리를 다른 작업이 기존 완성 산출물로 취급할 수 있다.

국가와 작업별 임시 경로에서 완성한 뒤 검증된 manifest를 기준으로 최종 불변 산출물을 등록하거나, 같은 출력의 생성 소유자를 하나로 두는 방식이 필요하다. 두 작업이 같은 기본 geometry 출력과 고정 보고서 경로를 공유하지 않아야 한다.

### 8.3 중국 표시 산출물이 전역 카탈로그에 묶여 있다

현재 지도 bootstrap은 중국이 포함되면 별도 중국 광역 표시와 선 LOD를 불러온다. 이 표시 자료는 중국 메타데이터뿐 아니라 전체 parents, incidence, catalog, detail index와 catalogRef에 연결돼 있다.

다른 나라를 추가하면서 전역 번호와 부모 목록이 바뀌면 중국의 물리적 영토가 그대로여도 표시 자료를 재검증하고 다시 연결해야 한다. 이번에 현재 bootstrap은 성공했고, 같은 카탈로그 객체에 가상의 다른 전역 버전만 전달한 음성 검사에서는 Catalog ref mismatch가 발생했다.

따라서 국가 추가와 중국 표시 개선을 서로 무관하게 발행할 수는 없다. 최종 통합 단계에서 표시 자료의 pin과 번호 연결도 함께 갱신해야 한다. 장기적으로 국가별 안정 ID와 관련 경계 ID를 기준으로 표시 자료를 묶고, 최종 카탈로그 ordinal에 연결하는 단계를 분리하는 것이 좋다. 기존 검증을 삭제해 우회해서는 안 된다.

### 8.4 새 카탈로그는 실행 중 게임과 자동 호환되지 않는다

세계 상태는 전체 territoryOrder와 catalogRef를 검증한다. 새 국가를 coarse에서 fine으로 바꾸면 해당 영토 ID와 전체 카탈로그 참조가 달라지므로 옛 save를 새 카탈로그로 조용히 해석할 수 없다.

현재 서버는 이전 카탈로그 게임 풀과 이력을 보존하고 전환 시 checkpoint를 쓰는 경로를 가지고 있다. 이전 세션에는 GAME_CATALOG_PRESERVED를 반환할 수 있다. 이는 새 카탈로그 위에서 기존 게임이 자동으로 이어진다는 보장은 아니다.

후보 준비 중에는 current를 유지하고 일반 개발을 계속할 수 있다. 최종 전환은 실행 중인 게임과 서버 버전을 확인해 별도로 진행해야 한다. 자동 이관이 검증되지 않았다면 새 게임으로 시작하는 것이 현재 계약이다.

## 9 권고하는 국가 추가 작업 구조

### 국가별 작업의 산출물

다음은 앞으로 일반화할 계약의 제안이다. 현재 이미 존재하는 범용 CLI라는 의미는 아니다.

- 대상 국가와 정확한 원본 및 라이선스, 시점, 정규화 입력.
- 행정 계층의 검증 범위와 미확정 항목.
- 기준 카탈로그와 관련 코드 및 입력 hash.
- 국가별 geometry 후보와 원본 feature 연결.
- 변경될 수 있는 인접국 경계 범위와 공유 경계 영향.
- 기존 영토에서 새 영토로의 lineage.
- 독립 검증 결과와 비대상국 보존 비교.

### 통합 담당자의 작업

1. 최신 활성 카탈로그를 읽고 제출된 기준선과 비교한다.
2. 오래된 후보의 국가 내부 자료는 재사용하되 최신 세계에 다시 연결한다.
3. 대상 국가만 교체하고 기존 fine 국가의 해상도, ID, 소속과 lineage를 보존한다.
4. 필요한 공유 국경을 정합하고 전역 topology와 번호, 타일을 생성한다.
5. 중국 등 기존 표시 자료를 새 전역 참조에 재연결한다.
6. 객체와 지역 조회, 양방향 첫 점령, 후속 진입, undo와 redo를 검사한다.
7. 실행 게임을 보존하고 포인터를 단독으로 바꾼다.
8. 새 버전 앱을 확인한 뒤 다음 후보를 통합한다.

공용 코드의 변경 담당자도 한 명으로 두거나 변경을 먼저 합친 후 국가별 작업이 그 버전을 고정하도록 한다. 별도 작업트리와 국가별 경로, 별도 출력과 포트를 사용하면 공유 작업 디렉터리에서 생기는 충돌을 줄일 수 있다.

큰 geometry 처리와 전체 타일 조립은 CPU와 메모리를 많이 사용할 수 있다. 파일이 분리됐다는 이유로 무제한 병렬 실행을 권고하지 않는다. 이번에는 여러 국가의 전체 생성기를 동시 실행하는 자원 부하 시험은 하지 않았다.

## 10 우선 보완 항목

| 우선순위 | 항목 | 이유 |
|---|---|---|
| 1 | 국가 adapter 등록과 현재 기준선 기반 증분 통합 일반화 | 현재 경로는 네 번째 국가를 그대로 받지 않음 |
| 2 | 최종 통합과 활성화의 단일 소유 또는 배타 잠금 | 오래된 후보 및 동시 발행 충돌 방지 |
| 3 | 전역 번호 변경과 기존 표시 자료의 재연결 단계 | 중국 표시 자료를 포함한 앱 부팅 보장 |
| 4 | 후보별 기준선, 입력, 코드와 영향 범위 manifest | 병렬 작업을 최신 세계에 안전하게 합류 |
| 5 | 공통 schema 변경에 맞는 테스트 fixture 정비 | 기존 테스트 4개가 필수 경계 인덱스 누락으로 실패 |

사용자가 나라를 하나씩 추가하는 방식은 지금 구조에서도 적절하다. 그 사이 일반 개발과 다음 국가의 조사·정규화를 병행하면 된다. 여러 국가의 실제 후보를 동시에 준비하고 싶다면 위의 기준선과 통합 계약을 먼저 정하는 편이 효율적이다.

## 11 검증 결과와 제한

### 실제 데이터 진단

[재현 코드](audit.cjs)를 다음과 같이 실행했다.

~~~powershell
node reports/province-independence-parallelism-20261103/audit.cjs
~~~

영토 ID와 객체 참조, 불변성, 세 나라 전체의 상세 feature 연결과 등록 부모 연결, 개별 상태 변경, 실제 전선 턴과 이력을 검사한 15개 상위 검사가 모두 통과했다. 실제 지도 bootstrap도 현재 표시 자료와 함께 통과했다.

등록 부모 연결이 완전하다는 결과를 행정적 소속의 사실 완전성과 혼동하지 않았다. 또한 전체 polygon 교차, 면적 오차, 모든 경계선의 정확도를 이번에 다시 계산한 것은 아니다.

### 기존 테스트

기존 application 테스트는 7개 파일 65개 중 61개 통과, 4개 실패였다. 실패는 모두 operational-mixed-membership.test.ts에서 발생했다.

그 fixture는 edge 수를 1로 선언하면서 edgeDetails를 빈 배열로 제공한다. 현재 로더는 경계 인덱스가 선언된 수를 채우는지 검사하므로 OPERATIONAL_EDGE_INDEX로 중단된다. 네 테스트 모두 실제 membership 본문에 도달하기 전에 실패한다.

현재 생산 카탈로그의 로딩과 직접 수행한 membership 및 실제 턴 진단은 통과했다. 따라서 이 네 실패를 세부 영토가 서로 같은 객체를 공유한다는 증거로 해석할 수는 없다. fixture가 현재 전달 계약을 충족하도록 고치는 것이 우선이며 운영 검증을 약화시키면 안 된다.

국가별 입력과 출력 경로의 격리를 확인하는 node 테스트 3개는 별도 실행해 모두 통과했다. 합계는 68개 중 64개 통과, 4개 실패다. 상세 명령과 결과는 [추가 검증 기록](verification.json)에 남겼다.

### 작업 범위

이번에는 국가를 추가하거나 활성 포인터, 지도 카탈로그, 애플리케이션 소스와 테스트를 수정하지 않았다. 기존 사용자 게임과 서버를 건드리지 않았고 실제 AI 호출, 외부 자료 수집, 전체 재생성, 배포도 수행하지 않았다.

소스와 데이터는 현재 작업 디렉터리 상태를 기준으로 읽고 hash를 남겼다. 진행 중인 다른 개발 작업의 변경을 되돌리지 않았다. 결론은 현재 세 나라의 독립적인 영토 상태 동작과 개발 파이프라인의 병렬화 가능 범위에 한정한다.

관련 선행 분석은 [국가 행동과 영토 변경 문제 보고서](../simulation-territorial-issues-20261103/report.md)다.
