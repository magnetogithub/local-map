# Prompt 10 — 국가·영토 분리형 동적 월드 런타임

## 0. 위치와 목적

이 문서는 저장소 루트를 기준으로 실행한다. 특정 개발 머신의 절대 경로를 전제로 하지 않는다.

Prompt 09의 9-1부터 9-14까지는 현재 구현과 감사 이력으로 보존한다. Prompt 09의 9-15부터 9-64까지는 이 Prompt 10이 대체한다. Prompt 10을 시작한 뒤에는 대체된 Prompt 09 단계를 실행하거나 완료 보고서로 만들지 않는다.

Prompt 10의 목표는 국가 정체성과 영토를 분리하고, 국가 생성·독립·소멸·분할·병합·영토 이전을 결정적이고 원자적으로 처리하는 런타임을 만드는 것이다.

최종 실행 흐름은 다음과 같다.

```text
MapCommand
→ structural schema validation
→ semantic planner
→ topology validation
→ immutable next domain state
→ atomic domain commit
→ WorldPatch
→ revision 기반 projection
→ search / selection / panel / map / border / label
```

자연어 해석기, LLM 연결, 외교·경제·국가 중점의 실제 게임 규칙은 이 Prompt의 범위가 아니다. 다만 이후 모듈을 `countryId`에 거대한 단일 객체로 합치지 않고 독립적으로 추가할 수 있는 구조를 제공해야 한다.

## 1. 확정된 설계 결정

### 1.1 국가와 영토 분리

`CountryEntity`는 국가 정체성과 핵심 metadata만 가진다. geometry를 소유하지 않는다.

영토 geometry와 실효 지배자는 `TerritoryEntity`가 가진다.

```text
CountryEntity
- id
- names
- politicalStatus
- presentationOverride
- moduleVersions

TerritoryEntity
- id
- ownerCountryId: string | null
- geometry
- properties
```

외교 관계, 경제, 국가 중점, 정치, 군사와 같은 후속 데이터는 별도 module store에 둔다. `CountryEntity` 내부에 모든 데이터를 중첩한 거대 객체를 만들지 않는다.

### 1.2 단일 실효 지배자

각 Territory는 현재 한 국가만 실효 지배할 수 있다. `ownerCountryId === null`은 미점유 영토를 뜻한다.

복수 국가의 영유권 주장과 분쟁 claim은 후속 module로 추가한다. 현재 단계에서는 겹치는 국가 polygon으로 claim을 표현하지 않는다.

### 1.3 국가 ID 수명

삭제된 `countryId`는 `retiredCountryIds`에 기록하고 재사용하지 않는다. undo는 같은 ID를 복원할 수 있지만, 삭제가 확정된 뒤 새로운 국가가 같은 ID를 다시 발급받아서는 안 된다.

### 1.4 geometry policy

좌표 정밀도, winding 정규화, boolean operation tolerance, 최소 면적과 topology 규칙은 versioned executor policy가 결정한다. 일반 command payload나 LLM이 이 정책을 선택하거나 임의로 완화할 수 없다.

모든 plan과 commit은 사용한 `policyVersion`을 기록한다.

### 1.5 domain commit과 projection

`WorldState` domain commit만 원자 transaction으로 취급한다. MapLibre, 검색 index, UI state와 Worker 결과를 하나의 브라우저 transaction으로 가장하지 않는다.

각 projection은 다음 계약을 따른다.

- committed revision만 읽는다.
- 자신이 반영한 `appliedRevision`을 기록한다.
- 갱신 실패 시 마지막 정상 projection을 유지하고 오류를 보고한다.
- 다음 성공 갱신에서 최신 committed revision으로 수렴한다.
- stale revision 결과를 적용하지 않는다.

### 1.6 presentation

center, defaultZoom, label anchor와 기본 typography는 geometry와 공통 policy에서 자동 계산한다.

수동 조정이 반드시 필요한 경우 하나의 `presentationOverride`에만 저장하며 근거와 policy version을 기록한다. `presentation`과 `initialPresentation`처럼 같은 의미의 필드를 중복 정의하지 않는다.

### 1.7 topology 구현 순서

인접국 index, canonical shared edge와 coast/internal-border 분류를 영토 split·merge executor보다 먼저 구현한다. polygon outline을 장기적인 제품 국경으로 사용하지 않는다.

## 2. 국가 생성과 소멸 계약

### 2.1 저수준 명령과 편의 명령 분리

저수준 명령은 한 가지 책임만 가진다.

- `country.create`: 영토 없는 국가 정체성을 생성한다.
- `territory.partition`: Territory를 결정적인 여러 Territory로 분할한다.
- `territory.assign`: 미점유 Territory의 owner를 지정한다.
- `territory.transfer`: 한 국가의 Territory 전부 또는 분할된 Territory를 다른 국가로 이전한다.
- `territory.unclaim`: owner를 null로 변경한다.
- `country.delete`: 소유 Territory가 0인 국가 정체성만 삭제한다.

편의 명령은 내부에서 저수준 명령 batch로 plan되며 한 revision으로 commit한다.

- `country.establish`: 국가 생성과 미점유 Territory 할당을 한 transaction으로 실행한다.
- `country.dissolve`: 모든 소유 Territory의 처리와 국가 삭제를 한 transaction으로 실행한다.
- `country.split`: source 영토 partition, 결과 국가 생성, 소유권 재할당과 source 삭제를 한 transaction으로 실행한다.
- `country.merge`: source 영토 이전, result 국가 생성 또는 갱신과 source 삭제를 한 transaction으로 실행한다.

### 2.2 중간 무주지 상태

planner 내부 임시 상태에서는 영토가 잠시 미점유일 수 있다. 그러나 establish, split, merge처럼 최종 소유자가 정해진 transaction은 중간 무주지 revision을 UI에 노출하지 않는다.

영토를 실제 미점유 상태로 남기는 것은 명시적인 `territory.unclaim` 또는 `country.dissolve` disposition으로만 허용한다.

### 2.3 국가 소멸 disposition

영토가 남은 국가를 `country.delete`로 직접 삭제할 수 없다.

`country.dissolve`는 모든 소유 Territory에 대해 다음 중 하나를 명시해야 한다.

```text
unclaim
transfer(targetCountryId)
merge(targetCountryId)
```

처리되지 않은 Territory가 하나라도 남으면 plan은 실패한다. geometry를 지도에서 묵시적으로 제거하는 disposition은 제공하지 않는다.

### 2.4 빈 세계

일반 `country.delete`와 `country.dissolve`는 마지막 유효 국가 삭제를 허용하지 않는다.

빈 세계가 필요한 테스트·seed 교체·관리 작업은 일반 MapCommand가 아닌 내부 helper 또는 별도의 privileged `world.reset` 경계를 사용한다.

## 3. 검증 책임

### 3.1 schema validator

schema validator는 다음만 책임진다.

- 필수 필드와 strict unknown-field 정책
- 문자열, ID, enum, 숫자와 배열 형식
- 유한 좌표와 기본 GeoJSON 구조
- command type과 payload의 구조적 대응
- batch 크기와 중첩 깊이 제한

schema validator는 현재 WorldState를 변경하거나 MapLibre artifact를 계산하지 않는다.

### 3.2 semantic planner

planner는 다음 핵심 불변식을 책임진다.

- 국가·영토 ID 존재 여부와 충돌
- retired ID 재사용 금지
- expectedRevision 일치
- ownerCountryId 참조 무결성
- 단일 실효 지배자
- 미점유 Territory만 establish에 사용
- 영토 보존과 허용 tolerance 이내의 gap/overlap
- split 결과 union과 source geometry의 동등성
- transfer 전후 전체 면적 보존
- dissolve 이후 dangling owner 0
- topology와 geometry의 일치
- 마지막 국가 삭제 금지

프롬프트 품질을 runtime 안전성의 근거로 사용하지 않는다. 대신 반복적인 보고서 hash, schema 단계의 artifact 검증과 적용 불가능한 rollback gate는 제거한다.

### 3.3 executor

executor는 이미 검증된 plan만 commit한다. executor가 명령 의미를 다시 해석하거나 임의의 fallback을 선택하지 않는다.

## 4. 영역별 계층 hash

하나의 거대한 국가 객체 또는 WorldState 전체 직렬화를 유일한 hash로 사용하지 않는다.

### 4.1 module leaf hash

현재 Prompt에서 최소 다음 hash를 정의한다.

```text
countryCoreHash[countryId]
countryPresentationHash[countryId]
territoryGeometryHash[territoryId]
territoryOwnershipHash[territoryId]
topologyEdgeHash[edgeId]
```

후속 module은 다음과 같이 독립 hash namespace를 추가한다.

```text
relationHash[canonicalCountryPair]
economyHash[countryId]
focusTreeHash[countryId]
politicsHash[countryId]
```

국가 관계 pair key는 정렬된 두 ID로 만든다.

```text
min(countryA, countryB) + ":" + max(countryA, countryB)
```

### 4.2 aggregate root

정렬된 leaf hash로 영역별 root를 만든다.

```text
countriesRootHash
territoriesRootHash
topologyRootHash
presentationRootHash
```

`worldContentHash`는 영역 root와 schemaVersion, seedVersion, policyVersion으로 계산한다. `revision`, issuedAt, commandId와 UI 상태는 `worldContentHash`에 포함하지 않는다.

### 4.3 목적별 hash

- `worldContentHash`: 의미상 국가·영토·topology 내용
- `commitHash`: revision, worldContentHash, policyVersion과 직전 commitHash
- `artifactHash`: 특정 revision의 projection 산출물
- `historyHash`: command history와 undo/redo pointer

undo 후 `worldContentHash`는 이전 내용과 같아질 수 있지만 revision과 commitHash는 감소하거나 과거 값으로 되돌아가지 않는다.

### 4.4 결정성

hash 입력은 canonical serialization을 사용한다.

- object key 정렬
- ID 목록 정렬 또는 명시적 domain order 사용
- policy가 정한 좌표 정밀도
- locale 비의존 숫자와 문자열 처리
- `undefined`, 함수, MapLibre·Worker 객체 제외

작은 module 변경이 무관한 module leaf hash를 변경하면 `fail`이다.

## 5. WorldState와 WorldPatch

새 WorldState는 최소 다음 영역을 가진다.

```text
schemaVersion
seedVersion
policyVersion
revision
countriesById
countryOrder
retiredCountryIds
territoriesById
territoryOrder
topology
hashRoots
```

WorldPatch는 단순한 국가 ID 집합만 가지지 않는다.

```text
beforeRevision / afterRevision
beforeContentHash / afterContentHash
countryCreated / countryUpdated / countryDeleted
territoryCreated / territoryUpdated / territoryDeleted
ownershipChanged
geometryChanged
topologyEdgesChanged
affectedCountryIds
affectedTerritoryIds
moduleHashChanges
```

각 집합은 중복과 모순이 없고 결정적인 순서를 가져야 한다.

## 6. 원자 단계 실행·보고 규칙

각 10-N은 하나의 독립 작업 세션이며 제품 책임 하나만 구현한다. 한 단계에서 서로 다른 command, projection, persistence 기능을 함께 구현하지 않는다.

각 단계의 기본 절차:

1. AGENTS.md와 현재 Prompt 10을 읽는다.
2. 실제로 수정하는 기술의 설치 문서만 읽는다.
3. 직전 단계 보고서의 status와 직접 output hash를 확인한다.
4. reports/prompt10/10-N-<slug>.json을 running으로 만든다.
5. 현재 실패 또는 미구현 상태를 targeted test로 고정한다.
6. 해당 번호의 제품 코드와 targeted test만 구현한다.
7. gate를 기록하고 pass 또는 fail에서 중단한다.
8. 다음 번호를 자동 실행하지 않는다.

보고서 형식:

~~~json
{
  "stage": "10-N",
  "status": "running | pass | fail | blocked",
  "objective": "",
  "promptHash": "",
  "directInputHashes": {},
  "outputHashes": {},
  "changedFiles": [],
  "commands": [],
  "measurements": {},
  "gates": {},
  "firstFailedGate": null,
  "implementationErrors": [],
  "environmentErrors": [],
  "rollbackVerified": null,
  "nextStage": "10-(N+1) | null"
}
~~~

rollbackVerified는 실제 state 변경과 rollback을 다루는 단계에서만 boolean을 사용한다. 타입·schema·감사 단계에서는 null이다.

과거 단계 output이 후속 단계에서 의도적으로 변경되면 최종 파일과 과거 hash가 같을 것을 요구하지 않는다. 직전 보고서 chain, 현재 Prompt hash와 최종 동작을 검증한다.

모든 단계에서 targeted test, 대상 lint와 typecheck를 실행한다. 전체 unit suite는 다음 checkpoint에서만 실행한다.

- 10-19: domain seed 전환
- 10-30: hash 기반
- 10-45: command schema
- 10-55: topology 기반
- 10-77: planner 완성
- 10-85: atomic executor
- 10-91: application projection
- 10-99: map projection
- 10-106: label projection
- 10-112: history·저장
- 10-124: 최종 판정

production build와 전체 E2E는 10-119 이후 통합 단계에서 실행한다.

## 7. 원자 소단계 목록

### A. 전환 감사

#### 10-1. Prompt 09 보고서 chain 확인

동작: Prompt 09의 9-1~9-14 status와 직접 hash chain만 감사한다.

검증: 누락·fail·hash 단절을 표로 기록한다. 제품 코드는 수정하지 않는다.

#### 10-2. 대체 단계 동결

동작: Prompt 09의 9-15~9-64가 Prompt 10으로 대체됐음을 보고서에 기록한다.

검증: 대체된 단계를 이후 실행 대상으로 해석하는 경로가 없어야 한다.

#### 10-3. runtime 국가 소유자 감사

동작: CountryEntity, 정적 countryById, Zustand와 선택 store의 국가 데이터 소유권을 목록화한다.

검증: runtime-read, seed-only, test-only 분류 누락 0.

#### 10-4. runtime geometry 소유자 감사

동작: 국가 polygon, low/high source, border, capital과 label geometry의 소유자를 목록화한다.

검증: geometry write 경로와 파생 경로의 미확인 항목 0.

#### 10-5. 기존 command 감사

동작: Prompt 09에서 만든 command envelope와 9-10~9-14 schema의 구조·semantic 책임을 분류한다.

검증: v2에서 유지·이동·폐기할 책임이 모든 필드에 지정되어야 한다.

### B. 국가·영토 domain type

#### 10-6. CountryId 수명 타입

동작: active와 retired 상태를 구분할 CountryId 계약을 정의한다.

검증: 빈 ID와 retired ID의 신규 발급을 타입 경계와 runtime helper가 거부한다.

#### 10-7. CountryNames module

동작: 국가 이름과 검색 alias를 독립 module 타입으로 분리한다.

검증: core identity나 geometry 없이 이름 module만 갱신할 수 있어야 한다.

#### 10-8. CountryEntity core

동작: geometry 없는 최소 CountryEntity를 정의한다.

검증: CountryEntity에 territory geometry, 경제, 외교, 국가 중점 필드가 없어야 한다.

#### 10-9. CountryPresentationOverride

동작: 자동 presentation과 구분되는 단일 override 타입을 정의한다.

검증: presentation과 initialPresentation 같은 중복 입력 경로 0.

#### 10-10. TerritoryId 계약

동작: 결정적으로 생성되는 TerritoryId 타입과 충돌 규칙을 정의한다.

검증: 동일 seed와 partition 입력이 같은 TerritoryId를 만든다.

#### 10-11. TerritoryEntity 타입

동작: id, nullable ownerCountryId, geometry와 properties를 가진 TerritoryEntity를 정의한다.

검증: 국가 metadata를 TerritoryEntity에 중복 저장하지 않는다.

#### 10-12. Territory owner 참조 불변식

동작: ownerCountryId가 active country 또는 null만 가리키도록 validator를 구현한다.

검증: unknown·retired owner 참조를 거부한다.

#### 10-13. 단일 실효 지배 불변식

동작: 하나의 Territory가 owner를 하나만 가지도록 표현과 validator를 확정한다.

검증: 복수 owner 입력과 겹치는 control 표현을 거부한다.

#### 10-14. 결정적 countryOrder

동작: active 국가 iteration order의 생성·삭제 규칙을 정의한다.

검증: record insertion order에 영향받지 않는다.

#### 10-15. 결정적 territoryOrder

동작: Territory iteration order의 생성·partition·merge 규칙을 정의한다.

검증: geometry feature 입력 순서에 영향받지 않는다.

#### 10-16. retiredCountryIds registry

동작: 삭제 확정 ID를 기록하는 registry를 구현한다.

검증: undo 복원은 허용하고 신규 재사용은 거부한다.

#### 10-17. TopologyState 타입

동작: canonical edge, neighbor와 coast/internal 분류를 담을 최소 타입을 정의한다.

검증: 동일 edge를 양쪽 국가에 중복 소유시키지 않는다.

#### 10-18. WorldState v2 container

동작: country, territory, topology, order, version과 hash root를 결합한 WorldState v2를 정의한다.

검증: 각 domain collection의 책임이 겹치지 않아야 한다.

#### 10-19. seed v1→v2 변환

동작: 기존 seed 국가와 geometry를 v2 Country·Territory로 변환한다.

검증: 국가, geometry, 수도, 이름 손실 0과 전체 unit suite 통과.

### C. 영역별 계층 hash

#### 10-20. canonical primitive serializer

동작: 문자열, boolean, null과 숫자의 locale 비의존 serializer를 구현한다.

검증: locale과 object insertion order에 무관한 byte sequence를 만든다.

#### 10-21. canonical geometry serializer

동작: policy precision과 winding을 적용한 geometry serializer를 구현한다.

## 8. 금지 구현

- CountryEntity에 geometry, 경제, 외교, 국가 중점 데이터를 모두 중첩한 거대 객체
- 여러 국가 polygon의 중첩으로 claim을 표현하는 구현
- 일반 command가 geometry tolerance나 winding policy를 선택하는 구현
- 소유 Territory가 남은 국가의 묵시적 삭제
- 국가 삭제 시 geometry를 지도에서 묵시적으로 제거
- 삭제된 countryId의 신규 국가 재사용
- command payload의 `allow-empty-world`
- prompt가 올바르다는 이유로 runtime planner 검증 생략
- schema parser에서 store·cache·MapLibre 수정
- MapLibre·Worker와 domain store를 완전한 단일 transaction으로 가장
- polygon outline을 최종 shared-border topology로 사용
- projection 실패를 domain state rollback으로 숨기는 구현
- revision, issuedAt, commandId를 worldContentHash에 포함
- 국가 변경마다 전체 module·label·search index 재계산
- 전체 artifact snapshot을 무제한 undo history에 저장
- LLM·UI·MapLibre의 WorldState 직접 수정

## 9. 후속 확장 계약

외교, 경제, 국가 중점과 claim module은 다음 규칙으로 추가한다.

- countryId를 참조하되 CountryEntity 내부에 대규모 데이터를 중첩하지 않는다.
- 독립 schemaVersion과 module hash를 가진다.
- WorldPatch에 module hash delta를 추가한다.
- 삭제 국가 참조 정리 정책을 module별로 정의한다.
- 관계 데이터는 canonical country pair key를 사용한다.
- claim은 실효 지배 owner와 분리하며 현재 Territory geometry를 중복 소유하지 않는다.

후속 자연어 시스템은 schema validator를 우회하지 않고 현재 WorldState 검색 결과로 countryId와 territoryId를 resolve해야 한다. 큰 영토 변경, 모호한 대상과 국가 소멸은 dry-run preview와 사용자 승인을 요구한다.
