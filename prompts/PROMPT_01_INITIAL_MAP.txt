당신은 “Pax Local” 프로젝트의 지도 프런트엔드 개발 담당자다.

이 프로젝트는 2020년 1월 1일 OTL(Original Timeline)을 출발점으로 하는
지도 기반 대체역사 시뮬레이션이다.

이번 작업 범위는 오직 “PC용 세계 지도와 플레이 국가 선택 기능”이다.
OpenAI API, AI 시뮬레이션, 턴 엔진, 외교 시스템, 전쟁 시스템, SQLite,
사용자 계정은 아직 구현하지 않는다.

완성된 지도 앱은 이후 별도의 게임 엔진과 OpenAI API를 연결할 수 있도록
확장 가능한 구조여야 한다.

이 프로젝트는 Windows 데스크톱 PC 전용이다.
모바일, 태블릿, 터치스크린 환경은 지원하지 않는다.

1. 작업 위치와 현재 환경
==================================================

작업 폴더:

D:\SSAFY\WORKSPACE\pax-local

운영체제:

Windows / PowerShell

확인된 개발 환경:

- Node.js v24.18.0
- Docker 설치됨
- NVIDIA RTX 5060 Ti 16GB
- RAM 32GB
- PowerShell 실행 정책 때문에 npm.ps1을 직접 실행할 수 없음

중요:

PowerShell에서 `npm` 대신 반드시 `npm.cmd`를 사용한다.

예:

npm.cmd install
npm.cmd run dev
npm.cmd run build
npm.cmd test

npx를 사용해야 한다면 `npx.cmd`를 사용한다.

프로젝트 폴더가 존재하지 않으면 생성한다.
이미 존재한다면 파일을 덮어쓰기 전에 현재 구조와 변경 사항을 확인하고
기존 작업을 보존한다.

Git 저장소가 있다면 기존 사용자 변경 사항을 삭제하거나 되돌리지 않는다.
git reset --hard, git checkout -- 등의 파괴적인 명령을 사용하지 않는다.

==================================================
2. 프로젝트 목표
==================================================

브라우저에서 다음 흐름이 완전하게 작동해야 한다.

1. 앱을 실행한다.
2. 2020년 세계 지도가 화면 전체에 표시된다.
3. 지도에서 국가에 마우스를 올리면 해당 국가가 강조된다.
4. 국가를 클릭하면 선택 상태가 된다.
5. 오른쪽 정보 패널에 해당 국가의 기본 정보가 표시된다.
6. 검색창에서 한국어 또는 영어 국가명으로 국가를 찾을 수 있다.
7. 검색 결과를 선택하면 지도가 해당 국가로 이동한다.
8. “이 국가로 시작” 버튼을 누르면 해당 국가가 플레이 국가로 저장된다.
9. 새로고침해도 선택된 플레이 국가가 유지된다.
10. 다른 국가를 선택하면 기존 플레이 국가가 교체된다.

한 게임에서 플레이어가 통제하는 국가는 정확히 하나다.

대한민국만 선택할 수 있는 것이 아니라 지도 데이터에 포함된 모든
플레이 가능 국가 중 하나를 선택할 수 있어야 한다.

다중 국가 동시 선택 기능은 구현하지 않는다.

4. 기술 스택
==================================================

다음 기술을 사용한다.

필수:

- Next.js App Router
- React
- TypeScript strict mode
- Tailwind CSS
- MapLibre GL JS
- Zustand
- Zod
- Vitest
- React Testing Library
- Playwright
- ESLint

권장 설치 절차:

1. 작업 루트로 이동한다.

   Set-Location 'D:\SSAFY\WORKSPACE'

2. 프로젝트가 없다면 생성한다.

   npx.cmd create-next-app@latest pax-local --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm

3. 프로젝트로 이동한다.

   Set-Location 'D:\SSAFY\WORKSPACE\pax-local'

4. 지도 및 상태 관리 패키지를 설치한다.

   npm.cmd install maplibre-gl zustand zod

5. 테스트 도구를 설치한다.

   npm.cmd install -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event @playwright/test

설치 전에 package.json이 이미 존재한다면 현재 의존성을 먼저 확인한다.
필요한 패키지만 추가하고 무관한 패키지를 제거하지 않는다.

MapLibre CSS를 애플리케이션에서 반드시 불러온다.

import "maplibre-gl/dist/maplibre-gl.css";

MapLibre를 사용하는 지도 컴포넌트는 브라우저 전용 Client Component로
구현한다. SSR 중 window 또는 WebGL 접근 오류가 발생하지 않아야 한다.

5. 외부 서비스 제한
==================================================

지도 MVP는 다음 서비스를 요구해서는 안 된다.

- Mapbox API 키
- Google Maps API
- 유료 지도 타일
- OpenAI API
- Supabase
- Firebase
- 외부 인증 서비스

앱의 핵심 국가 지도는 로컬 GeoJSON만으로 표시되어야 한다.

외부 배경 타일이 로딩되지 않아도 다음 요소는 정상 작동해야 한다.

- 바다 배경
- 국가 영토
- 국경선
- 국가명
- 국가 선택
- 국가 검색
- 국가 정보 패널

초기 버전에서는 실제 지형·도로·위성 이미지를 구현하지 않아도 된다.
단색 또는 은은한 그라데이션의 바다 배경 위에 국가 폴리곤을 표시한다.

==================================================
6. 지도 데이터
==================================================

공개된 Natural Earth 기반 데이터를 사용한다.

필요 데이터:

- Admin 0 Countries
- Populated Places 또는 별도로 정리한 수도 데이터

원본 데이터의 라이선스와 출처를 확인하고 다음 파일에 기록한다.

data/ATTRIBUTION.md

지도 UI 하단에도 간결한 출처 표기를 표시한다.

예:

Map data: Natural Earth

원본 Shapefile을 앱에서 직접 읽지 않는다.
브라우저에서 사용할 수 있도록 GeoJSON으로 변환하고 정규화한다.

권장 결과 파일:

public/data/maps/countries-2020.geojson
public/data/maps/country-labels-2020.geojson
public/data/maps/capitals-2020.geojson
src/data/countries-2020.json

국가 폴리곤의 각 feature에는 최소 다음 속성이 있어야 한다.

{
  "type": "Feature",
  "properties": {
    "countryId": "KOR",
    "iso3": "KOR",
    "nameEn": "South Korea",
    "nameKo": "대한민국",
    "mapColor": "#B8D8C0",
    "playable": true
  },
  "geometry": {}
}

countryId는 앱 전체에서 사용하는 안정적인 내부 식별자다.
가능한 경우 ISO 3166-1 alpha-3 코드를 사용한다.

Natural Earth의 일부 영역은 ISO 코드가 -99 또는 누락될 수 있으므로
그 값을 그대로 내부 ID로 사용하지 않는다.

정규화 과정에서 ADM0_A3 등의 필드를 확인하고 명시적인 보정 테이블을 둔다.

권장 위치:

src/data/country-id-overrides.ts

지도 geometry와 게임 국가 데이터는 분리한다.

GeoJSON은 지도 형상과 feature ID를 담당한다.
countries-2020.json은 표시 이름과 국가 정보를 담당한다.

- GDP 세부 통계

필요하면 다음 속성을 사용한다.

- disputed
- claimants
- mapDisplayPolicy

8. 데이터 정규화 도구
==================================================

원본 지도 데이터를 수동 편집하는 대신 재실행 가능한 변환 스크립트를 만든다.

권장 위치:

scripts/prepare-map-data.mjs

스크립트가 수행할 작업:

1. 원본 GeoJSON 읽기
2. 필요한 속성만 남기기
3. countryId 정규화
4. 한국어·영어 국가 데이터 연결
5. 플레이 가능 여부 추가
6. 기본 지도 색상 추가
7. 잘못된 geometry 검사
8. 결과 GeoJSON 생성
9. 국가 수와 누락된 ID 출력
10. 파일 크기 출력

원본 데이터는 다음 위치에 둘 수 있다.

data/raw/

생성 결과만 앱의 public 폴더에 둔다.

package.json에 다음 스크립트를 추가한다.

"data:prepare": "node scripts/prepare-map-data.mjs"

변환 스크립트는 같은 입력으로 실행할 때 동일한 결과를 생성해야 한다.

국가 색상은 무작위로 매 실행마다 변경되면 안 된다.
미리 정의한 팔레트 또는 countryId 기반의 결정적 해시를 사용한다.

인접 국가가 가능한 한 비슷한 색상이 되지 않도록 하되,
MVP에서는 완벽한 그래프 컬러링까지 요구하지 않는다.

==================================================
11. 지도 초기화
==================================================

지도는 다음 기본값을 사용한다.

- center: [10, 20] 부근
- zoom: 전 세계가 보이는 수준
- minZoom: 세계 전체보다 지나치게 축소되지 않도록 제한
- maxZoom: 국가 선택에 충분한 수준
- renderWorldCopies: false
- attributionControl: true
- dragRotate: false
- pitchWithRotate: false
- pitch: 0
- 과도한 3D 효과 사용 금지

전략 지도이므로 회전과 3D 기울기를 사용하지 않는다.

지원 입력:

- 마우스 클릭
- 마우스 드래그
- 마우스 휠 확대·축소
- 키보드 검색

터치 입력은 구현하거나 테스트하지 않는다.

지도 컴포넌트가 unmount될 때 MapLibre 인스턴스와 이벤트 리스너를
정상적으로 제거한다.

React Strict Mode에서 지도가 두 번 생성되거나
“container is already initialized” 오류가 발생하지 않아야 한다.

사이드 패널 및 브라우저 창 크기 변화에 대응하여
지도가 올바르게 resize되어야 한다.

==================================================
12. 지도 스타일과 레이어
==================================================

레이어 순서는 최소 다음과 같다.

1. 바다 배경
2. 국가 영토 fill
3. 내부 국경선
4. 국가 외곽선
5. 호버 강조
6. 선택 국가 강조
7. 확정된 플레이 국가 강조
8. 국가명 라벨
9. 수도 마커
10. 수도명 라벨

국가 영토:

- 파스텔 계열 색상
- 기본 opacity는 0.9 이상
- 국경선은 확대 수준에 따라 두께 조정
- 해안과 국가 경계가 명확해야 함

호버 상태:

- 커서를 pointer로 변경
- 국가 fill을 약간 밝게 표시
- 얇은 밝은 외곽선 표시
- MapLibre feature-state 또는 별도 필터 레이어 사용
- 이전 호버 상태 정상 해제

선택 상태:

- 호버보다 강한 외곽선
- 선택 국가 fill을 약간 밝게 표시
- 다른 국가는 약간 낮은 채도 또는 opacity
- 검색과 지도 클릭에서 동일하게 적용

확정된 플레이 국가:

- 후보 선택 상태와 시각적으로 구분
- 아이콘, 배지 또는 별도의 외곽선 사용
- 색상만으로 상태를 구분하지 않음

라벨:

- 기본 UI 언어는 한국어
- 낮은 줌에서는 너무 작은 국가의 라벨을 숨길 수 있음
- 텍스트 halo를 적용하여 가독성 확보
- MapLibre의 라벨 충돌 처리 활용
- 국가명은 별도 label point 데이터 사용
- 글자가 국경을 심하게 벗어나지 않게 조정

수도:

- 낮은 줌에서는 주요 국가 수도만 표시 가능
- 확대하면 더 많은 수도 표시
- 수도 마커와 국가명 라벨 충돌 최소화

==================================================
13. 지도 인터랙션
==================================================

국가 클릭:

1. 클릭한 feature의 countryId를 읽는다.
2. 정규화된 국가 데이터를 조회한다.
3. selectedCountryId를 갱신한다.
4. 오른쪽 정보 패널을 연다.
5. 선택 강조 레이어를 갱신한다.

지도 전체를 다시 초기화하지 않는다.

국가 호버:

1. hoveredCountryId를 갱신한다.
2. 해당 국가를 밝게 표시한다.
3. 커서를 pointer로 바꾼다.
4. 다른 국가로 이동하면 기존 상태를 해제한다.
5. 바다로 이동하면 호버 상태를 제거한다.

빈 바다 클릭:

- 현재 후보 선택을 해제할 수 있다.
- 확정된 playerCountryId는 삭제하지 않는다.

더블 클릭:

- 기본 확대 동작을 허용할 수 있다.
- 선택 이벤트가 중복 처리되지 않게 한다.

우클릭:

- 특별한 기능을 구현하지 않는다.
- 브라우저 기본 컨텍스트 메뉴를 유지해도 된다.

==================================================
14. 국가 검색
==================================================

검색은 최소 다음을 지원한다.

- 한국어 국가명
- 영어 국가명
- ISO3 코드
- 대소문자 무시
- 앞뒤 공백 무시
- 부분 일치
- 키보드 위/아래 탐색
- Enter 선택
- Escape 닫기

예:

“대한” → 대한민국
“korea” → South Korea, North Korea
“FRA” → France
“jap” → Japan

검색 결과는 최대 8개를 표시한다.
외부 검색 API를 사용하지 않는다.

검색 결과를 선택하면:

1. 해당 국가를 selectedCountryId로 설정한다.
2. 오른쪽 정보 패널을 연다.
3. 지도 카메라를 해당 국가로 이동한다.
4. 국가 크기에 맞는 확대 수준을 적용한다.
5. 검색 드롭다운을 닫는다.
6. 선택 강조 레이어를 갱신한다.

검색 입력이 비어 있으면 결과 목록을 닫는다.

검색 결과 정렬 우선순위:

1. 완전 일치
2. 이름 시작 부분 일치
3. 부분 일치
4. 한국어·영어 이름
5. ISO 코드

==================================================
15. 플레이 국가 선택
==================================================

다음 세 상태를 구분한다.

- hoveredCountryId
- selectedCountryId
- playerCountryId

의미:

- hoveredCountryId: 현재 마우스를 올린 국가
- selectedCountryId: 현재 정보 패널에서 확인 중인 국가
- playerCountryId: 게임 시작 대상으로 확정된 단일 국가

정보 패널에는 다음을 표시한다.

- 국기
- 한국어 국가명
- 영어 국가명
- 수도
- 지역
- 2020년 1월 1일 기준 표시
- 플레이 가능 여부
- “이 국가로 시작” 버튼

버튼을 누르면:

1. playerCountryId를 선택 국가로 설정한다.
2. 기존 playerCountryId가 있으면 새 국가로 교체한다.
3. localStorage에 저장한다.
4. 성공 상태를 명확하게 표시한다.
5. 확정된 국가를 지도에서 별도로 강조한다.

한 번에 하나의 playerCountryId만 존재해야 한다.

다음 구조는 사용하지 않는다.

controlledCountryIds: string[]

다음 구조를 사용한다.

playerCountryId: string | null

아직 실제 게임 화면으로 이동하지 않아도 된다.
다음 단계에서 라우팅을 붙일 수 있도록 명확한 함수를 제공한다.

예:

confirmPlayerCountry(countryId)

==================================================
16. 상태 관리
==================================================

Zustand store가 최소 다음 상태를 관리한다.

type GameSetupState = {
  scenarioId: "2020-otl";
  scenarioDate: "2020-01-01";
  hoveredCountryId: string | null;
  selectedCountryId: string | null;
  playerCountryId: string | null;
  searchQuery: string;
  isCountryPanelOpen: boolean;
};

필요 액션:

- setHoveredCountry
- selectCountry
- clearSelectedCountry
- confirmPlayerCountry
- setSearchQuery
- restorePersistedState
- resetGameSetup

지도 인스턴스 자체를 Zustand에 넣지 않는 것을 권장한다.
지도 인스턴스는 WorldMap 내부 ref로 관리한다.

일시적 호버 상태는 localStorage에 저장하지 않는다.
검색 문자열도 저장하지 않는다.

==================================================
17. 상태 저장
==================================================

MVP에서는 SQLite를 사용하지 않는다.

다음 정보만 localStorage에 저장한다.

{
  "scenarioId": "2020-otl",
  "scenarioDate": "2020-01-01",
  "playerCountryId": "FRA"
}

localStorage 접근은 브라우저에서만 수행한다.
SSR hydration mismatch가 발생하지 않아야 한다.

저장 데이터는 Zod로 검증한다.
잘못되거나 오래된 값이면 안전하게 무시하고 기본 상태로 시작한다.

저장 키는 버전을 포함한다.

pax-local:game-setup:v1

저장된 playerCountryId가 현재 국가 데이터에 존재하지 않거나
playable이 false라면 무시한다.

18. 디자인 방향
==================================================

원본 Pax Historia의 로고, 이미지, CSS, 아이콘, 소스 코드 또는
고유 자산을 복사하지 않는다.

다만 다음과 같은 전략 지도 경험은 참고할 수 있다.

- 지도가 화면의 중심
- 상단에 얇은 헤더
- 오른쪽에 고정 국가 정보 패널
- 지도 위에 떠 있는 검색 컨트롤
- 밝고 부드러운 국가 색상
- 선명한 국경선
- 최소한의 장식
- 역사 지도책과 현대 전략 게임의 중간 느낌

색상 방향:

- 배경: 미색 또는 밝은 회색
- 바다: 낮은 채도의 청색
- 국가: 파스텔 팔레트
- 선택: 밝은 외곽선
- 확정된 플레이 국가: 별도 강조색
- 텍스트: 검정에 가까운 회색
- 패널: 반투명한 흰색 또는 옅은 크림색

UI는 한국어를 기본으로 한다.

사용 문구 예:

- 국가 검색
- 2020년 1월 1일
- 선택한 국가
- 수도
- 지역
- 이 국가로 시작
- 플레이 국가로 선택됨
- 검색 결과가 없습니다
- 지도 데이터를 불러오는 중입니다

이모지를 주요 UI 아이콘으로 사용하지 않는다.
아이콘이 필요하면 단순한 SVG 또는 일관된 아이콘 라이브러리를 사용한다.

과도한 둥근 카드, 거대한 제목, 마케팅 랜딩 페이지 같은 디자인은 피한다.
지도 애플리케이션처럼 조밀하고 실용적인 화면을 만든다.

==================================================
19. 데스크톱 레이아웃 대응
==================================================

모바일 반응형 UI는 구현하지 않는다.

대신 다음 데스크톱 화면 크기에서 정상 동작해야 한다.

1280×720:

- 모든 핵심 기능 표시
- 오른쪽 패널 약 340~360px
- 지도 검색 사용 가능
- 버튼과 정보가 화면 밖으로 잘리지 않음

1440×900:

- 기본 개발 및 검증 해상도
- 오른쪽 패널 약 380px
- 지도와 정보 패널이 균형 있게 표시

1920×1080 이상:

- 지도 영역이 자연스럽게 확장
- 패널 너비는 지나치게 넓어지지 않음
- 콘텐츠 최대 너비를 적절히 제한

2560×1440:

- 지도 라벨과 컨트롤이 너무 작아 보이지 않게 유지
- 정보 패널은 고정된 합리적 너비 유지

브라우저 창 너비가 1280px 미만이면 지원 안내 화면 또는 경고를 표시한다.

모바일용으로 다음 기능을 만들지 않는다.

- 하단 시트
- 햄버거 메뉴
- 터치 전용 제스처
- 모바일 검색 레이아웃
- 세로 화면 레이아웃
- 44px 터치 영역 규칙
- 모바일 Safe Area 처리
- 모바일 브라우저 테스트

==================================================
20. 접근성
==================================================

MapLibre 캔버스만으로 국가 선택 기능을 제공하지 않는다.

키보드 사용자는 검색을 통해 모든 플레이 가능 국가를 선택할 수 있어야 한다.

요구사항:

- 검색 입력에 label 또는 aria-label 제공
- 검색 결과에 listbox/option 의미 제공
- 위/아래 방향키로 결과 이동
- Enter로 결과 선택
- Escape로 결과 닫기
- 선택 버튼에 명확한 accessible name 제공
- 포커스 표시 제거 금지
- 색상만으로 선택 상태를 표현하지 않음
- 정보 패널에 적절한 heading 구조 제공
- 로딩 및 오류 메시지를 스크린 리더가 인식하도록 처리
- 국기 alt 속성을 적절하게 처리
- 충분한 텍스트 대비 유지

터치 접근성은 이번 범위에 포함하지 않는다.

==================================================
21. 오류와 로딩 처리
==================================================

다음 상태를 구현한다.

- 지도 데이터 로딩 중
- 지도 데이터 로딩 실패
- WebGL을 사용할 수 없음
- 선택한 countryId에 대응하는 국가 데이터 없음
- GeoJSON feature에 countryId가 없음
- localStorage 값이 손상됨
- 검색 결과 없음
- 지원하지 않는 화면 크기

오류가 발생하면 흰 화면이 되지 않아야 한다.

사용자에게 한국어로 이해 가능한 메시지를 표시한다.

예:

- 지도 데이터를 불러오지 못했습니다.
- 브라우저에서 WebGL을 사용할 수 없습니다.
- 선택한 국가 정보를 찾을 수 없습니다.
- 1280×720 이상의 PC 화면에서 이용해 주세요.

필요한 경우 다시 시도 버튼을 제공한다.

개발 환경에서는 누락된 국가 ID를 console warning으로 출력할 수 있지만,
동일한 경고를 무한 반복하지 않는다.

==================================================
22. 성능 요구사항
==================================================

모바일 최적화는 하지 않지만 PC에서도 불필요하게 무거워지지 않게 한다.

요구사항:

- 지도 생성은 한 번만 수행
- React 상태가 바뀔 때 지도 전체 재생성 금지
- 선택 및 호버는 layer filter 또는 feature-state 사용
- 대형 GeoJSON을 매 렌더마다 복사하거나 변환하지 않음
- 국가 검색 인덱스는 최초 한 번 생성
- 불필요한 React re-render 최소화
- 이벤트 리스너 중복 등록 금지
- 컴포넌트 해제 시 이벤트 리스너 제거
- 국가명 변경 때문에 전체 GeoJSON을 다시 내려받지 않음
- production build에서 심각한 console error가 없어야 함
- 첫 지도 로딩 중 명확한 로딩 UI 표시

지도 데이터가 지나치게 크다면:

- geometry 단순화
- 불필요한 properties 제거
- 적절한 소수점 정밀도 축소

단, 국경 형상이 눈에 띄게 파괴되지 않게 한다.

가능하면 지도 데이터의 압축 전후 크기를 README에 기록한다.

- 국가 정보 패널 렌더링

- 검색 결과 선택

E2E 테스트:

1. 1440×900 화면으로 홈 화면을 연다.
2. 세계 지도가 표시되는지 확인한다.
3. 검색창에 “프랑스”를 입력한다.
4. 프랑스를 선택한다.
5. 정보 패널에 “프랑스”와 “파리”가 표시되는지 확인한다.
6. “이 국가로 시작”을 누른다.
7. 플레이 국가 확정 표시를 확인한다.
8. 새로고침한다.
9. 플레이 국가가 프랑스로 유지되는지 확인한다.
10. 일본을 검색한다.
11. 일본을 플레이 국가로 확정한다.
12. 프랑스가 아니라 일본 하나만 저장되었는지 확인한다.

추가 E2E 검증:

- 1280×720
- 1920×1080
- 2560×1440

모바일 뷰포트 테스트는 작성하지 않는다.

WebGL을 사용하는 지도 자체와 일반 UI 테스트를 분리한다.
필요하면 단위 테스트에서 MapLibre를 mock한다.

최종 검증은 실제 데스크톱 Chromium 브라우저에서 수행한다.

28. 작업 방식
==================================================

먼저 현재 작업 폴더와 기존 파일을 조사한다.
그다음 짧은 구현 계획을 세우고 실제 개발을 진행한다.

불필요한 확인 질문은 하지 말고,
안전한 범위에서는 합리적인 가정을 사용한다.

데이터 다운로드나 패키지 설치에 네트워크 승인이 필요하면
적절한 승인 요청을 한다.

각 주요 단계마다 실제 실행으로 검증한다.
코드를 작성한 것만으로 완료했다고 판단하지 않는다.

디자인 구현 후 실제 브라우저에서 다음을 직접 확인한다.

- 지도가 화면을 정확하게 채우는가
- 국가 색상과 국경이 읽기 쉬운가
- 국가명이 과도하게 겹치지 않는가
- 오른쪽 패널이 지도를 비정상적으로 가리지 않는가
- 검색과 선택 흐름이 자연스러운가
- 1280×720에서도 핵심 기능이 잘리지 않는가
- 2560×1440에서도 UI가 지나치게 작아 보이지 않는가

최종 응답에는 다음을 간결하게 보고한다.

- 구현한 기능
- 주요 파일
- 지도 데이터 출처
- 실행 방법
- 수행한 테스트와 결과
- 검증한 PC 화면 크기
- 남아 있는 제한
- 다음 단계에서 게임 엔진과 AI를 연결할 확장 지점

이 작업의 최우선 목표는 “보기 좋은 정적 지도”가 아니라,
PC에서 국가를 탐색하고 원하는 국가 하나를 플레이 국가로 선택할 수 있는
안정적인 지도 애플리케이션을 완성하는 것이다.
