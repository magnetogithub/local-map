# Prompt 08 — 국가 폴리곤 기반 world-space 국가명 글자

당신은 `D:\SSAFY\WORKSPACE\pax-local` 프로젝트의 구현 에이전트다. 사용자에게는 한국어로 보고한다.

이 문서는 Prompt 08의 새로운 권위 문서다. 과거 Prompt 08의 데이터 소유권 경계는 필요한 범위에서 재사용할 수 있지만, 과거 단계 번호와 실패한 MapLibre symbol 줌 밴드 접근은 계승하지 않는다.

이 프롬프트의 범위는 오직 지도 위 국가명 글자의 생성, 배치, 렌더링, 스타일, 검증이다. 공식 국호 변경, 국가 데이터 정리, 국경 topology, Admin 1, 국가 생성·소멸, 게임 이벤트, 저장·복원, 검색 alias, UI 재설계는 구현하지 않는다.

---

## 1. 실행 원칙과 순서

1. 시작 전에 `AGENTS.md`와 설치된 Next.js 버전의 관련 문서를 읽는다.
2. 과거 PASS 로그를 신뢰하지 말고 현재 코드, 데이터, 실제 renderer로 재검증한다.
3. 기존 사용자 변경과 `CountryEntity → WorldState → map artifacts → setData()` 경계를 보존한다.
4. 국가별 글자 좌표를 하드코딩하지 않는다. 예외는 `fontScale`, `curvature`, `letterSpacing`, `insideRatioTarget`, `fallbackMode` 같은 정책 값으로만 표현하고 근거를 기록한다.
5. 실패를 숨기거나 validator 허용 기준을 임의로 낮추지 않는다.
6. `8-1`부터 `8-31`까지 각각이 독립 승인 단계다. 한 단계의 구현과 독립 검증을 끝낸 뒤 보고하고 반드시 종료한다. 사용자 확인 없이 다음 번호로 넘어가지 않는다.
7. 한 단계가 실패하면 후속 단계는 실행하지 않는다.

### 모든 번호에 적용하는 단계 완료 프로토콜

각 `8-N` 단계는 다음 절차를 반드시 자체적으로 수행한다.

1. 선행 단계 보고서가 `pass`이고 현재 입력 hash와 일치하는지 확인한다.
2. 해당 단계 전용 보고서 `reports/fix08-N-<slug>.json`을 `running`으로 원자 초기화한다.
3. 그 단계에 명시된 범위만 구현한다. 후속 단계의 제품 코드, 테스트, 보고서를 미리 작성하지 않는다.
4. 정적 검증과 필요한 최소 실행 검증을 수행한다.
5. 실행 명령, 종료 코드, 입력·출력 hash, 변경 파일, 원시 수치, 실패 게이트를 보고서에 쓴다.
6. 모든 게이트가 통과하면 `pass`, 구현 오류면 `fail`, 환경 때문에 완료할 수 없으면 `blocked`로 판정한다.
7. 사용자에게 결과와 산출물 경로를 보고하고 반드시 종료한다.

각 단계 보고서는 최소한 다음 필드를 가진다.

```json
{
  "stage": "8-N",
  "status": "running | pass | fail | blocked",
  "inputHashes": {},
  "outputHashes": {},
  "changedFiles": [],
  "commands": [{"command": "", "exitCode": 0, "durationMs": 0}],
  "gates": {},
  "implementationErrors": [],
  "environmentErrors": [],
  "nextStage": "8-(N+1)"
}
```

`nextStage`는 안내 정보일 뿐 자동 실행 권한이 아니다.

## 2. 권위 있는 렌더링 모델

curved 국가명은 MapLibre `symbol`의 `text-field`, `text-size`, `symbol-placement: line`, collision placement로 렌더링하지 않는다. 폰트 glyph outline을 지도상의 world-space geometry로 변환하여 국가 polygon과 같은 지도 좌표계에서 렌더링한다.

```text
CountryEntity geometry + mapLabelKo
  → shape-aware baseline
  → font glyph outline
  → glyph advance와 kerning
  → baseline 위 glyph 배치
  → 접선 방향 회전과 곡률 적용
  → 지도 좌표의 glyph polygon
  → fill/outline artifact
  → 전용 source/layer 렌더링
```

국가 polygon과 글자 polygon은 같은 좌표계에서 움직이지만 boolean union하지 않는다. 글자는 국가로부터 결정적으로 파생되는 별도 artifact다. 국가 면적, 클릭 판정, 국경 topology와 territory fill이 글자 때문에 변해서는 안 된다.

### 반드시 제거할 curved 렌더링 의존성

- 줌 이벤트의 `setLayoutProperty("text-size", ...)`
- quarter-zoom 또는 기타 zoom-band layer 전환
- MapLibre `textMaxSize`
- symbol collision box
- fixed pixel size 또는 pixel cap
- symbol 존재 여부를 이용한 curved 라벨 성공 판정

Point fallback에는 기존 symbol을 제한적으로 유지할 수 있지만 curved 대상에는 적용하지 않는다.

### 구현 우선순위

1차안은 glyph outline을 Polygon/MultiPolygon artifact로 만들어 MapLibre fill 계열 layer로 그리는 방식이다. 다음 중 하나가 수치로 입증될 때만 국가명 전용 WebGL custom layer를 허용한다.

- 한글 glyph의 contour와 hole을 GeoJSON polygon으로 정확히 표현할 수 없음
- geometry 크기 또는 렌더 비용이 성능 예산을 명백히 초과함
- fill과 outline을 모두 world-space로 유지할 수 없음

WebGL을 선택해도 이 문서의 world-space 비율, 결정성, artifact 변경 전파, 인스턴스 수, 픽셀 스타일 게이트는 그대로 지킨다.

## 3. 공통 데이터 계약

### 입력

- `countryId`
- 현재 `CountryEntity.geometry`
- 현재 `mapLabelKo`
- 프로젝트에 포함된 실제 폰트 bytes와 font hash
- geometry에서 계산한 baseline
- 명시적인 정책 값

브라우저 또는 OS 폰트 fallback과 정적 GeoJSON의 과거 계산값을 진실 원본으로 사용하지 않는다.

### 출력

각 curved 국가는 다음 정보를 잃지 않는 artifact를 생성한다.

```ts
type CountryLabelGlyphArtifact = {
  countryId: string;
  labelInstanceId: string;
  text: string;
  geometryHash: string;
  fontHash: string;
  layoutVersion: string;
  baseline: LineString;
  glyphs: Array<{
    glyphIndex: number;
    codePoint: number;
    advanceWorld: number;
    baselineDistanceWorld: number;
    tangentAngle: number;
    fillGeometry: Polygon | MultiPolygon;
    outlineGeometry?: Polygon | MultiPolygon;
  }>;
  boundsWorld: [number, number, number, number];
  effectiveTerritoryWidthWorld: number;
  labelWidthWorld: number;
  widthRatio: number;
  insideRatio: number;
};
```

실제 타입명은 프로젝트에 맞춰도 된다.

### 결정성과 변경 전파

- 같은 geometry, 이름, 폰트, 정책은 실행 순서와 시각에 관계없이 같은 결과를 만든다.
- 난수와 OS locale에 의존하지 않는다.
- 좌표 precision과 collection 정렬 순서를 고정한다.
- 국가 artifact는 `countryId`, glyph는 `glyphIndex`, contour는 결정적인 기준으로 정렬한다.
- 이름만 바뀌면 territory는 유지되고 label artifact만 재생성된다.
- geometry가 바뀌면 baseline과 glyph artifact가 함께 재생성된다.
- 국가 추가·삭제가 모든 label collection과 source에 반영된다.
- 순수 artifact 함수에 MapLibre 객체를 전달하지 않는다.

## 4. 기반 조사·순수 geometry·대표 국가 통합

### 목적과 대상

대표 curved 국가명을 실제 glyph polygon으로 렌더링하여 국토와 글자가 같은 비율로 확대·축소되고 모든 연속 줌에서 사라지거나 중복되지 않음을 증명한다.

- 필수 대표 국가: `AUS`, `RUS`
- 초기 세계 화면 확인: `USA`, `RUS`, `CHN`
- 대표 국가는 Point fallback을 허용하지 않는다.

### 단계 운영 규칙

다음 순서를 바꾸지 않는다. 각 번호가 끝날 때 해당 번호 전용 보고서를 작성하고 사용자에게 보고한 뒤 종료한다. 실패 시 다음 번호로 진행하지 않는다.

#### 8-1. 현재 구현과 기존 데이터 경계 감사

1. `CountryEntity`, `WorldState`, `buildCountryMapArtifacts()`, `buildCountryMapArtifactCollections()`, source 갱신 함수의 실제 위치와 타입을 찾는다.
2. 기존 curved baseline 생성 함수, font metrics 계산 함수, MapLibre curved symbol layer, zoom-band 관련 상수와 이벤트 handler를 목록화한다.
3. 과거 데이터 경계 보고서의 주장과 현재 unit test를 대조한다.
4. 재사용할 코드, 교체할 코드, 8-7 PASS 후 제거할 코드를 표로 기록한다.
5. 이 단계에서는 제품 코드를 수정하지 않는다.

완료 증거: `reports/fix08-1-current-boundary-audit.json`, 파일·함수·source·layer 의존성 목록과 보존 계약.

#### 8-2. glyph outline 기술 탐색

1. 저장소의 실제 한국어 폰트 파일과 라이선스, font format, hash를 확인한다.
2. 현재 dependency로 glyph contour, advance, kerning을 읽을 수 있는지 확인한다.
3. 불가능하면 최소 의존성을 비교하되 설치 전에 기존 lockfile과 호환성을 확인한다.
4. 제품 통합 전에 테스트 코드에서 `호주`, `러시아`의 모든 glyph outline을 추출한다.
5. contour 수, hole 수, vertex 수, 누락 glyph를 JSON으로 기록한다.
6. curve flatten tolerance 후보를 최소 2개 비교하여 vertex 수와 시각 오차를 기록한다.

완료 게이트: 대표 문자열 누락 glyph 0, hole 보존, deterministic outline hash 동일.

완료 증거: `reports/fix08-2-font-outline-probe.json`과 대표 glyph 진단 이미지.

#### 8-3. 순수 world-space 변환 함수 구현

1. font unit의 glyph outline을 원점 기준 정규화한다.
2. 문자열의 advance와 kerning을 합산한다.
3. 국가 geometry로부터 baseline과 effective territory width를 계산한다.
4. 목표 width ratio로 단일 world-space scale을 계산한다.
5. 각 glyph의 누적 중심 거리를 baseline 거리로 변환한다.
6. baseline 위치와 접선을 계산하여 glyph를 지도 좌표로 변환한다.
7. contour winding과 hole 관계를 유지한 Polygon/MultiPolygon을 만든다.
8. dateline 국가에는 unwrap 상태에서 계산한 뒤 안전하게 split/wrap한다.
9. 결과를 canonical 순서와 고정 precision으로 직렬화한다.

완료 게이트: AUS/RUS artifact 생성, 유효 polygon, glyphIndex 연속, 동일 입력 hash 동일.

완료 증거: `reports/fix08-3-world-geometry-unit.json`과 순수 단위 테스트.

#### 8-4. 기존 artifact 파이프라인 확장

1. 기존 country artifact 타입에 glyph label artifact를 명시적으로 추가한다.
2. collection builder가 fill/outline feature collection을 생성하게 한다.
3. feature마다 `countryId`, `labelInstanceId`, `glyphIndex`, `role`, `geometryHash`를 넣는다.
4. 이름 변경, geometry 변경, 추가, 삭제 patch가 glyph collection까지 전파되게 한다.
5. 기존 다섯 source 갱신 계약을 깨지 말고 새 label source 갱신을 명시적으로 추가한다.
6. 정적 초기 데이터와 WorldState에서 파생한 초기 glyph collection의 동등성을 검사한다.

완료 게이트: 순수 unit test 통과, MapLibre import 없는 artifact 모듈, 변경 전파 테스트 통과.

완료 증거: `reports/fix08-4-artifact-pipeline.json`.

#### 8-5. MapLibre 임시 병행 통합

1. glyph fill과 진단용 outline source/layer를 추가한다.
2. layer 순서를 territory fill·국경·Admin 1·highlight와 비교해 명시한다.
3. feature flag 또는 debug toggle로 기존 symbol과 새 geometry renderer를 서로 배타적으로 전환한다.
4. 새 renderer 활성 시 기존 curved symbol layer를 숨긴다.
5. Point fallback layer에는 영향을 주지 않는다.
6. hover, 선택, 플레이 국가 상태가 glyph geometry 수를 바꾸지 않는지 확인한다.

완료 게이트: 정상 지도에서 AUS/RUS/USA/CHN이 새 geometry renderer로 보이고 기존 curved symbol 중복 0.

완료 증거: `reports/fix08-5-map-integration.json`과 초기 화면 스크린샷.

#### 8-6. renderer bounds와 debug API 구현

1. glyph feature 수와 논리적 label instance 수를 분리해 반환한다.
2. 실제 투영된 glyph polygon vertex로 renderer bounds를 계산한다.
3. baseline 또는 territory geometry의 실제 투영 bounds를 계산한다.
4. 각 결과에 renderer 종류, layer ID, worldCopy, glyphIndex 집합을 포함한다.
5. `isRenderSettled()`는 카메라 이동 종료뿐 아니라 source data와 style render 완료를 확인하게 한다.
6. 추정 문자열 폭은 진단 필드로만 남기고 PASS 계산에서 제외한다.

완료 게이트: E2E가 내부 MapLibre collision index 없이 실제 polygon bounds를 취득.

완료 증거: `reports/fix08-6-renderer-bounds.json`과 bounds 계약 테스트.

#### 8-7. 대표 국가 수치 검증

1. 고정 viewport와 초기 center를 설정한다.
2. 정상 지도에서 초기 `USA`, `RUS`, `CHN` 가시성을 기록한다.
3. AUS를 줌 1, 2, 3에서 측정하고 스크린샷을 저장한다.
4. RUS를 줌 1, 2, 3에서 같은 방식으로 측정한다.
5. 각 연속 줌의 label 성장률, territory 성장률, width ratio drift를 계산한다.
6. `1.2499/1.25/1.2501`, `1.4999/1.5/1.5001`을 순서대로 왕복 측정한다.
7. 각 경계에서 최소 2개의 안정 render frame을 관찰하고 0개·2개 인스턴스가 없는지 확인한다.
8. 같은 E2E를 새 브라우저 context에서 한 번 더 실행한다.

완료 게이트: 아래 대표 국가 브라우저 검증 기준 전부 충족.

완료 증거: `reports/fix08-7-representative-zoom.json`과 AUS/RUS 스크린샷.

#### 8-8. 기존 curved symbol 경로 제거와 회귀

1. 8-7이 PASS한 뒤에만 curved zoom-band 상수, 동적 `text-size` 변경, 사용하지 않는 curved symbol layer를 제거한다.
2. Point fallback symbol과 관련 size 함수는 필요한 범위만 보존한다.
3. debug API, 테스트, 타입에서 제거된 layer ID 참조를 정리한다.
4. unit test, lint, TypeScript 검사를 실행한다.
5. production build 오류가 있으면 구현 오류와 환경 오류를 분리한다.

완료 게이트: curved renderer에 zoom-band/textMaxSize 의존성 0, 기본 정적 검사 성공.

완료 증거: `reports/fix08-8-legacy-renderer-removal.json`.

### 폰트 outline 추출

- 저장소의 실제 한국어 폰트 파일을 사용한다.
- glyph advance, kerning, contour, hole을 보존한다.
- 복합 glyph는 변환을 적용해 최종 outline을 만든다.
- quadratic/cubic curve는 명시적인 고정 tolerance로 평탄화한다.
- tolerance는 줌에 따라 변하지 않는다.
- contour winding, hole 관계, self-intersection을 검사한다.
- 누락 glyph를 조용히 대체하지 말고 명시적으로 실패 또는 fallback 처리한다.

### baseline 배치

- 기존 geometry 기반 baseline 계산을 우선 재사용한다.
- 문자열 전체 advance와 baseline 유효 길이로 단일 world-space scale을 계산한다.
- 각 glyph를 누적 advance 거리로 baseline에 배치하고 해당 지점 접선으로 회전한다.
- rigid glyph 회전만 사용할지 outline 점을 곡선에 따라 변형할지 수치와 스크린샷으로 비교한다.
- 글자 순서가 baseline 진행 방향에서 역전되지 않아야 한다.
- 한글 내부 hole을 유지한다.
- dateline에서 polygon이 지구 반대편을 가로지르지 않도록 longitude unwrap/wrap 규칙을 구현하고 테스트한다.

### 크기 계약

```text
labelWidthWorld / effectiveTerritoryWidthWorld = targetWidthRatio
```

- artifact는 줌마다 다시 생성하지 않는다.

### 논리적 인스턴스 정의

## 5. 타이포그래피 정책

8-9까지 확정한 world-space glyph geometry renderer는 보존한다. 이 절은 renderer를 교체하지 않고, 글자 크기·자간·곡률·배치 폭을 예시와 같은 전략 지도 국가명에 맞게 개선한다.

현재처럼 문자열 전체 advance를 목표 폭에 맞추는 단일 scale 방식은 폐기한다. 짧은 국가명은 지나치게 커지고 긴 국가명은 지나치게 작아지기 때문이다.

### 권위 있는 타이포그래피 계약

다음 값을 서로 독립적으로 계산한다.

```text
glyphScale
  = 국토의 유효 짧은 축 또는 baseline 주변 가용 두께로 결정

naturalGlyphSpan
  = shaped glyph advance 합계 × glyphScale

targetLabelSpan
  = 실제 label corridor 길이 × targetSpanRatio

trackingWorld
  = (targetLabelSpan - naturalGlyphSpan) / max(glyphCount - 1, 1)
```

- `glyphScale`은 글자 자체의 크기만 결정한다.
- `trackingWorld`는 글자 사이 간격만 결정한다.
- 짧은 이름을 국토 폭에 맞추려고 glyph 자체를 거대하게 만들지 않는다.
- 긴 이름을 맞추려고 가독성 하한 아래로 축소하지 않는다.
- tracking이 허용 범위를 넘으면 target span을 줄이거나 fallback 정책을 적용한다.
- 한 글자 이름은 tracking을 사용하지 않고 corridor 중앙에 둔다.
- scale과 tracking은 world-space 값이며 줌에 따라 다시 계산하지 않는다.
- 국가별 좌표나 glyph별 위치를 하드코딩하지 않는다.

필수 정책 값:

- `glyphHeightRatio`
- `minGlyphHeightRatio`
- `maxGlyphHeightRatio`
- `targetSpanRatio`
- `minTrackingEm`
- `maxTrackingEm`
- `maxAbsoluteGlyphAngle`
- `maxAdjacentAngleDelta`
- `curvatureSmoothing`

정책 값은 공통 기본값을 우선 사용한다. 국가별 override가 필요하면 위 정책 값으로만 허용하고 전후 수치와 근거를 보고한다.

#### 8-10. glyph 크기와 tracking 분리

1. 기존 `targetWidth / totalAdvance` 단일 scale 계산의 호출부와 파생 필드를 목록화한다.
2. baseline 주변의 가용 두께 또는 territory minor-axis를 결정적으로 계산한다.
3. 그 두께에서 `glyphScale`과 glyph 높이를 계산한다.
4. shaped advance 합계로 `naturalGlyphSpan`을 계산한다.
5. corridor 길이와 `targetSpanRatio`로 `targetLabelSpan`을 계산한다.
6. 남는 길이를 glyph 사이에 `trackingWorld`로 균등 분배한다.
7. `glyphScale`, `naturalGlyphSpan`, `targetLabelSpan`, `trackingWorld`, tracking의 em 환산값을 artifact에 기록한다.
8. 1글자, 2~3글자, 4~6글자, 7글자 이상 synthetic 사례를 단위 테스트한다.
9. 동일 입력의 geometry와 hash가 결정적인지 검증한다.

완료 게이트:

- glyph 크기와 label span이 서로 다른 변수로 계산된다.
- RUS의 짧은 이름 때문에 glyph 높이가 국토 두께를 초과하지 않는다.
- AUS의 긴 이름이 가독성 하한보다 작아지지 않는다.
- glyph 순서와 hole, dateline 계약이 유지된다.
- 줌 밴드 또는 pixel cap을 다시 도입하지 않는다.

## 6. 전체 국가 품질과 fallback

### 단계 운영 규칙

8-13 보고서가 현재 코드 기준 `pass`인지 먼저 확인한다. 아니면 아무것도 구현하지 않고 차단 사유만 보고한다.

#### 8-14. 전체 입력 집합 고정

1. WorldState의 전체 국가 ID 집합을 읽는다.
2. curved 후보와 기존 Point fallback 집합을 계산한다.
3. 누락·중복·고아 artifact를 먼저 검사한다.
4. 기존 `182/74`와 차이가 있으면 국가 목록과 원인을 기록한다.

#### 8-15. 전체 glyph artifact 생성

1. 모든 curved 후보를 동일한 순수 함수로 생성한다.
2. 실패 국가도 결과 목록에서 제거하지 않고 failure record로 남긴다.
3. 국가별 glyph/contour/vertex/insideRatio/overlap/angle 지표를 기록한다.
4. 생성 순서를 뒤집어 hash 결정성을 표본 검사한다.

#### 8-16. 자동 geometry·타이포그래피 품질 판정

1. invalid polygon과 self-intersection을 검사한다.
2. glyphIndex, code point, 진행 방향을 검사한다.

#### 8-17. 정책 조정과 fallback 확정

3. 정책으로 해결할 수 없는 국가만 Point fallback으로 이동한다.
4. fallback 사유를 국가별로 기록한다.
5. curved와 Point 집합의 배타성과 전체 포괄성을 다시 검사한다.

#### 8-18. 난형 국가 실제 렌더 검증

1. `RUS`, `CAN`, `USA`, `CHL`, `IDN`, `AUS`, `JPN`을 정상 지도에서 연다.

### 전체 품질 게이트

각 curved 국가에 대해 다음을 계산한다.

- 문자열 code point 수, glyph 수, 누락 glyph 수
- baseline 길이, label width, territory width, width ratio
- glyph height, corridor thickness, glyph height ratio
- natural glyph span, target label span, trackingWorld, trackingEm
- invalid polygon과 self-intersection 수
- glyphIndex 누락·중복
- glyph 진행 방향 단조성
- 인접 glyph 중첩률과 접선 각도 변화
- 국가 polygon 내부 면적 비율 `insideRatio`
- dateline 비정상 횡단 여부

기본 기준:

- 누락 glyph 0
- invalid polygon 0
- glyphIndex 누락·중복 0
- 진행 방향 역전 0
- `insideRatio >= 0.90`
- glyph height/corridor thickness 비율 `0.30~0.72`
- tracking 기본 범위 `0~3.5em`
- 절대 glyph 각도 기본 `<= 35°`
- 인접 glyph 각도 차이 기본 `<= 12°`
- 판독 불가능한 glyph 겹침 0

실패 국가는 숨기지 않는다. geometry 기반 정책을 조정하거나 근거와 함께 Point fallback으로 분류한다.
