당신은 “Pax Local” 프로젝트의 지도 2차 개선 담당자다.

프로젝트 위치:

D:\SSAFY\WORKSPACE\pax-local

이번 작업은 기존 지도 MVP를 폐기하거나 새로 만드는 작업이 아니다.
현재 구현을 보존하면서 지도 표현의 품질과 탐색 경험을 개선한다.

작업의 핵심 목표는 다음 네 가지다.

1. 현재 1:110m 국가 경계를 1:10m 기반 고해상도 경계로 교체
2. 전 세계 1단계 행정구역인 주·도·성·광역 행정구역 경계 표시
3. 지도 위에 국가 이름과 주요 수도 이름 표시
4. 태평양을 넘어 동서로 계속 이동할 수 있는 순환 세계 지도 구현

OpenAI API, 턴 엔진, 외교, 전쟁, 경제, 데이터베이스는 이번 작업에서
구현하지 않는다.

4. 고해상도 국가 데이터
==================================================

현재 사용 중인 Natural Earth 1:110m Admin 0 데이터를
Natural Earth 1:10m Admin 0 Countries 또는 적합한 1:10m Map Units 데이터로
교체한다.

공식 데이터:

Natural Earth 1:10m Admin 0 Countries
Natural Earth 1:10m Admin 0 Map Units
Natural Earth 1:10m Admin 0 Label Points

국가 선택의 기본 단위가 주권국가인지 country/map unit인지 먼저 정리한다.

원칙:

- 플레이 국가 ID는 안정적인 ISO3 기반 countryId 사용
- 해외 영토는 지도에는 별도 geometry로 표현할 수 있음
- 해외 영토를 클릭하면 기본적으로 해당 소유 국가를 선택
- 검색 가능한 주권국가가 작은 섬이라는 이유로 누락되면 안 됨
- Natural Earth의 `-99` ID를 그대로 사용하지 않음
- 기존 country ID와 localStorage 호환 유지
- 분쟁 지역의 정치적 표현을 임의로 바꾸지 않음
- 데이터 출처의 표현 방식을 README와 ATTRIBUTION에 기록

다음과 같은 국가가 검색과 선택에서 누락되지 않게 한다.

- 싱가포르
- 바레인
- 몰디브
- 몰타
- 안도라
- 리히텐슈타인
- 모나코
- 산마리노
- 바티칸
- 카리브해의 소규모 주권국가
- 태평양 도서국가

작은 국가의 실제 폴리곤이 클릭하기 지나치게 어렵다면
지도 geometry와 별도로 `small-country-points` 데이터를 만든다.

작은 국가 선택 방식:

- 검색으로 항상 선택 가능
- 충분히 확대하면 실제 폴리곤 클릭 가능
- 낮은 줌에서는 작은 국가 위치 마커 클릭 가능
- 마커 클릭 역시 동일한 countryId를 반환
- 마커는 실제 영토 크기를 왜곡하는 영토 폴리곤으로 취급하지 않음

5. 멀티 해상도 데이터 전략
==================================================

1:10m 전체 GeoJSON을 최초 화면에서 그대로 렌더링하면 파일 크기,
파싱 시간, 메모리와 WebGL 성능 문제가 생길 수 있다.

따라서 다음 전략 중 가장 적합한 것을 구현한다.

권장 방식:

- 낮은 줌: 1:50m 또는 적절히 단순화한 국가 geometry
- 높은 줌: 1:10m 국가 geometry
- Admin 1: 필요한 줌 이상에서만 표시
- 원본 1:10m 데이터를 그대로 매 렌더마다 처리하지 않음

가능한 구현 방식:

A. 줌별 GeoJSON 교체
B. Tippecanoe 등으로 생성한 로컬 vector tile
C. PMTiles 기반 로컬 vector tile
D. 사전에 단순화한 여러 단계의 GeoJSON

현재 프로젝트 규모에서는 다음 중 하나를 선택한다.

- 간단한 구현: 줌별 단순화 GeoJSON
- 장기적으로 좋은 구현: 로컬 PMTiles/vector tiles

새로운 복잡한 타일 파이프라인을 도입한다면 다음을 만족해야 한다.

- Windows에서 재생성 가능
- README에 생성 명령 기록
- 유료 서버 불필요
- 개발 서버에서 로컬로 제공 가능
- 원본 데이터 출처와 라이선스 명시
- 생성 결과를 재현할 수 있음

목표:

- 1440×900 Chrome에서 지도 이동이 눈에 띄게 끊기지 않음
- 국가 선택 시 전체 geometry를 재구성하지 않음
- React 상태 변경으로 지도 source를 반복 다운로드하지 않음
- 초기 지도 로딩 상태를 명확하게 표시
- 지도 준비 후에만 로딩 오버레이 제거

6. 1단계 행정구역 경계
==================================================

Natural Earth 1:10m Admin 1 States and Provinces 데이터를 사용한다.

대상:

- 미국의 주
- 캐나다의 주
- 중국의 성·자치구
- 일본의 도도부현
- 대한민국의 광역 행정구역
- 북한의 도
- 독일의 주
- 러시아의 연방주체
- 기타 데이터에 포함된 전 세계 1단계 행정구역

이번 단계에서는 Admin 1 영역을 클릭 가능한 게임 영토로 만들지 않는다.
먼저 시각적 경계선만 표시한다.

레이어 역할:

- 국가 국경: 진하고 두껍게
- Admin 1 경계: 더 얇고 낮은 대비로
- 해안선: 국가 외곽과 구분 가능하게
- 선택 국가 내부에서도 Admin 1 경계가 보이게 유지
- 너무 낮은 줌에서는 Admin 1 경계를 숨김

권장 줌 규칙:

- zoom < 2.2: Admin 1 숨김
- zoom 2.2~3.5: 주요 경계만 매우 희미하게
- zoom >= 3.5: 일반 Admin 1 경계 표시
- zoom >= 5: 경계 선명도와 두께 약간 증가

정확한 임계값은 실제 화면으로 조정한다.

Admin 1 선 스타일 예:

- 색상: 국가 국경보다 낮은 대비
- opacity: 0.25~0.55
- width: 0.35~1.0px를 줌에 따라 보간
- dasharray는 가독성을 해치지 않으면 사용 가능
- 국가 국경보다 위에 그리지 않도록 레이어 순서 주의

Admin 1 polygon fill은 기본적으로 사용하지 않는다.
국가별 색상을 가리는 방식으로 만들지 않는다.

데이터 속성 최소 요구사항:

{
  "admin1Id": "USA-CA",
  "countryId": "USA",
  "nameEn": "California",
  "nameLocal": "California",
  "type": "State"
}

향후 영토 시스템에서 사용할 수 있도록 안정적인 admin1Id를 만든다.
그러나 이번 작업에서는 행정구역을 플레이 단위로 선택하지 않는다.

7. 국가명 라벨
==================================================

지도 위에 국가 이름을 반드시 표시한다.

폴리곤 centroid를 즉석에서 계산해 사용하는 방식은 피한다.
Natural Earth Admin 0 Label Points 또는 별도로 검증된 label point를 사용한다.

생성 파일 예:

public/data/maps/country-labels-2020.geojson

각 feature 최소 속성:

{
  "countryId": "KOR",
  "nameKo": "대한민국",
  "nameEn": "South Korea",
  "labelRank": 2,
  "minZoom": 1,
  "maxZoom": 7,
  "textSize": 18
}

기본 표시 언어:

- 한국어
- 한국어가 없으면 영어
- 내부 ID나 ISO 코드만 국가명으로 표시하지 않음

라벨 스타일:

- 지도 위에서 충분히 읽을 수 있는 글자색
- 밝은 halo 적용
- 국가의 크기와 중요도에 따른 글자 크기
- 확대 수준에 따라 글자 크기 보간
- 가능한 경우 대문자 자간 느낌을 과도하게 사용하지 않음
- 작은 국가 이름이 바다나 인접국을 지나치게 덮지 않게 함
- MapLibre symbol collision 처리 사용
- `symbol-sort-key` 또는 유사 우선순위 사용
- 동일 국가의 라벨이 한 화면에 불필요하게 중복되지 않게 함

권장 우선순위:

1. 화면에서 매우 큰 국가
2. 중간 크기 국가
3. 작은 국가
4. 종속 지역과 기타 지도 단위

세계 전체 줌에서도 최소한 주요 국가 이름은 보여야 한다.

예:

- 미국
- 캐나다
- 브라질
- 러시아
- 중국
- 인도
- 대한민국
- 일본
- 호주
- 주요 유럽 국가

확대하면 더 많은 작은 국가 라벨을 표시한다.

8. 글꼴과 한글 glyph

요구사항:

- 한글과 영문을 모두 표시 가능한 오픈 라이선스 글꼴 사용
- 가능하면 Noto Sans KR 계열 사용
- 글꼴 라이선스 기록
- 필요한 MapLibre glyph PBF를 로컬에서 제공하거나,
  현재 MapLibre 버전에서 검증된 로컬 글꼴 방식을 사용
- 네트워크가 끊겨도 국가명 표시 가능
- production build에서도 glyph 요청이 404가 되지 않음

권장 스타일 구조:

{
  "glyphs": "/fonts/{fontstack}/{range}.pbf"

실제 선택한 구현 방식과 글꼴 생성·배치 방법을 README에 기록한다.

- 선택 국가의 수도는 우선 표시 가능

10. 순환 세계 지도
==================================================

현재 지도는 다음 설정 때문에 동서 이동이 끊긴다.

renderWorldCopies: false

이를 수정한다.

필수 동작:

- 태평양에서 동쪽으로 계속 이동하면 미국이 다시 나타남
- 대서양에서 서쪽으로 계속 이동해도 세계가 이어짐
- ±180도 날짜변경선에서 빈 공간이 나타나지 않음
- 지도 드래그가 경도 경계에서 갑자기 멈추지 않음
- 국가 fill, Admin 1 경계, 국가명, 수도가 반복 세계에서도 정상 표시
- 검색 후 이동한 카메라도 가장 가까운 세계 사본으로 자연스럽게 이동
- 선택·호버·플레이 국가 강조가 반복된 세계 사본에서도 작동

MapLibre 설정:

renderWorldCopies: true

MapLibre 기본값도 true지만 명시적으로 설정한다.

다음 설정을 추가하지 않는다.

- 전 세계 경도를 한 번으로 제한하는 maxBounds
- 경도를 -180~180으로 강제 고정하는 커스텀 constrain
- 지도 드래그 종료 때 중심을 강제로 원래 세계로 되돌리는 처리

카메라 중심 경도는 필요하면 정규화하되 사용자의 연속 이동을 방해하지 않는다.

검색으로 미국을 선택했을 때 현재 카메라가 동경 170도 부근이라면,
불필요하게 지구 반대 방향으로 길게 회전하지 않고 가장 가까운 미국 사본으로
이동하도록 경도 unwrap 로직을 구현한다.

예시 개념:

function nearestWrappedLongitude(
  targetLongitude: number,
  currentLongitude: number
): number

targetLongitude에 ±360의 배수를 더해 현재 중심과 가장 가까운 경도를 선택한다.

==================================================
12. 지도 로딩과 상태 동기화
==================================================

현재 코드는 MapLibre 객체 생성 직후 로딩 완료로 처리한다.
이를 실제 `map.load` 또는 스타일 준비 완료 시점으로 수정한다.

지도 로딩 완료 시 다음을 수행한다.

1. 현재 selectedCountryId 읽기
2. 현재 playerCountryId 읽기
3. 선택 강조 필터 적용
4. 플레이 국가 강조 필터 적용
5. 모든 필수 source와 layer 존재 확인
6. 로딩 오버레이 제거

새로고침 후 localStorage에서 플레이 국가가 복원되면
지도 강조선도 반드시 복원되어야 한다.

상태 경쟁 조건을 제거한다.

다음 경우를 모두 지원한다.

- store 복원이 지도보다 먼저 끝남
- 지도가 store보다 먼저 로드됨
- 검색으로 국가 선택
- 지도 클릭으로 국가 선택
- 플레이 국가 변경
- 컴포넌트 재마운트

==================================================
13. 호버와 바다 클릭
==================================================

기존의 MapLibre feature-state 호버 표현을 유지한다.

추가로 Zustand의 hoveredCountryId도 갱신한다.

국가 진입:

setHoveredCountry(countryId)

국가 이탈:

setHoveredCountry(null)

빈 바다를 클릭하면:

- selectedCountryId를 null로 변경
- 국가 정보 패널을 기본 상태로 되돌림
- playerCountryId는 유지
- 플레이 국가 강조도 유지

국가 feature 클릭과 일반 map 클릭이 동시에 실행되어
선택 직후 해제되지 않게 이벤트 처리 순서를 주의한다.

14. 데이터 생성 스크립트
==================================================

`scripts/prepare-map-data.mjs`를 개선한다.

생성 결과 예:

public/data/maps/countries-50m.geojson
public/data/maps/countries-10m.geojson
public/data/maps/admin1-boundaries-10m.geojson
public/data/maps/country-labels-2020.geojson
public/data/maps/capitals-2020.geojson
public/data/maps/small-country-points-2020.geojson
src/data/countries-2020.json

스크립트 검증 항목:

- feature 총수
- 주권국가 총수
- 플레이 가능한 국가 수
- countryId 누락
- 중복 countryId
- 잘못된 geometry
- 빈 geometry
- Admin 1의 parent countryId 누락
- label point 없는 국가
- 수도 없는 국가
- 검색 데이터와 geometry 간 불일치
- 각 결과 파일 크기

스크립트 실행 결과에서 누락을 숨기지 않는다.

모든 플레이 국가가 다음 중 하나 이상을 가져야 한다.

- 실제 country polygon
- small-country marker
- 검색 카메라 중심점

15. 성능 기준
==================================================

고해상도 지도를 추가하더라도 다음을 지킨다.

- 지도 인스턴스는 한 번만 생성
- React 상태 변경 시 지도 재생성 금지
- GeoJSON을 React render 중 변환하지 않음
- 동일 source를 반복 fetch하지 않음
- 호버 때 전체 source 교체 금지
- 선택 때 전체 GeoJSON 재생성 금지
- feature-state 또는 layer filter 사용
- Admin 1은 줌 조건으로 제한
- 라벨 충돌 처리는 MapLibre에 위임
- 필요하면 geometry를 줌별로 단순화
- production build에서 심각한 console error가 없어야 함

성능 측정 결과를 README에 간단히 기록한다.

최소 기록:

- 생성된 각 지도 파일 크기
- 최초 로딩에 사용되는 데이터 크기
- 1440×900에서 지도 준비까지 걸린 대략적인 시간
- Admin 1 표시 후 이동이 눈에 띄게 끊기는지 여부

정확한 벤치마크 인프라까지 만들 필요는 없지만,
브라우저에서 체감 성능을 반드시 확인한다.

17. Playwright 실행 개선
==================================================

Playwright가 별도 수동 서버 실행 없이 동작하도록 `webServer`를 설정한다.

Windows 호환 명령을 사용한다.

예:

webServer: {
  command: "npm.cmd run dev",
  url: "http://localhost:3000",
  reuseExistingServer: true,
  timeout: 120000
}

기존 PLAYWRIGHT_BASE_URL 환경 변수도 유지할 수 있다.

E2E 테스트에서 `.first()`로 결과를 무조건 선택하지 말고,
정확한 국가 이름 또는 ISO 코드로 대상을 선택한다.

18. 실제 브라우저 검증

코드와 테스트만 통과시키고 완료하지 않는다.

Chrome 데스크톱에서 다음 해상도를 확인한다.

- 1280×720
- 1440×900
- 1920×1080
- 2560×1440

각 해상도에서 확인:

- 지도에 국가명이 보임
- 국가명끼리 지나치게 겹치지 않음
- 확대하면 Admin 1 경계가 보임
- 국가 경계와 Admin 1 경계가 구별됨
- 수도명과 국가명이 서로 완전히 겹치지 않음
- 지도 드래그가 날짜변경선에서 막히지 않음
- 태평양 너머로 미국이 다시 나타남
- 검색·선택·확정 패널이 기존처럼 작동
- 지도 이동 중 심각한 깜빡임 없음
- console에 glyph, source, WebGL 관련 오류 없음

완성 화면 스크린샷을 최소 다음 상태로 남긴다.

- 세계 전체 화면
- 동아시아 확대
- 미국 확대
- 날짜변경선을 넘어 세계가 반복된 화면
- 플레이 국가가 강조된 화면
