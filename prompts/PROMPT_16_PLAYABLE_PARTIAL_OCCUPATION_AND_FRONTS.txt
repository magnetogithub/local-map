# PROMPT 16 — 기존 미세 영토로 부분 점령·전선을 먼저 플레이 가능하게 만들기

작성 기준: 2026-10-28, D:\gen.

이 문서는 Prompt 15에서 이미 만든 데이터 이후의 구현을 이어가는 새 실행 프롬프트다. 이번 요청이 프롬프트 작성뿐이면 문서만 만들고 구현을 시작하지 않는다. 구현을 요청받으면 아래 내용을 따라 실제 게임 연결을 끝낸다.

사용자가 정한 진행 방식은 “먼저 구현 → 사용자가 직접 플레이 → 불편하거나 잘못된 부분을 수정”이다. 목표는 사용자가 로컬 게임에서 행정구역 내부 부분 점령과 전선 이동을 직접 확인할 수 있게 만드는 것이다.

## 1. Prompt 15와의 분기점

- `prompts/PROMPT_15_OPERATIONAL_MICRO_TERRITORIES_AND_PARTIAL_FRONTS.txt`는 과거 요구사항과 작업 기록으로 그대로 보존한다. 수정하거나 완료 처리하지 않는다.
- 현재 출발점은 Prompt 15의 15-21까지 생성하고 검증 접수한 기존 산출물이다. 데이터가 준비된 것과 새 데이터가 실제 게임에 연결된 것은 구분한다.
- 15-22 전체 국가 감사는 미완료다. 15-23 독립 전 세계 재생성과 15-24/REVIEW C 및 이후 REVIEW의 통과를 이번 구현의 선행 조건으로 요구하지 않는다.
- Prompt 15의 남은 구현 중 지역 조회·범위 선택·provider 연결·상태 이전·점령 처리·지도 연결을 가져온다. 대응 범위는 주로 15-25~15-29, 15-31~15-34, 15-36~15-38이며, 15-39~15-42의 사용자 행동은 직접 플레이할 수 있는 목표로 사용한다.
- 이 문서가 정한 작업 순서와 최소 확인 범위가 Prompt 15의 단계별 독립 검증·REVIEW·전수 감사·증거 재접수 요구보다 우선한다. Prompt 15 전체나 옛 총괄 인수인계의 감사 절차를 다시 적용하여 시작을 막지 않는다.
- Prompt 15 자동 실행기는 재개하지 않는다. 새 오케스트레이터, 검증 세션 체계, 승인 manifest 체계도 만들지 않는다. 아래 구현 묶음마다 별도 승인이나 독립 PASS를 기다리지 않고 이어서 작업한다.

### 기존 미해결 사항 처리

- `docs/automation/prompt15-numerical-deferral.json`의 CIV·FRA·GBR·MYS·UKR·VNM 수치 문제 보류 결정을 이어받는다.
- 기존 sliver 문제와 관련 draft, 검증기 오류, 미완료 전수 감사도 이번 기능 구현의 착수 조건에서 제외한다. 23개 sliver 국가를 모두 복구하거나 새 후보의 전수 승인을 받아야 다음 코드를 작성할 수 있다는 순서를 만들지 않는다.
- 기존 FAIL·미해결 기록은 그대로 둔다. 보류된 문제를 PASS로 바꾸지 않는다. 승인되지 않은 sliver draft로 기본 데이터를 자동 교체하지 않는다.
- 실제 게임에서 지도 누락·잘못된 점령·소유권·인접성 오류·로딩 실패가 관측되면 해당 원인과 영향 범위를 수정한다. 같은 알려진 미소 차이를 검증기가 다시 출력했다는 이유만으로 국가 재검사나 전 세계 재생성을 시작하지 않는다.

## 2. 구현 목표와 유지할 기본 동작

최종적으로 다음 행동을 기존 게임 화면에서 할 수 있어야 한다.

1. 대한민국으로 플레이하며 “북한에 전쟁을 개시하여 휴전선 인근을 점령”처럼 접경 일부를 지시한다.
2. 기존 북한 도 하나 안에 점령된 영토와 북한이 계속 통제하는 영토가 함께 남는다.
3. 지도에 해당 부분의 점령색과 도 내부를 지나는 전선이 표시된다.
4. 다음 진격은 현재 전선에서 이어진다.
5. 해방·양도·undo/redo 후 실제 소유/통제 상태와 지도 표시가 함께 바뀐다.
6. 슬로베니아 등 다른 국가에도 같은 구조가 적용되고 기존 행정구역 조회와 경계 표시를 사용할 수 있다.

다음 제품 동작은 유지한다.

- 점령은 controller를 바꾸며 owner는 보존한다. 양도 등 owner 변경이 필요한 행동은 기존 의미를 따른다.
- 국가·행정구역·미세 영토를 구분한다. 원본 국가와 행정 identity는 점령 후에도 유지한다.
- 한 요청이 실패하면 world와 simulation을 부분 변경하지 않는다. 기존 revision·authority·aggregate cap과 production DEBUG 제한을 유지한다.
- AI는 자연어 의미와 행동을 해석하고, 서버가 실제 catalog ID와 선택 범위를 결정한다. AI가 좌표·polygon·존재하지 않는 ID를 생성하도록 하지 않는다.
- 턴 진행 중 영토를 새로 자르거나 topology를 생성하지 않는다. 기존 산출물을 사용한다.
- 기존 국가 선택·국가 색상·이름·클릭·뉴스·날짜·history를 유지한다. 새 전쟁 시스템이나 브라우저 저장 기능은 추가하지 않는다.
- 원본 데이터와 기존 승인 산출물은 덮어쓰지 않는다. 기능상 실제 데이터 수정이 필요하면 영향 범위를 별도 출력으로 만들고 현재 게임이 어느 버전을 사용하는지 명확히 한다.

## 3. 작업 분기·합류와 구현 순서

아래는 작업을 이어가기 위한 묶음이다. 각 묶음에 독립 검증 단계나 승인 대기를 붙이지 않는다. 이미 구현된 부분은 사용하고 빠진 연결만 작성한다. 매 단계마다 전체 저장소를 다시 감사하지 않는다.

### 3.1 작업 분기와 합류 흐름

16-01~16-09를 실행 단위로 사용한다. 3.2~3.5절은 각 작업의 구현 요구사항이며, 실제 실행 순서는 아래 의존관계를 따른다.

```text
기존 15-21 산출물에서 시작
            ↓
16-01 공통 catalog 연결·서버 조회·공유 타입 정리
            ↓
      작업 분기 [동시 진행 최대 2개]
            │
  ┌─────────┼─────────────────────┐
  ↓         ↓                     ↓
[A 상태]  [B 지도]              [C AI·도구]
16-02     16-04                  16-06
초기화·   asset·protocol·        현재 전선 기반
상태 이전 상세 geometry 연결    작은 범위 선택
  ↓         ↓                     ↓
16-03     16-05                  16-07
점령·     점령색·전선·          provider 제출·
undo/redo incremental projection 범위 검증 연결
  │         │                     │
  └─────────┼─────────────────────┘
            ↓ A·B·C 구현 결과 합류
16-08 기존 게임 화면·실제 턴 경로에 통합
            ↓
16-09 최소 확인 [4절을 한 번 묶어서 수행]
            ↓
사용자가 직접 플레이할 수 있게 전달
            ↓
사용자가 불편·오류를 확인하면 해당 구현만 수정
            └─→ 관련 부분의 짧은 확인 → 다시 플레이
```

분기별 작업과 의존관계는 다음과 같다.

| 작업 | 분기 | 선행 작업 | 구현 결과 |
| --- | --- | --- | --- |
| 16-01 | 공통 | 기존 15-21 산출물 | 서버 catalog loader, 전체 지역 membership 조회, ID/ordinal·catalog ref와 분기에서 사용할 최소 공유 타입 |
| 16-02 | A 상태 | 16-01 | 새 게임의 cell 상태 초기화, 이전 부모의 owner/controller·참조 이전, catalog 전환 |
| 16-03 | A 상태 | 16-02 | 실제 cell 단위 occupy/liberate/transfer·atomic commit·history·undo/redo |
| 16-04 | B 지도 | 16-01 | 로컬 asset 제공, catalog-v3 bootstrap·gzip/protocol·숫자 feature ID·필요한 exact detail 로딩 |
| 16-05 | B 지도 | 16-04 | 상태 변경 입력에 따른 점령색·전선·경계 layer와 incremental projection |
| 16-06 | C AI·도구 | 16-01 | 전달받은 현재 world 상태와 catalog graph로 실행하는 bounded frontier 선택·지역 조회 |
| 16-07 | C AI·도구 | 16-06 | 기존 provider의 lookup→submit 연결과 revision·actor·operation·제출 범위 처리 |
| 16-08 | 합류 | 16-03·16-05·16-07 | 실제 world/turn controller·서버·지도·기존 UI 연결, 대표 점령부터 후속 진격까지 실행 가능한 게임 |
| 16-09 | 마무리 | 16-08 | 4절의 최소 확인과 사용자의 직접 플레이 안내 |

분기 운영 규칙:

- 16-01에서 같은 catalog ref와 ID, 현재 상태를 읽는 방식, 선택 결과와 상태 변경을 전달하는 최소 인터페이스만 맞춘다. 별도 설계 승인이나 문서 묶음을 만들지 않는다.
- A·B·C는 16-01 이후 각각 시작할 수 있다. 동시에 진행하는 작업은 최대 2개이며, 여유가 생기면 나머지 분기를 시작한다. 병렬 실행 환경이 없으면 같은 의존관계대로 순차 수행한다.
- A는 상태 초기화·migration·commit·history, B는 asset route·지도 loader·renderer, C는 범위 선택·tool·provider 경로를 맡는다. 실제 편집 파일이 겹치는 부분은 순차로 조정한다.
- B는 전달받은 상태 변경으로 화면을 갱신하고, C는 전달받은 현재 상태로 선택하도록 만든다. A의 내부 구현이나 별도 전역 상태에 의존하지 않도록 16-01의 인터페이스를 사용한다.
- 16-08에서 실제 턴 controller와 연결할 때 A·B·C의 결과를 함께 사용한다. 공유 타입이나 연결부 수정도 이 단계에서 정리한다.
- 분기 구현 완료 후 사용할 수 있는 인터페이스와 남은 연결 사항을 짧게 남기고 합류한다. 분기마다 독립 검증·PASS 판정·사용자 승인을 추가하지 않는다. 4절의 최소 확인은 16-09에서 모아 수행한다.
- 한 분기에 문제가 생기면 해당 작업과 직접 의존하는 작업만 조정한다. 독립된 다른 분기는 계속 진행하고, 완료한 분기를 처음부터 다시 실행하지 않는다.

### 3.2 기존 catalog를 서버와 지도에서 읽을 수 있게 연결 [16-01·16-04]

- 현재 서버 catalog loader, 지역 resolver, world catalog ref와 지도 bootstrap/asset loader를 찾아 기존 15-21 데이터로 연결한다.
- 현재 지도 consumer는 Prompt 14의 catalog-v1 protocol을 사용한다. 새 catalog-v3 ref와 manifest, 숫자 cell/edge ordinal, gzip asset을 실제로 읽도록 adapter 또는 consumer를 수정한다. 버전 문자열만 바꿔서 구형 schema로 읽게 하지 않는다.
- 원래 cell ID와 숫자 ordinal 사이의 대응, 행정→cell membership, 이전 territory→cell mapping, edge의 left/right incidence를 기존 index에서 읽는다.
- 로컬 게임에서 필요한 asset을 제공하도록 실제 route 또는 로컬 asset 경로를 연결한다. 외부 배포나 hosting 작업은 이번 범위에 없다.
- 초기 화면에 전 세계 상세 geometry를 모두 내려받지 않는다. overview tile과 필요한 국가·변경 cell의 exact detail을 나누어 읽고 기존 캐시를 재사용한다.
- overview에서 생략된 작은 cell은 필요할 때 기존 exact detail로 표시한다. 눈에 보이게 하려고 원본 geometry를 임의로 크게 만들지 않는다.
- gzip payload, 해제 후 PBF, 숫자 feature ID와 incidence metadata의 관계는 `docs/automation/prompt15-task-15-21.md`를 필요한 범위에서 참고한다. 그 문서의 전체 검증 절차를 실행할 필요는 없다.
- 이 단계에서 기존 행정구역 이름으로 cell 집합을 조회할 수 있게 한다. 저장된 membership은 512개에서 자르지 않는다. 저장 크기와 한 행동의 변경 한도는 구분한다.

### 3.3 실제 world·simulation과 기존 상태 연결 [16-02]

- 새 게임이 같은 catalog ref와 실제 cell 집합으로 시작하도록 연결한다. 서버·world·simulation·지도가 서로 다른 catalog를 사용하지 않게 한다.
- 기존 상태를 새 cell로 옮길 때 기존 previous-parent index를 사용하고, 각 이전 부모의 현재 owner/controller를 상속한다. sourceCountryId를 현재 owner로 대체하지 않는다.
- 기존 authority scope, 지역 참조, simulation territory 참조와 pending action을 필요한 범위에서 새 membership에 연결한다. 해석할 수 없는 참조는 기존 상태를 보존한 채 명시적으로 실패시킨다.
- world·simulation·catalog ref의 전환은 한 번에 반영한다. 변환 중 오류가 나면 전환 전 상태를 유지한다.
- 기존 history와 snapshot을 임의 삭제하지 않는다. snapshot의 catalog version에 맞는 상태와 지도 asset을 복원하도록 하고, 구버전 참조가 남으면 해당 asset을 유지한다.
- 과거 모든 버전의 범용 migration framework를 새로 만드는 대신 현재 게임에서 사용하는 이전 catalog와 이 문서의 새 catalog 연결을 끝낸다.

### 3.4 AI가 작은 범위를 선택하고 실제 effect를 제출하게 연결 [16-06·16-07]

- 기존 border lookup·region tool·provider 경로를 확장해 국가, 방향, 접경, 현재 전선, 작은 진격 범위를 처리한다.
- `near`, `limited`, `deeper` 등 범위 표현을 실제 cell graph의 연속된 선택으로 연결한다. 기존 물리 규모·범위 정책을 재사용하며 새로운 세계 해상도 실험을 시작하지 않는다.
- 첫 점령은 해당 육상 접경에서, 후속 진격은 현재 controller 경계에서 인접한 미점령 cell을 선택한다. 바다·점 접촉·원격 cell을 육상 연결로 취급하지 않는다.
- “휴전선 인근”, “북부 접경 일부”처럼 문맥으로 판단 가능한 요청에 매번 도 이름을 요구하지 않는다. 대상 자체를 결정할 수 없는 경우에만 이유를 표시한다.
- 선택 결과를 catalog/world revision, actor/target, operation과 결합하고 제출된 실제 ID 집합이 그 범위인지 commit 전에 확인한다. 별도 token 체계는 필요한 경우에만 추가한다.
- 제한된 접경 조회 뒤 도 전체 regionRefs로 바꿔 제출하는 우회를 허용하지 않는다. 큰 범위나 cap 초과는 더 작은 요청으로 유도하고 임의 절단을 숨기지 않는다.
- lookup → effectTarget 제출 → validator/planner → commit이 기존 provider 예산 안에서 이어지게 한다. 기존 API 오류·Retry 흐름을 유지한다.
- 대표 요청이 큰 도 전체를 선택한다면 범위 선택 구현을 고친다. 모든 국가의 깊이·폭·면적을 새 보고서로 측정하는 작업은 하지 않는다.

### 3.5 부분 점령·전선·후속 진격을 지도까지 연결 [16-03·16-05·16-08]

- occupy/liberate/transfer가 선택된 실제 cell만 변경하도록 기존 authoritative state 경로에 연결한다. 지도색만 바꾸는 구현으로 끝내지 않는다.
- 변경된 cell과 관련 경계만 incremental projection에 반영한다. 매 턴 전 세계 GeoJSON이나 전체 tile을 다시 만들지 않는다.
- 점령색은 현재 controller를 기준으로 기존 국가 색상 정책과 연결한다.
- 양쪽 cell의 현재 controller가 다른 공유 edge를 전선으로 표시한다. 같은 controller 사이에는 가짜 전선을 표시하지 않는다.
- 국가 경계·실제 행정 경계·합성 cell 경계·현재 전선을 구분한다. 기존 zoom 4 미만 행정선 숨김을 유지하고, 합성 cell 격자는 기본적으로 숨긴다.
- 후속 진격, 해방, 양도, undo/redo가 동일한 authoritative state와 지도 projection을 사용하게 한다.
- 한국/북한 전용 좌표나 국가별 전용 코드를 넣지 않는다. 슬로베니아의 기존 행정 identity와 membership도 같은 resolver와 지도 경로로 처리한다.
- 기존 UI에서 사용자가 바로 요청하고 결과를 볼 수 있게 연결한다. 검증 보고서나 별도 실험 화면만 제공하는 상태로 끝내지 않는다.

## 4. 구현자가 수행할 최소 확인 [16-09]

구현 중에는 변경 부분에 필요한 짧은 검사만 한다. 아래 확인을 마무리 단계에서 한 번 묶어서 실행하고, 실패한 경우 관련 부분만 수정·재실행한다.

1. 타입 확인: `node node_modules/typescript/bin/tsc --noEmit`.
2. production build 한 번: `npm run build`. 사용 중인 dev server와 `.next`가 충돌하면 설치된 Next 문서에 따라 별도 출력 경로를 사용한다.
3. 변경한 runtime의 핵심 상태 확인: 작은 고정 입력으로 아래 세 동작을 확인한다. 기존 테스트를 재사용하고 필요한 assertion만 보완한다.
   - 부분 점령이 대상 cell의 controller만 바꾸고 owner와 비대상 cell을 보존한다.
   - 잘못된 ID 또는 stale revision이 포함된 요청은 부분 commit 없이 실패한다.
   - 점령 후 undo/redo가 상태를 복원하고 지도 projection이 그 상태를 사용한다.
4. 로컬 화면에서 새 catalog가 로딩되고 위 대표 점령 요청의 상태 변경과 점령색·전선 연결이 실행되는지 한 번 짧게 확인한다. 실제 외부 API를 필수 호출하지 말고, 필요하면 기존 개발용 scripted provider나 허용된 DEBUG 경로를 사용한다. 실제 API 호출로 확인한 것처럼 보고하지 않는다.

전 세계 생성·247개국 geometry 감사·독립 재생성 byte 비교·전체 E2E·국가별 screenshot·성능 benchmark·별도 검증 세션은 필수로 수행하지 않는다. 새 검증 runner나 전수 감사용 fixture를 만드는 데 시간을 쓰지 않는다. lint는 변경 파일에 필요한 경우만 실행하고 전체 lint를 별도 완료 관문으로 추가하지 않는다.

빌드나 핵심 동작이 이번 변경 때문에 실패하면 해당 코드를 고친다. 기존의 무관한 실패는 짧게 기록하고 이번 변경과 직접 관련된 확인으로 범위를 좁힌다. 직접 실행하지 못한 확인은 남은 항목으로 알리되, 무관한 전체 검증을 새로 요구하며 기능 개발을 멈추지 않는다.

## 5. 사용자의 직접 확인과 후속 수정

사용자가 기존 게임 화면에서 바로 확인할 수 있게 다음만 간단히 안내한다.

- 실행 명령과 접속 주소.
- 대한민국 선택 후 입력할 대표 점령 문장.
- 다음 진격·해방·양도·undo/redo를 확인하는 조작 또는 입력 예시.
- 지도에서 점령색과 도 내부 전선을 볼 위치와 대략적인 확대 수준.
- 필요하면 기존 새 게임 흐름으로 다시 시작하는 방법.

사용자가 직접 본 점령 범위, 전선 모양, 표시 품질, 속도, 조작 불편을 다음 수정 대상으로 삼는다. 국가마다 별도 승인이나 체크리스트 제출을 요구하지 않는다. 아직 사용자가 확인하지 않은 항목을 사용자 검증 완료라고 기록하지 않는다.

## 6. 작업 운영과 완료 보고

- 먼저 `AGENTS.md`를 읽고, Next 관련 코드를 수정하기 전에 `node_modules/next/dist/docs/`의 해당 문서를 읽는다.
- 기존 사용자 변경과 다른 작업 중인 파일을 보존한다. 필요한 구현 파일만 수정하고 관계없는 리팩터링을 확대하지 않는다.
- 역할 분리, 새 에이전트, 태스크마다 새 세션, 재접수용 evidence bundle을 기본 작업으로 만들지 않는다.
- 이미 승인된 구현 범위 안에서는 단계마다 확인 질문을 반복하지 않는다. 진행 상황은 짧게 알리고 직접 플레이 가능한 연결까지 계속한다.
- 작업 후에는 변경 요약, 실행한 최소 확인의 결과, 사용자가 바로 해볼 방법, 남은 문제만 간단히 보고한다. 파일 hash·세션 ID·국가별 판정표를 최종 보고의 필수 항목으로 만들지 않는다.
- 이번 완료 기준은 위 동작을 구현하고 최소 확인을 수행하여 “사용자가 직접 플레이하며 확인할 수 있는 상태”로 전달하는 것이다. Prompt 15의 전체 감사 완료나 전 세계 정밀 품질 보증을 주장할 필요는 없다.
- 사용자가 확인한 실제 문제는 영향 범위를 고친다. 문제 하나를 이유로 Prompt 15의 전체 감사·독립 생성·REVIEW 루프를 다시 시작하지 않는다.
