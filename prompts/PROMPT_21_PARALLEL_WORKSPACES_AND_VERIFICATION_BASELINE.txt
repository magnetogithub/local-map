# PROMPT 21 — 병렬 개발 작업 공간 분리와 검증 기준선 정비

작성 기준은 2026-11-03의 현재 저장소다.

이 문서는 메인 프로젝트의 프롬프트·런타임 개선과 국가별 세부 프로빈스 준비를 별도 작업 공간에서 진행하도록 만드는 실행 프롬프트다. 앞선 계획의 2번인 “메인 개발과 국가 추가 작업 공간 분리” 전체와 3번인 “현재 검증 기준 정비”의 남은 항목을 수행한다. 1번의 공통 데이터 계약과 프롬프트 20 보완 결과를 재사용한다.

프롬프트 작성 요청에는 이 문서만 작성한다. “21 실행”을 요청받으면 5절의 의존관계에 따라 21-01부터 21-08까지 구현·검증한다. “21-XX만 실행”은 해당 태스크와 검증된 선행 산출물을 대상으로 한다. “21번 다음 태스크”는 완료 근거를 읽고 실행 가능한 첫 미완료 태스크 하나를 수행한다.

문서가 있거나 과거 보고서에 PASS가 적혀 있다는 이유로 현재 태스크를 완료 처리하지 않는다. 실행 요청에는 필요한 로컬 기준선 커밋과 작업트리 생성이 포함된다. 환경의 실제 권한 제한을 따르고, 기존 사용자 변경을 보존한다.

## 1. 목표와 완료 범위

최종 목표는 다음 네 가지다.

1. 현재 프롬프트 20의 코드·데이터·계약을 새 작업트리에서도 재현할 수 있는 Git 기준선으로 고정한다.
2. 메인 개발과 국가별 원본 조사·정규화·계층·이름 자료 준비의 작업트리, 브랜치, 쓰기 경로와 담당자를 분리한다.
3. 과거 테스트 실패 4개를 현재 코드에서 추적하고, 기존 세 나라 각각의 실제 카탈로그에서 전선 선택·점령·undo/redo와 선택 밖 객체 보존을 검사한다. 기존 객체 독립성·지리 조회 검사와 함께 재현 가능한 검증 기준으로 정리한다.
4. 실제 검사 도구의 동시 실행과 쓰기 경로 격리, 준비 시작 후 관련 메인 변경의 감지·동기화·재검증·인계 수락을 작은 실험으로 확인한다.

국가별 실제 형상 생성기와 증분 발행 경로의 일반화는 앞선 계획의 4번이다. 공유 국경·전역 ordinal·타일·중국 표시 자료의 실제 재조립과 활성 전환은 5번이다. 새 국가 하나를 추가해 실제 플레이까지 확인하는 일은 6번이다. 이 세 항목의 구현은 후속 프롬프트에서 수행한다.

21의 병렬 진행 완료 기준은 메인 개발과 국가 자료 준비가 독립적으로 시작될 수 있는 상태다. 실제 후보 생성 가능 범위는 현재 도구를 조사해 따로 기록한다. 최종 카탈로그 조립과 활성 포인터 변경은 통합 담당자가 순차 소유한다.

대상국이 지정되지 않은 실행에서는 countryId가 null인 빈 국가 준비용 작업트리 하나로 격리를 검증한다. 임의 국가를 선정하거나 자료 조사·다운로드·미세 경계 생성을 시작하지 않는다. 이후 국가가 지정되면 국가마다 독립 브랜치·작업트리·출력 경로를 사용한다.

## 2. 반드시 유지할 계약과 실행 경계

- AGENTS.md와 현재 git status를 먼저 읽는다. Next 관련 코드를 수정할 경우 설치된 node_modules/next/dist/docs/의 해당 문서를 먼저 확인한다.
- State는 기존 stateId로, province는 기존 TerritoryId와 같은 provinceId로 구분한다. 이름이 같아도 서로 다른 ID의 객체와 mutable 상태는 독립적이다. 명칭 변경이나 sid·pid 신규 발급을 시작하지 않는다.
- 하나의 state에 여러 province가 속할 수 있다. state 부모가 미확정인 province의 null과 품질 상태를 유지한다. 검색용 이름 묶음이 실제 TerritoryEntity를 합치지 않게 한다.
- sourceCountryId, 공식 부모, 현재 ownerCountryId·controllerCountryId를 구별한다. 개별 ID 조회, 검증된 부분 점령, 원자적 commit, undo/redo와 기존 게임 보존 정책을 유지한다.
- 현재 catalogRef는 data/runtime/operational-catalog/current.json과 실제 index·descriptor에서, metadataRef는 data/runtime/geography/current.json과 연결된 manifest에서 읽는다. catalogVersion·geometryRoot·topologyRoot·renderArtifactRoot·manifestPath 전체를 비교한다.
- 국가·state·province 수, fine 국가 집합, 부모 미확정 수를 과거 보고서에서 고정 기대값으로 복사하지 않는다. 현재 채택 입력·실제 카탈로그·공통 계약을 대조하는 기존 검증을 재사용한다.
- 기존 geometry·topology·영토 ID·ordinal·행정 membership·seed lineage·활성 포인터를 보존한다. 기준선 고정과 작업 공간 분리를 위해 데이터 재생성이나 카탈로그 재발행을 수행하지 않는다.
- 실행 중인 게임·checkpoint·서버·사용자 작업트리를 유지한다. 전체 reset, 강제 checkout, 강제 worktree 제거, 일괄 clean·prune로 작업 공간을 정리하지 않는다.
- 프롬프트 20의 partial·unsupported coverage, 미확정 부모, coarse·residual 자료는 지원되는 상태다. 이를 임의 보완해 complete로 만들지 않는다.
- 조약의 영토 이전, 전쟁 종료 처리, REPAIR_FAILED 등 앞선 게임 실행 문제는 이번 작업 공간 분리와 별개다. 관련 동작의 회귀 검증은 재사용하되 새 해결 범위를 추가하지 않는다.
- 실제 외부 AI 호출·유료 API·메신저 전송·원격 배포·push와 다음 국가 자동 실행은 별도 요청에 따른다.
- 프롬프트 작성만 요청받은 세션에서는 아래 실행 산출물, 작업트리, 기준선 커밋과 PASS 보고를 생성하지 않는다.

최신 프롬프트 20 검증 기록은 20개 파일의 테스트 185개 통과다. 이 수는 해당 실행의 관측값이다. 과거 병렬성 보고서의 실패 4개가 발생한 operational-mixed-membership.test.ts는 그 검사 묶음에 포함되지 않았으므로 별도로 추적한다.

과거 실패 4개는 fixture가 edge 수를 1로 선언하면서 detail-index의 edgeDetails를 빈 배열로 제공해 OPERATIONAL_EDGE_INDEX에서 중단된 사례다. 현재에도 같은 원인인지 다시 확인하고, 각 테스트가 의도한 membership·seed lineage 본문에 도달하도록 고친다. 운영 로더의 경계 검증을 완화하지 않는다.

기존 감사에는 전선 선택에 실패한 턴을 기록만 하고 최종 실패 집계에서 빠뜨릴 수 있는 경로가 있다. 상위 검사 통과 수와 별개로 한국·북한·중국을 각각 대상으로 한 세 턴의 실행·성공 여부를 확인한다. 기존 evidence의 성공 기록은 재사용할 로직과 비교할 결과의 근거다.

Vitest가 테스트 수집 전에 임시 파일·캐시 권한 오류로 중단되면 환경 실패로 기록한다. 과거 네 테스트의 현재 통과·실패는 수집과 실행이 완료된 뒤 판정한다. 권한 오류의 원인은 실제 경로·발생 단계·단독 실행 재현 결과로 판단한다.

## 4. 작업 공간·소유권·출력 계약

### 4.1 작업 공간

현재 저장소를 메인 개발 공간으로 유지한다. 국가 준비 공간은 같은 저장소의 별도 Git worktree와 전용 브랜치로 만든다. 기본 부모 경로는 현재 저장소 밖이면서 허용된 workspace 안인 local-map-worktrees/와 같은 형제 디렉터리로 정한다. 실제 절대 경로와 충돌 여부를 실행 시 확인한다.

대상국 미지정 상태의 브랜치·폴더에는 country-prep와 실행별 구분자를 사용할 수 있다. 국가가 지정되면 기존 CountryId 매핑을 확인한 뒤 국가별 이름을 사용한다. 기존 브랜치나 폴더를 강제로 재사용하지 않는다.

Git worktree는 객체·refs·LFS 저장소 일부를 공유한다. 별도 브랜치와 파일 트리의 격리 범위를 문서화한다. 같은 브랜치의 중복 checkout, 공용 refs의 강제 변경, 다른 작업의 worktree 삭제를 피한다.

다음 쓰기 자원은 작업트리·실행별 독립 경로를 사용한다. 기본 위치는 각 작업트리 안이다. 도구가 OS 임시 루트를 사용하면 실제 하위 경로와 작성 프로세스를 확인해 격리를 입증한다.

| 자원 | 분리 규칙 |
| --- | --- |
| 의존성 | 작업트리별 node_modules와 동일 lockfile 기반 설치. 다른 작업이 사용하는 디렉터리를 수정·삭제하는 writable 공유 금지 |
| 임시 파일·로그·검사 JSON | 각 작업트리의 .tmp/ 아래 실행별 경로 |
| Vitest·Vite 캐시·OS 임시 파일 | 설치된 도구가 지원하는 캐시 설정과 프로세스별 TEMP/TMP 등으로 독립 경로를 정하고 실제 적용 경로를 확인. 환경변수는 해당 검사와 자식 프로세스에 한정 |
| Next 산출물 | 기존 PAX_BUILD_DIST_DIR 지원을 사용한 .next-* 경로. 같은 작업트리 안의 동시 실행도 서로 다른 경로 |
| 개발 서버 | 필요할 때만 독립 포트·프로세스. 기존 실행 프로세스를 임의 종료하지 않음 |
| 환경변수·로컬 설정 | 작업트리별 로컬 파일. 비밀 값과 사용자 게임 snapshot은 Git·인계 문서에 포함하지 않음 |
| 국가 입력·후보·검증 | 국가·실행별 상대 경로를 manifest에 명시. 다른 국가의 출력과 활성 runtime 경로에 직접 쓰지 않음 |

원본과 큰 고정 입력은 기존 추적·LFS 정책을 우선한다. 읽기 전용 공유가 실제 도구에서 지원되고 바이트 pin을 확인한 경우에만 재사용한다. writable junction·symlink로 node_modules·.next·.tmp를 공유하지 않는다. 전체 저장소 복제나 대용량 자료의 일괄 재다운로드를 기본 방식으로 삼지 않는다.

작업트리 생성 전에 남은 디스크 공간, checkout/LFS 실체화 크기와 의존성 설치 예상량을 확인한다. 필요한 입력과 과거 검증 근거를 정리 대상으로 오인하지 않는다. 공간이 부족하면 실제 필요한 범위와 부족량을 보고하고 영향을 받지 않는 문서·검증 준비를 진행한다.

### 4.2 담당자와 변경 경계

| 담당 역할 | 소유하는 변경 | 합류 규칙 |
| --- | --- | --- |
| 메인 공통 담당 | 공통 schema·loader·API·GPT 지시·의존성·공용 설정·검증 기준 | 공통 인터페이스 변경을 먼저 공지하고 준비 브랜치가 새 기준선을 반영 |
| 국가 준비 담당 | 자기 국가의 조사·원본 참조·정규화·계층·이름·별칭·입력 pin·후보 및 전용 증거 | 공통 코드는 제안과 재현 자료로 인계. 다른 국가 파일을 직접 수정하지 않음 |
| 통합 담당 | 공통 변경 합류, 활성 catalog·geography 포인터, 최종 조립과 전역 자료 변경의 순서 | 최신 메인과 현재 참조를 재확인한 뒤 후속 프롬프트에서 순차 통합 |

한 사람이 여러 역할을 맡을 수 있다. 역할별 변경 범위를 기록하고 같은 파일의 동시 편집을 피한다. 국가 공용 source-lock·adapter registry가 단일 파일이라면 각 국가가 동시에 수정하는 방식 대신 국가별 자료를 통합 담당자에게 인계한다. 실제 registry·생성 경로 일반화는 후속 범위다.

절대 경로·포트·실행 프로세스와 로컬 설치 상태는 .tmp/의 로컬 기록으로 관리한다. 버전 관리하는 지침은 상대 경로와 재현 명령을 중심으로 작성한다. 별도 오케스트레이터나 배타 잠금 서비스를 만들지 않는다.

```text
                                             ↓
                           21-07 합류·격리·재현·인계 실험
                                             ↓
                              21-08 완료 근거와 다음 작업 인계
```

21-01 → 21-02 → 21-03은 공통 선행 작업이다. 21-04·21-05·21-06은 21-03에서 정한 인터페이스와 파일 소유권 아래 병렬로 진행할 수 있다. 21-07은 세 분기의 산출물이 모두 준비된 뒤 시작한다. 21-08은 실제 실험 결과를 기준으로 완료 여부를 기록한다.

A는 작업 공간 설정·로컬 경로·격리 기록을, B는 기존 fixture와 검증 명령·기준선 문서를, C는 국가 인계·동기화 지침을 소유한다. 공용 설정 파일 변경이 겹치면 공통 담당자가 순차 반영한다. 병렬 가능성은 새 채팅·서브에이전트 생성을 요구하지 않는다.

## 6. 태스크별 지시와 완료 조건

### 21-01 — 현재 상태와 기존 실패를 추적한다

1. 브랜치·HEAD·git status·worktree 목록을 읽는다. 추적 수정, 미추적 필수 입력, ignored 로컬 산출물을 구별한다. 프롬프트 20에 속하는 변경과 그 밖의 사용자 변경을 분류한다.
2. 활성 두 포인터, 전체 catalogRef·metadataRef·schema, 실제 index·manifest와 필요한 채택 입력의 바이트 pin을 기록한다. 기존 검증 helper와 보고서를 우선 재사용한다.
3. 과거 실패 4개의 원래 명령·파일·테스트 이름·오류와 현재 상태를 대응시킨다. 해당 파일을 좁혀 실행해 실패 원인이 유지되는지 확인한다. 이미 수정됐으면 변경 근거와 재검증 결과를 기록한다.
4. 기존 동적 기대값·ID 독립성·게임 버전 보존 보완이 현재 파일에 존재하는지 확인한다. 같은 보완을 중복 구현하지 않는다.
5. 디스크·LFS 실체 파일·현재 의존성·실행 중인 서버와 점유 포트를 확인한다. 로컬 환경 조사는 필요한 정보만 기록하고 비밀 값·게임 내용을 수집하지 않는다.

산출물은 reports/maintenance/prompt21-baseline.json이다. 현재 참조·파일 identity·검사 명령·관측 결과와 기존 실패의 대응 관계를 담는다. 개인 절대 경로·세부 로그는 .tmp/prompt21/에 두고 보고서에서 상대 참조한다.

완료 조건은 새 작업트리에 필요한 파일 집합과 현재 남은 실패를 구별할 수 있는 것이다. 이 단계에서 재현한 기존 fixture 실패는 21-05의 수정 대상으로 명시한다.

### 21-02 — 현재 공통 계약을 Git 기준선으로 고정한다

1. 새 작업트리에 필요한 프롬프트 20의 코드·데이터·문서·테스트와 이번 프롬프트를 기준선 커밋에 포함한다. 미추적 필수 파일을 누락하지 않는다. 이미 적합한 커밋이 있으면 내용과 identity를 확인해 재사용한다.
2. 의존성·빌드 캐시·임시 로그·비밀 값·사용자 게임 checkpoint를 포함하지 않는다. 무관한 사용자 변경은 남겨두고 파일별로 stage한다. 일괄 git add나 reset으로 분류를 생략하지 않는다.
3. LFS 포인터와 실제 파일을 구별하고 필요한 입력이 checkout에서 실체화되는지 확인한다. 기존 LFS 객체를 재사용하며, 누락됐을 때 실제 필요한 객체만 복구한다.
4. pin으로 검사하는 데이터의 Git 저장 bytes와 checkout bytes를 확인한다. CRLF·Git text 변환으로 pin이 달라질 가능성이 있으면 해당 경로의 .gitattributes를 최소한으로 보완하고 재검증한다. 전역 core.autocrlf 변경이나 해시 기대값 덮어쓰기로 차이를 숨기지 않는다.
5. 로컬 기준선 커밋 B0와 포함·제외 파일, 미해결 기존 검사 상태를 기록한다. B0는 보존·분리용 시작점이다. 21-05에 배정한 실패가 남아 있으면 그 사실을 함께 기록한다.

완료 조건은 B0에서 필요한 공통 계약과 활성 입력을 얻을 수 있고, 기존 사용자 변경이 보존되는 것이다. 파일·LFS 누락 또는 pin 불일치가 있으면 이를 고친 뒤 21-04의 작업트리 생성으로 넘어간다.

### 21-03 — 파일 소유권과 경로 인터페이스를 확정한다

1. 4절을 현재 저장소의 실제 구조에 대응시킨다. 메인·국가별·통합 담당의 수정 경로, 단일 작성 파일과 최종 포인터 소유권을 정한다.
2. 국가 준비용 입력·정규화·후보·증거의 상대 경로, 실행별 .tmp·검사 캐시·OS 임시 경로와 Next 출력 규칙을 정한다. 기존 스크립트의 실제 입출력을 조사해 지원되는 경로와 후속 일반화가 필요한 경로를 구별한다.
3. A·B·C 분기의 문서·보조 스크립트 파일을 나눈다. 기존 helper를 재사용하고, 반복 재현에 필요한 작은 명령 묶음만 추가한다. 실행되지 않는 추상 플랫폼·설정 체계를 만들지 않는다.
4. 이 인터페이스를 공통 기준선에 반영하고 세 분기가 같은 내용을 참조하게 한다.

산출물은 docs/development/workspace-ownership-v1.md와 workspace-layout-v1.md의 공통 경로·규칙 부분이다. 기존에 같은 역할의 문서가 있으면 그 위치를 재사용한다.

완료 조건은 각 분기가 다른 분기의 미완성 구현을 기다리지 않고 자기 파일을 작업할 수 있으며, 공용 파일 변경의 합류 담당이 명확한 것이다.

### 21-04 — 작업트리와 쓰기 출력을 실제로 분리한다

1. B0와 21-03의 공통 커밋을 포함하는 기준에서 국가 준비용 브랜치·작업트리를 만든다. 원본 메인 공간은 유지한다. 대상국 미지정이면 빈 country-prep 공간 하나를 사용한다.
2. 생성 경로가 허용된 workspace 안인지, 기존 worktree·폴더·브랜치와 충돌하는지 검사한다. 기존 항목이 있으면 내용과 소유 작업을 확인하고 별도 이름을 사용한다.
3. 필요한 파일과 LFS 입력을 확인한 뒤 lockfile에 맞게 독립 의존성을 준비한다. node_modules가 없어 검사가 생략된 상태를 격리 성공으로 기록하지 않는다.
4. 국가·실행별 출력과 .tmp·Next build·검사 캐시·OS 임시 경로 규칙을 적용한다. 해당 검사 프로세스가 사용할 실제 임시 루트와 캐시 설정을 확인한다. 현재 도구가 runtime 고정 경로에 쓰면 해당 도구를 실행 가능한 준비 명령에서 제외하고 후속 일반화 대상으로 명시한다.
5. 실제 worktree·브랜치·공통 기준 commit·로컬 경로·도구별 입출력·필요한 환경을 기록한다. 반복 설정이 필요하면 scripts/workspaces/에 작은 setup helper를 두되 기존 구성을 우선한다. 21-07에서 같은 실행 경로로 두 대표 검사를 동시에 수행할 수 있게 한다.

산출물은 실제 국가 준비용 작업트리, workspace-layout-v1.md의 재현 절차와 .tmp/prompt21/workspace-layout.json이다.

완료 조건은 두 공간에서 필요한 공통 코드를 읽고 자체 출력에 쓸 수 있으며, 국가 준비 작업이 다른 공간의 캐시·산출물·활성 포인터를 변경하지 않는 것이다. 마지막 실제 동시 실험은 21-07에서 수행한다.

### 21-05 — 기존 fixture와 재현 가능한 검증 기준을 정비한다

1. operational-mixed-membership.test.ts의 과거 실패를 현재 로더 계약에 맞게 수정한다. 선언한 edge 수와 detail index·실제 edge 자료가 일치하는 최소 fixture를 만든다. 경계 연결과 기존 membership·lineage 의도를 보존한다.
2. edge 수를 0으로 바꾸어 검사를 회피하거나 운영 로더를 느슨하게 하지 않는다. skip·삭제·예외 문자열 일반화로 통과시키지 않는다. 정상 경계 입력을 가진 경우가 실제로 로드되고, 원래 양성·음성 테스트가 각각 목표 assertion에 도달하는지 확인한다.
3. 기존 동적 기대값 helper와 실제 채택 입력 대조를 재사용한다. 고정된 과거 snapshot 검사와 현재 활성 카탈로그 검사를 구별한다. fine/residual 분류, 동일 이름·다른 ID, 미확정 부모와 원본 연결을 유지한다.
4. 아래 검증 묶음의 실제 명령·실행 위치·필요 입력·예상 성격을 정리한다. fixture 수정과 아래 세 나라 검사는 이 단계에서 실행한다. 최종 관련 검사 묶음은 21-07에서 합류한 기준으로 실행하며, 코드·입력이 같은 검사의 근거는 연결해 재사용한다. 테스트 수는 실행 결과에서 읽는다.

5. 세 나라 실제 카탈로그 검사는 각 턴을 독립적인 새 메모리 게임에서 수행한다. 실제 전선 선택기·턴 계획 검증·원자적 runtime·이력 경로를 사용하고 아래 조건을 모두 검사한다. 현재 기록의 한 셀 선택 수를 고정 기대값으로 삼지 않는다.

   - 전선 선택 집합이 비어 있지 않고, 선택 집합과 실제 변경 집합이 정확히 같다.
   - 점령 후 선택 셀의 sourceCountryId와 법적 owner가 유지되고 controller가 공격국으로 바뀐다.
   - commit·undo·redo의 각 단계에서 선택 밖 모든 객체의 참조와 상태가 보존된다.
   - undo는 점령 전 world를, redo는 점령 후 world를 기존 authoritative hash와 상태 검사로 복원한다.
   - 국가별 actor·target·선택 ID·변경 ID·delta·이력 검사 결과와 전체 catalogRef를 기록한다.

6. 세 대상 KOR·PRK·CHN의 검사 레코드가 각각 존재하고 세 턴이 모두 실행·통과해야 성공이다. 전선 선택 실패·빈 선택·commit 실패·실행 누락은 실패로 집계해 검사 명령이 실패 종료하도록 한다. audit.cjs의 선택 실패 후 continue 경로와 최종 집계를 보완하거나 그 로직을 재사용하는 전용 테스트에서 같은 조건을 보장한다. 상위 PASS 개수만으로 성공을 판정하지 않는다.
7. 감사의 기존 보고서·evidence를 보존하고 새 실행 출력은 .tmp/prompt21/ 아래 실행별 경로에 둔다. 기존 스크립트를 직접 재사용할 경우 출력 경로를 분리하는 최소 보완을 한다. 실제 카탈로그는 읽고 게임 변경은 새 메모리 게임에 한정한다.
8. Node test runner 파일은 node --test로 별도 실행한다. Vitest 명령의 인자에 .node-test.mjs를 넣은 것만으로 실행됐다고 판단하지 않는다. 실제 수집 파일과 테스트 이름을 확인한다.
9. 현재 테스트 명령이 의존하는 ignored 입력이 있으면 출처·복구 방법을 확인한다. 재생성이나 복구가 필요한 경우 대상과 비용을 기록한다. 원본 없는 입력을 빈 파일이나 가짜 PASS로 대체하지 않는다.

산출물은 필요한 최소 fixture 수정과 docs/development/verification-baseline-v1.md다. 재사용 명령이 길거나 누락되기 쉬우면 작은 검증 helper를 추가한다. 이 작업에서 새 회귀를 막는 데 필요한 검사만 추가하고 무관한 테스트 재작성은 피한다.

완료 조건은 과거 실패 4개의 대응과 현재 결과를 설명할 수 있고, 세 나라 각각의 실제 전선·점령·undo/redo·선택 밖 객체 보존이 모두 통과하는 것이다. 검사 명령·필수 대상·실패 집계가 재현 가능해야 한다. 이번 변경과 관련된 실패를 해결한 뒤 21-07로 합류한다.

### 21-06 — 국가 준비와 최신 메인 합류 계약을 작성한다

기존 docs/geography/country-metadata-handoff-v1.md를 재사용해 docs/development/country-workspace-handoff-v1.md에 작업 공간·버전 합류 절차를 연결한다. 공통 지리 schema를 복제하지 않는다.

인계에는 최소한 다음 정보가 있어야 한다.

- 실제 CountryId 또는 대상 미지정의 null과 준비 단계.
- base commit, 공통 계약 버전, 전체 catalogRef와 metadataRef, 실제 의존하는 공통 검증 코드·입력의 상대 경로와 바이트 pin.
- 원본 배포자·직접 참조·고정 시점·license·source-lock 및 검증한 계층의 근거. 미조사 상태는 명시적 미조사.
- 입력·출력의 상대 경로, 실제 존재하는 파일의 sha256·byteLength, 생성 명령과 사용 코드 commit.
- 국가별 소유 파일과 공용 변경 요청, 비대상국에 미치는 알려진 영향.
- 이름·부모·범위의 확인 수준, 미확정·partial·unsupported 항목과 알려진 한계.
- 실제 실행한 검사·결과·실패·생략 사유와 후속 통합에서 다시 확인할 항목.

메인이 바뀌면 다음 순서로 처리한다.

1. 국가 준비 담당자가 마지막으로 검증한 base와 최신 공통 변경의 차이를 확인한다.
2. 자기 브랜치에서 적절한 merge·rebase 또는 선택한 공통 커밋 반영으로 동기화한다. 진행 중인 변경을 보존하고 다른 작업의 브랜치를 강제 갱신하지 않는다.
3. 실제 의존하는 공통 schema·검증 코드·참조·입출력 pin이 바뀌면 기존 검증 근거를 재검증 필요 상태로 처리한다. 관련 코드·입력을 동기화하고 검사를 다시 실행한 뒤 인계 manifest의 기준선·의존 pin·검증 결과를 갱신한다. 관계없는 문서 변경은 영향 검토 결과를 기록하고 유효한 준비 자료와 근거를 재사용한다.
4. 국가별 인계는 통합 담당자가 최신 메인과 활성 참조를 기준으로 다시 검사한다. 두 국가가 같은 옛 기준에서 준비됐어도 최종 합류는 최신 상태에 하나씩 적용한다.

원본 조사·계층·이름 준비는 새 TerritoryId가 나오기 전에 진행할 수 있다. 이 단계에서 미래 ID를 임의 발급하거나 source feature ID를 provinceId로 대체하지 않는다. 실제 신규 영토와 metadata의 연결은 후속 후보 생성·통합 단계에서 확인한다.

현재 metadata 입력 helper가 검증하는 기존 카탈로그의 셀 집합과 미래 국가 형상 후보를 구별한다. source-preparation 단계의 인계를 production metadata 채택 성공으로 표시하지 않는다.

완료 조건은 메인 변경 중에도 국가 준비 담당자가 유지할 자료와 재검증할 자료를 구별할 수 있고, 통합 담당자가 stale·잘못된 국가·근거 누락을 확인할 수 있는 것이다. 21-07의 관련 메인 변경·동기화 연습에서 같은 인계 검사 절차를 사용한다.

### 21-07 — 합류한 기준으로 격리·재현·인계를 실험한다

#### 공통 기준과 검증 재현

1. A·B·C의 공통 산출물을 합류한 준비 기준 커밋 B1을 만든다. 국가 준비용 작업트리에 정상적인 Git 절차로 반영한다. 기존 브랜치의 사용자 변경을 강제 초기화하지 않는다.
2. 두 작업 공간의 공통 소스·lockfile·활성 입력 pin이 B1 기준에 맞는지 확인한다. 모든 HEAD가 같아야 한다고 강제하지 말고 공통 base와 이후 각자 변경을 구별한다. LFS 포인터 잔존·줄바꿈 변환·미추적 입력 누락도 검사한다.
3. 통합 공간에서 21-05의 최종 관련 검증 묶음을 한 번 실행한다. 세 나라 실제 전선 검사는 21-05에서 검사한 코드·입력 pin이 같으면 근거를 연결해 재사용한다. 관련 코드·입력이 바뀌면 영향받은 검사를 다시 수행한다. 국가 준비 공간에서도 실제 metadata 읽기와 아래 대표 검사를 재현하고 공간별 명령·수집 파일·결과를 기록한다.

#### 실제 도구의 동시 실행과 쓰기 경로

1. 두 공간에서 같은 상대 .tmp 경로에 서로 다른 작은 표식을 쓰고 각자 결과가 유지되는지 확인한다. 이어서 Vitest로 실행하는 metadata 입력 helper 또는 수정한 membership fixture 중 작은 대표 파일 하나를 정해 두 작업트리에서 동시에 실행한다. 기본 실험은 각 공간 한 프로세스씩의 동시 실행 1회다.
2. 작업트리·실행별 캐시·결과·OS 임시 하위 경로를 정하고 해당 프로세스와 자식 프로세스에 적용한다. 설치된 Vitest·Vite의 지원 설정을 확인한다. 실행 전에 검사 루트·해석된 캐시 경로·실제 OS 임시 루트를 확인하고, 실행 중 또는 실행 로그에서 실제 생성 경로와 작성 프로세스를 대조한다.
3. 프로세스별 시작·종료 시각과 종료 코드, 실제 수집 파일·검사 수, 캐시·임시 파일·결과의 관측 경로를 기록한다. 두 검사의 실행 구간이 겹치고, 각자의 지정 경로에 쓰며, 상대 작업 공간의 결과를 덮어쓰지 않고 모두 정상 종료해야 통과다. OS 임시 루트의 실제 독립 하위 경로도 판정 근거로 남긴다.
4. 파일 rename·권한 오류가 발생하면 실패 경로·발생 단계·오류 코드와 단독 실행 재현 여부를 확인한다. 환경 권한 문제와 경로 공유 문제를 근거에 따라 구별하고, 필요한 최소 경로·실행 설정을 고친 뒤 동시 실험을 재시도한다. 테스트 수집 전 중단과 assertion 실패는 결과에서 구별한다.
5. 활성 catalog·geography 두 포인터와 보호 입력의 전후 hash를 확인한다. 경로 설정은 해당 검사 프로세스와 자식 프로세스에 한정한다. 성공한 동시 실행 1회를 완료 근거로 삼고, 추가 반복은 발견한 오류의 수정 확인에 한정한다.

#### 준비 시작 후 관련 메인이 바뀌는 연습

1. 작은 합성 인계로 정상 수락과 stale ref·schema 불일치·다른 국가 연결의 거부를 확인한다. 기존 helper를 우선 사용하고 필요한 작업 공간 인계 검증만 최소한으로 보완한다. 합성 자료는 실행별 경로에 둔다.
2. 기존 두 작업 공간의 전용 연습 브랜치에서 B1을 기준으로 준비 인계 H1을 만든다. 준비 자료·의존 pin·검증 근거를 고정하고 준비 브랜치를 B1에 둔 채, 통합 측 연습 브랜치에 관련 공통 변경 커밋 B2를 만든다. B2는 준비 자료가 실제 의존하는 공통 입력 또는 검증 규칙 하나의 작은 호환 변경으로 정한다. 같은 원본 준비 자료가 새 검증도 통과할 수 있는 사례를 사용한다.
3. B2의 최신 의존성을 기준으로 H1을 검사해 기존 검증 근거가 재검증 필요 상태로 거부되는지 확인한다. 단순히 인계의 ref 문자열을 임의로 바꾸는 음성 검사와 구별하고 실제 두 브랜치의 commit·의존 파일 pin 차이를 근거로 남긴다.
4. 준비 브랜치에 B2를 정상적인 Git 절차로 반영하고 관련 검사를 재실행한다. 원본 준비 자료 bytes는 유지한 채 기준선·의존 pin·검증 결과를 갱신한 H2를 제출해 수락되는지 확인한다. H1 거부와 H2 수락, 동기화 전후 commit, 재실행 명령·결과, 준비 자료 hash 보존을 기록한다.
5. 이 연습은 관련 변경 하나의 감지 → 동기화 → 재검증 → 수락 1회로 완료한다. 변경 영향은 실제 의존 파일과 계약을 기준으로 판단한다. 연습 변경은 전용 브랜치와 합성 입력에 한정하고, 실제 활성 포인터·카탈로그·국가 원본은 B1의 검증된 상태로 유지한다. 이후 작업 공간은 정상적인 Git 절차로 검증한 공통 개발 기준에 연결하고 연습 브랜치·근거는 보존한다.

#### 실행 범위와 완료 판정

변경이 fixture·개발 지침·로컬 설정 helper에 한정되면 해당 검사로 검증한다. 런타임·빌드 설정을 실제로 바꿨으면 독립 build 경로와 로컬 포트로 관련 build·API·브라우저 확인을 추가한다. 기존 build 근거를 재사용할 경우 코드·입력 identity와 근거 경로를 확인한다. 실행한 자신의 서버·임시 설정만 확인해 정리하고, Next가 추가한 임시 tsconfig include는 본인 변경분만 되돌린다.

완료 조건은 두 작업 공간이 공통 계약을 재현하고, 실제 대표 검사 동시 실행 1회에서 캐시·임시 파일·결과의 격리와 정상 종료를 입증하며, 관련 메인 변경 연습 1회에서 기존 인계 거부 후 동기화·재검증·수락을 확인하는 것이다. 실험 규모는 위의 각 1회로 정하고 추가 실행은 발견 오류의 수정 확인과 관련 변경의 재검증에 한정한다. 실제 국가 추가·전역 조립·포인터 전환은 후속 범위다.

### 21-08 — 완료 근거와 다음 작업을 인계한다

reports/maintenance/prompt21-completion.md와 prompt21-completion.json에 실제 실행 결과를 정리한다. 별도의 태스크 순서표는 만들지 않고 이 문서 5절의 다이어그램을 참조한다.

기록할 항목은 다음과 같다.

- 완료·미완료 태스크와 실제 변경 파일, B0·B1·연습용 B2 및 검증한 각 작업 공간의 commit.
- 작업트리·브랜치·상대 출력 경로, 공통 담당·국가 담당·통합 담당의 변경 경계.
- 전체 catalogRef·metadataRef, 실제 입력·코드 pin과 기존 포인터·게임 상태 보존 결과.
- 과거 실패 4개의 테스트 이름·원인·수정·현재 결과 대응, 기존 보완 검사의 재사용 근거.
- KOR·PRK·CHN 세 대상 각각의 전선 선택·점령·undo/redo·선택 밖 객체 보존 결과와 필수 세 턴의 실행·성공 집계. 실행 누락·전선 선택 실패도 포함.
- 공간별 실행 명령·실제 통과/실패 수·수집 파일과 시간, 전체 실행·대표 실행·기존 근거 재사용의 구별.
- Git/LFS·줄바꿈·의존성 준비, 실제 대표 검사 동시 실행 구간과 프로세스별 캐시·OS 임시·결과 경로, 정상 종료와 보호 입력 보존 결과.
- 관련 메인 변경 B2, 이전 인계 H1의 재검증 요구, 준비 브랜치 동기화·재실행과 H2 수락, 원본 준비 자료 hash 보존 결과.
- 발견한 환경 권한·경로 문제의 재현과 조치, 테스트 수집 전 실패와 실행된 테스트 결과의 구별.
- 대상국 null 여부, 실제 국가 조사·후보 생성·발행을 시작하기 위한 남은 조건.
- 국가 adapter·증분 조립의 일반화, 최종 전역 통합·전환, 새 국가 전체 검증으로 이어지는 후속 범위.

최종 보고 파일은 자기 자신의 hash나 자신을 포함하는 commit을 내부에서 고정하려고 반복 갱신하지 않는다. 검증한 코드·입력 기준 commit을 기록하고 보고서가 추가된 최종 commit은 최종 답변 또는 별도 실행 기록으로 연결한다.

최종 답변에는 바로 병렬 진행할 수 있는 메인 개발·국가 자료 준비의 범위, 실제 사용 가능한 작업 공간, 공통 변경의 합류 담당과 남은 제한을 짧게 설명한다. 실행하지 않은 검사는 명시하고 PASS로 기록하지 않는다.

## 7. 최종 완료 체크

- 프롬프트 20의 필수 수정·미추적 파일이 새 작업트리에서 재현되는 기준선에 포함됐다.
- 기존 사용자 변경·게임·활성 catalog·geography 포인터와 보호 입력을 보존했다.
- 메인 공간과 국가 준비 공간의 브랜치·쓰기 경로·의존성·빌드 산출물이 분리됐다.
- 과거 fixture 실패 4개를 추적했고 의도한 membership·lineage 검사가 실제로 실행된다.
- 현재 활성 자료를 하드코딩된 개수 없이 검사하고, 독립 ID·점령·undo/redo·게임 보존 검증을 재사용했다.
- KOR·PRK·CHN 각각의 실제 전선 선택·점령·undo/redo·선택 밖 객체 보존을 검사했고 필수 세 턴이 모두 실행·통과했다.
- 두 작업 공간의 실제 대표 검사 동시 실행 1회에서 프로세스별 캐시·OS 임시·결과 경로 격리와 정상 종료를 확인했다.
- 관련 메인 변경 연습 1회에서 이전 인계 거부 → 준비 브랜치 동기화·재검증 → 같은 준비 자료를 사용한 인계 수락을 확인했다.
- 변경 의존성에 따른 최신 메인 동기화와 국가별 인계, 단일 통합 담당의 순차 합류 규칙을 확정했다.
- 실제 새 국가의 생성·발행·전환은 후속 범위로 구분했고 프롬프트 22나 국가 추가를 자동 시작하지 않았다.

완료 근거가 빠진 항목은 미완료 또는 구체적인 제한으로 남긴다. 프롬프트 문서 작성 자체와 “21 실행”의 구현 완료를 구별한다.
