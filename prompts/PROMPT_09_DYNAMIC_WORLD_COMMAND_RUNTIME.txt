# Prompt 09 — 동적 국가 생성·삭제·분할·병합 런타임

## 0. 목표

`D:\SSAFY\WORKSPACE\pax-local`에 국가가 빠르게 생성·삭제·분할·병합·이름 변경·영토 이전되어도 검색, 선택, 국가 패널, 지도 폴리곤, 국경, 라벨, 저장, undo/redo가 동일한 상태를 유지하는 동적 월드 런타임을 구현한다.

이 Prompt 09의 최종 산출물은 자연어 프롬프트 해석기가 아니다. 자연어 해석기가 안전하게 호출할 수 있는 결정적이고 원자적인 `MapCommand -> WorldState -> WorldPatch -> MapArtifacts` 실행 기반이다. 프롬프트 UI와 LLM 연결은 후속 Prompt에서 수행한다.

Prompt 08은 취소된 구상이다. Prompt 08 보고서나 단계 상태를 Prompt 09의 선행 PASS 근거로 사용하지 않는다. 기존 world-space glyph 코드와 중국 31개 성 분할 테스트는 재사용 가능한 현재 코드일 뿐, 완료 증거로 간주하지 않는다.

## 1. 절대 원칙

1. `WorldState`를 런타임 국가 정보의 유일한 원본으로 만든다.
2. 정적 JSON과 GeoJSON은 초기 seed와 원본 복구 자료로만 사용한다.
3. 검색, 선택, 플레이 국가, 패널, 지도 source, 라벨은 모두 같은 `WorldState.revision`에서 파생한다.
4. LLM, UI, MapLibre가 `WorldState`를 직접 수정하지 못하게 한다.
5. 모든 변경은 구조화된 `MapCommand`와 단일 command executor를 통과한다.
6. 명령은 검증과 파생 artifact 준비가 모두 성공한 뒤 한 번만 commit한다.
7. 실패한 명령은 국가 하나, source 하나도 부분 반영하지 않는다.
8. 전체 세계 복사나 전체 라벨 재계산으로 간단히 우회하지 않는다.
9. 변경된 국가와 실제 영향 이웃만 다시 계산한다.
10. 빠른 임시 라벨과 정밀 glyph 라벨을 분리한다.
11. 정밀 라벨 계산은 UI 스레드를 막지 않는다.
12. 국가별 수동 좌표와 수동 폰트 크기 예외를 추가하지 않는다.
13. 동일 입력, 동일 seed, 동일 policy version은 동일한 결과와 hash를 만든다.
14. 삭제된 국가 ID를 선택·검색·라벨·캐시·국경에 남기지 않는다.
15. rollback과 undo는 원본 좌표를 손실 없이 복구해야 한다.

## 2. 실행 규칙

각 `9-N`은 하나의 독립 작업 세션이다. 한 세션에서는 해당 번호의 범위만 구현한다. 다음 번호의 제품 코드, 테스트, 보고서를 미리 만들지 않는다.

각 단계 시작 시:

1. `AGENTS.md`를 읽는다.
2. 설치된 Next.js의 관련 문서를 `node_modules/next/dist/docs/`에서 읽는다.
3. 이전 단계 보고서의 `status`와 입력 hash를 현재 파일과 비교한다.
4. `reports/prompt09/9-N-<slug>.json`을 `running`으로 생성한다.
5. 현재 실패 재현 또는 기준 수치를 기록한다.

각 단계 종료 시 보고서에 다음을 기록한다.

```json
{
  "stage": "9-N",
  "status": "running | pass | fail | blocked",
  "objective": "",
  "inputHashes": {},
  "outputHashes": {},
  "changedFiles": [],
  "commands": [{"command": "", "exitCode": 0, "durationMs": 0}],
  "measurements": {},
  "gates": {},
  "firstFailedGate": null,
  "implementationErrors": [],
  "environmentErrors": [],
  "rollbackVerified": false,
  "nextStage": "9-(N+1)"
}
```

### 공통 검증 분기

- 모든 gate 통과: `pass`로 기록하고 중단한다. 다음 단계는 자동 실행하지 않는다.
- 구현 또는 테스트 실패: `fail`로 기록하고 중단한다. 다음 단계 산출물을 만들지 않는다.
- 환경 권한·브라우저·빌드 캐시 문제: 안전한 재시도를 한 번 수행한다. 재시도도 실패하면 `blocked`로 기록한다.
- 이전 보고서 hash 불일치: 이전 단계를 현재 입력으로 재검증한다. 일치가 복구되지 않으면 현재 단계를 시작하지 않는다.
- 테스트 기대값만 낡은 경우: 현재 제품 계약과 데이터 근거를 먼저 제시한다. 제품 코드가 맞다는 증거가 있을 때만 테스트를 수정한다.
- 성능 gate 실패: 기능 PASS로 축소하지 않는다. 해당 단계는 `fail`이다.
- rollback 불일치: 생성 화면이 정상이어도 해당 단계는 `fail`이다.
- 화면과 도메인 상태 불일치: 화면이 정상이어도 해당 단계는 `fail`이다.

## 3. 성능 기준

개발 머신에서 warm cache 기준으로 측정하며 최소 20회, p50과 p95를 보고한다.

- 단일 국가 이름 변경 commit: p95 50ms 이하
- 단일 국가 생성 또는 삭제 commit: p95 100ms 이하
- 31개 국가 분할의 즉시 commit: p95 250ms 이하
- 즉시 polygon·임시 label 화면 반영: 명령 commit 후 p95 300ms 이하
- 31개 정밀 glyph label 준비: worker에서 p95 2초 이하
- 명령 수행 중 100ms를 넘는 main-thread long task: 0개
- 영향 없는 국가 artifact 재생성: 0개
- rollback 즉시 commit: p95 150ms 이하

환경 편차로 절대 시간이 불안정하면 동일 머신의 전체 재생성 대비 비율도 기록한다. 증분 경로는 전체 재생성보다 유의하게 빨라야 하며, 최소 3배 개선되지 않으면 원인을 분석하고 `fail` 처리한다.

## 4. 단계 목록

### 기반 감사

#### 9-1. 런타임 상태 원본 목록 작성

동작: 국가 정보를 보유하는 정적 JSON, `countryById`, Zustand store, MapLibre source, label metrics, glyph GeoJSON, capital 데이터와 테스트 snapshot의 경로·소유자·갱신 방식을 목록화한다. 제품 코드는 수정하지 않는다.

검증: 국가 이름 변경, 국가 삭제, 중국 31개 분할 각각이 어느 저장소에 반영되고 누락되는지 표로 기록한다.

분기: 소유자를 확인하지 못한 source가 하나라도 있으면 `fail`. 모두 확인하면 `pass`.

#### 9-2. 현재 동적 변경 기준 성능 측정

동작: 이름 변경 1개, 생성 1개, 삭제 1개, 중국 31개 분할과 rollback의 현재 시간·재계산 수·`setData()` 수를 계측한다. 제품 코드는 수정하지 않는다.

검증: 동일 seed로 20회 실행하고 p50/p95, main-thread long task, 변경 source를 보고한다.

분기: 측정 자체가 비결정적이거나 rollback 후 hash가 다르면 `fail`. 측정 가능하면 성능이 느려도 `pass`하고 기준선으로 보존한다.

#### 9-3. 정적 국가 의존성 차단 목록 확정

동작: 런타임에서 제거해야 할 `countries-2020.json` 직접 import와 고정 `countryById` 사용 지점을 분류한다.

검증: 각 사용 지점을 seed-only, runtime-read, test-only로 분류한다.

분기: 분류되지 않은 직접 import가 남으면 `fail`.

### WorldState 저장소

#### 9-4. WorldState 불변식 타입 정의

동작: revision, countriesById, countryOrder, schemaVersion을 가진 런타임 타입과 불변식을 정의한다.

검증: 빈 ID, 중복 ID, entity.id와 key 불일치, 잘못된 geometry를 거부하는 단위 테스트를 작성한다.

분기: 잘못된 상태가 생성 가능하면 `fail`.

#### 9-5. seed에서 WorldState 생성

동작: 정적 metadata·geometry·capital을 오직 초기화 함수에서 결합한다.

검증: 현재 사용자가 확정한 국가 집합과 순서가 손실 없이 생성되고 `미합중국`, `중화인민공화국`이 보존되는지 확인한다.

분기: 고정 국가 수를 테스트에 다시 쓰면 `fail`; seed 자체 개수를 기준으로 검증하면 `pass`.

#### 9-6. WorldState 런타임 store 생성

동작: Zustand에 WorldState와 읽기 전용 selector를 추가한다. 기존 선택 UI를 아직 전환하지 않는다.

검증: 구독자는 revision 변경 시 한 번만 통지되고 무관한 UI selector는 재렌더되지 않아야 한다.

분기: 국가 변경 한 번에 중복 commit이 발생하면 `fail`.

#### 9-7. 동적 `getCountryById` selector 구현

동작: 정적 `countryById` 대체 selector를 구현한다.

검증: 런타임 추가 국가를 즉시 조회하고 삭제 직후 null을 반환한다.

분기: 정적 index fallback으로 삭제 국가가 반환되면 `fail`.

#### 9-8. 동적 국가 iteration selector 구현

동작: 결정적 `countryOrder`에 따라 국가 목록을 반환한다. React/Zustand 구독에 사용하는 selector는 동일한 `WorldState` snapshot에 대해 동일한 배열 참조를 반환하도록 memoize한다. 같은 snapshot을 읽을 때마다 `map()`으로 새 배열을 생성해서는 안 된다.

검증: 생성·삭제·rollback 전후 순서 hash가 결정적인지 확인한다. 동일 snapshot을 연속 조회한 두 결과가 `Object.is` 기준으로 같아야 한다. `useWorldStateSelector(store, selectCountriesInOrder)`를 사용하는 실제 React 컴포넌트를 렌더링하고, 무한 재렌더 없이 초기 목록과 생성·삭제·rollback 이후 목록이 갱신되는지 단위 테스트로 확인한다.

분기: Object insertion order에 암묵적으로 의존하거나, 동일 snapshot에서 새 배열 참조를 반환하거나, React 렌더에서 `getSnapshot should be cached` 경고 또는 `Maximum update depth exceeded` 오류가 발생하면 `fail`.

### 명령 스키마

#### 9-9. MapCommand 공통 envelope 정의

동작: commandId, type, expectedRevision, payload, issuedAt, source를 정의한다.

검증: 알 수 없는 필드, 빈 ID, 잘못된 revision을 schema validator가 거부한다.

분기: TypeScript cast만으로 명령을 신뢰하면 `fail`.

#### 9-10. `country.create` 스키마 정의

동작: 새 CountryEntity 전체와 선택적 초기 presentation을 payload로 정의한다.

검증: 기존 ID 충돌, 잘못된 polygon, 빈 이름, 허용되지 않은 unitType을 거부한다.

분기: 기존 국가를 묵시적으로 overwrite하면 `fail`.

#### 9-11. `country.delete` 스키마 정의

동작: countryId와 삭제 정책을 정의한다.

검증: 없는 국가 삭제와 마지막 유효 국가 삭제 정책을 명시적으로 처리한다.

분기: 없는 국가 삭제를 조용히 성공 처리하면 `fail`.

#### 9-12. `country.rename` 스키마 정의

동작: shortKo, officialKo, mapKo, english, aliases 중 명시된 필드만 변경하도록 정의한다.

검증: geometry hash는 유지되고 label cache key만 필요한 경우 바뀌어야 한다.

분기: 이름 변경이 polygon artifact를 재생성하면 `fail`.

#### 9-13. `territory.replace` 스키마 정의

동작: 단일 국가 geometry 전체 교체 명령을 정의한다.

검증: self-intersection, 빈 polygon, 비유한 좌표, 비정상 winding 입력을 정규화 또는 거부한다.

분기: 정규화 결과가 결정적이지 않으면 `fail`.

#### 9-14. `territory.transfer` 스키마 정의

동작: from, to, transferGeometry와 boolean-operation policy를 정의한다.

검증: 전달 면적이 from과 겹치지 않거나 to와 충돌하는 경우를 거부한다.

분기: 면적 손실 또는 중복이 tolerance를 넘으면 `fail`.

#### 9-15. `country.split` 스키마 정의

동작: sourceCountryId, result countries, partition geometries를 정의한다.

검증: 결과 union이 원본과 일치하고 결과끼리 중첩되지 않아야 한다.

분기: gap/overlap이 tolerance를 넘거나 원본이 결과에도 남으면 `fail`.

#### 9-16. `country.merge` 스키마 정의

동작: source IDs와 단일 result entity를 정의한다.

검증: result geometry가 source union과 일치하고 source IDs가 제거되는지 확인한다.

분기: source metadata가 어느 규칙으로 승계되는지 불명확하면 `fail`.

#### 9-17. command batch 스키마 정의

동작: 여러 명령을 순서가 있는 하나의 transaction으로 묶는다.

검증: batch 내부에서 생성한 ID를 다음 명령이 참조할 수 있고, 실패 시 전부 취소되어야 한다.

분기: 부분 commit 가능성이 있으면 `fail`.

### 실행 계획과 원자성

#### 9-18. dry-run planner 구현

동작: 현재 상태를 변경하지 않고 명령 결과의 생성·수정·삭제 ID를 계산한다.

검증: dry-run 전후 WorldState object identity와 hash가 동일해야 한다.

분기: dry-run이 캐시나 store를 변경하면 `fail`.

#### 9-19. expectedRevision 충돌 검사

동작: stale command가 최신 WorldState를 덮어쓰지 못하게 한다.

검증: revision N 명령을 N+1 상태에 적용하면 명시적 conflict를 반환한다.

분기: 자동 재시도나 묵시적 merge를 수행하면 `fail`.

#### 9-20. 영향 국가 집합 계산

동작: created, updated, deleted, direct neighbors를 계산한다.

검증: 중국 분할에서 중국 인접국은 포함하고 남미 국가는 포함하지 않는다.

분기: 매번 모든 국가를 affected로 반환하면 `fail`.

#### 9-21. 임시 next state 생성

동작: 현재 state를 보존한 채 변경된 map entry만 복사해 next state를 만든다.

검증: 영향 없는 CountryEntity는 참조 동일성을 유지한다.

분기: 전체 entity deep clone이면 성능 측정과 함께 `fail`.

#### 9-22. commit 함수 구현

동작: 검증된 next state를 revision 한 번 증가시켜 store에 반영한다.

검증: batch 크기와 관계없이 subscriber 통지가 한 번인지 확인한다.

분기: 31개 생성에서 31번 commit하면 `fail`.

#### 9-23. 실패 원자성 검증

동작: batch 중간에 의도적 오류를 삽입한다.

검증: state revision, 국가 hash, selection, artifact index가 모두 이전과 같아야 한다.

분기: 하나라도 변하면 `fail`.

### WorldPatch

#### 9-24. WorldPatch 타입 정의

동작: created, updated, deleted, affectedNeighbors, beforeRevision, afterRevision을 정의한다.

검증: 집합이 중복·교차하지 않고 정렬이 결정적인지 확인한다.

#### 9-25. 이름 변경 patch 생성

동작: rename이 updated 한 개만 반환하도록 한다.

검증: affectedNeighbors와 geometryChanged가 비어 있어야 한다.

분기: 전체 국가가 updated로 표시되면 `fail`.

#### 9-26. 생성·삭제 patch 생성

동작: create/delete에 대한 정확한 집합을 생성한다.

검증: 삭제 ID는 이후 selector에서 즉시 사라져야 한다.

#### 9-27. 중국 31개 분할 patch 생성

동작: CHN 삭제와 31개 생성 및 인접국 집합을 계산한다.

분기: 테스트용 고정 source를 제품 executor가 특별 취급하면 `fail`.

### 검색·선택·패널

#### 9-28. 검색 인덱스 patch API 구현

## 5. 금지 구현

- LLM이 GeoJSON source나 Zustand를 직접 수정하는 코드
- 국가별 하드코딩된 생성·삭제 분기
- 중국 전용 제품 command executor
- 국가 변경마다 전체 세계 label 재계산
- 국가 변경마다 전체 검색 index 재생성
- 정적 `countryById`와 동적 WorldState 동시 사용
- 실패한 batch의 부분 commit
- rollback을 위한 boolean 역연산만 저장
- stale Worker 결과 적용
- 국가별 수동 label anchor·font size·tracking 추가

- MapLibre 화면만 바꾸고 WorldState는 그대로 두는 구현
- 전체 source snapshot을 장기 undo history로 무제한 저장
- Prompt 08 단계나 보고서를 Prompt 09 PASS 증거로 재사용

## 6. Prompt 09 이후 연결 계약

후속 자연어 프롬프트 시스템은 다음 인터페이스만 사용할 수 있다.

```text
사용자 자연어
→ 해석된 MapCommand batch
→ schema validation
→ dry-run preview
→ 사용자 승인
→ atomic executor
→ WorldPatch
→ WorldState 및 파생 artifact 반영
```

후속 시스템은 country ID를 임의로 추측하지 않고 현재 WorldState 검색 결과로 대상을 resolve해야 한다. 모호한 대상, 충돌하는 명령, 큰 영토 변화는 apply 전에 사용자 확인을 요구한다.
