# [임시 보관] Pax Local 8차 작업: 곡선 국가명·윤곽선 스타일·공식 국호·SPI 병합

이 문서는 7O 전체 회귀 및 최종 완료 감사가 성공했다는 전제에서 시작하는 8차 작업 프롬프트다.

이번 단계의 중심은 **현재 정적 2020 OTL 지도에서 국가명을 국토 형상과 방향을 따라 자연스럽게 휘어 표시하는 기능을 완성하는 것**이다.

목표는 다음 세 가지다.

1. 현재 `Point + text-rotate` 방식의 직선 국가명을 geometry에서 계산한 곡선 `LineString`을 따르는 국가명으로 개선하고, 글자 내용과 테두리가 모두 흰색인 스타일을 적용한다.
2. 중국·북한·미국의 지도 표시명을 공식 국호로 변경한다.
3. 기술 지도 단위 `SPI — Southern Patagonian Ice Field`를 제거하고 아르헨티나에 병합한다.

이번 단계에서는 런타임 국가 생성·소멸, 실시간 영토 이전, 런타임 국경 topology 재구축, 동적 세계 상태 저장·복원을 구현하지 않는다. 단, 곡선 좌표를 국가별로 하드코딩하지 말고 현재 국가 geometry에서 결정적으로 재계산할 수 있는 순수 함수 구조를 유지하여 후속 확장을 막지 않는다.

이 문서 전체를 한 번에 실행하지 마라. 8A부터 순서대로 진행하되, 아래 묶음 단위로 구현과 독립 검증을 분리한다.

```text
8A 구현 → 독립 검증 → 사용자 확인
8B~8C 구현 → 독립 검증 → 사용자 확인
8D 최종 회귀 감사
```

각 구현 묶음이 끝나면 결과를 보고하고 반드시 종료한다. 사용자 확인 없이 다음 묶음으로 넘어가지 않는다.

## 0. 공통 운영 규칙

- 먼저 `AGENTS.md`를 읽는다.
- Next.js 코드를 수정할 때는 `node_modules/next/dist/docs/`의 현재 설치 버전 문서를 먼저 확인한다.
- 7O가 실제로 PASS인지 확인한다. PASS가 아니면 8차 작업을 시작하지 않는다.
- 기존 사용자 변경을 보존한다.
- 2020 OTL의 기존 플레이 가능 국가와 국가 선택 흐름을 보존한다.
- 큰 영토는 국가당 하나의 곡선 line 라벨, 소국가는 국가당 하나의 Point 폴백을 사용하고 같은 줌에서 둘이 중복되지 않게 한다.
- world-space 크기, shape-aware 배치, 실제 폰트 metric, raw 중복 검증을 유지한다.
- 국가별 anchor·angle 좌표 override로 문제를 우회하지 않는다.
- 데이터 피처 수, 논리적 라벨 수, 실제 화면 라벨 수를 별도로 검증한다.
- 실패한 항목이 있으면 전체 완료라고 보고하지 않는다.
- 개발 서버와 Playwright worker를 작업 후 남기지 않는다.

### 향후 확장성을 위한 필수 경계

이번 작업은 정적 지도 생성 파이프라인에서 수행해도 된다. 그러나 다음 경계는 반드시 지킨다.

```text
Country geometry
  → shape-aware layout 계산
  → 곡선 baseline 생성
  → 렌더용 GeoJSON 생성
  → MapLibre 렌더링
```

- 곡선 baseline 생성은 DOM, React, MapLibre 객체에 의존하지 않는 순수 함수여야 한다.
- 입력은 최소한 `countryId`, `geometry`, `label`, 선택적 `previousLayout`을 받을 수 있어야 한다.
- 출력은 직렬화 가능한 GeoJSON 및 수치 데이터여야 한다.
- `recomputeCountryLabels(changedCountries, previousLayouts)`의 변경 국가만 재계산하는 계약과 `geometryHash`를 유지한다.
- MapLibre source는 향후 `GeoJSONSource#setData()`로 교체할 수 있는 구조를 유지한다.
- 현재 2020년 국가 목록이나 특정 국가 ID allowlist가 곡선 계산 함수 내부에 들어가면 안 된다.
- 국가별 미세 조정이 꼭 필요하면 좌표가 아니라 `curvature`, `letterSpacing`, `fontScale` 같은 정책 값으로 제한하고 근거를 기록한다.

## 8A. geometry 기반 곡선 국가명과 윤곽선 스타일

> **2026-08-14 재작성 지시:** 이 절의 `8A-R1`~`8A-R6` 순서가 8A의 최신 권위 있는 실행 순서다. 아래에 남아 있는 기존 `8A-1`~`8A-5`의 기술 요구사항은 참고 체크리스트로만 사용하고, 서로 충돌하면 `8A-R1`~`8A-R6`을 따른다.

### 목적

현재 구현은 영토에서 계산한 Point anchor에 전체 문자열을 한 각도로 회전해 표시한다. 계산된 baseline도 두 점짜리 직선이며 실제 텍스트 렌더링에는 사용되지 않는다.

이를 다음 구조로 변경한다.

```text
현재 국가 Polygon
  → 유효 라벨 영토 선택
  → anchor·angle·가용 폭·높이 계산
  → 여러 점으로 이루어진 완만한 곡선 LineString 생성
  → 텍스트를 곡선 경로를 따라 렌더링
```

목표는 단순히 문자열 전체를 기울이는 것이 아니라 각 glyph가 국토의 장축을 따르는 완만한 곡선 위에 배치되는 것이다. 동시에 국가명의 글자 내용과 주 테두리를 모두 흰색으로 변경한다.

### 최신 구현 감사 결과와 출발점

8A는 재시행되어 다음 항목까지 구현된 상태다.

- 17개 좌표를 가진 포물선형 baseline 생성
- 큰 영토 baseline source 등록
- MapLibre `symbol-placement: "line"` 적용
- line 라벨의 `text-rotate` 제거
- 소국가 Point 폴백 분리
- 상한 전 `fontSizeWorldUnits × 2^zoom`으로 증가하고 MapLibre line anchor 배치를 위해 `25.6px`에서 멈추는 단일 world-space `text-size` 표현식
- 흰색 글자 내용과 어두운 halo 설정
- 8A-1~8A-4 보고서와 대표 국가 스크린샷 생성

독립 재검증 결과는 다음과 같다.

- unit test: 7개 파일, 39개 테스트 전부 PASS
- lint: 오류 0개, 기존/신규 warning 3개
- curved 대상: 182개, Point 폴백: 74개, 합집합 256개, 교집합 0개
- curved 전체 최소 `baselineInsideRatio`: `0.901235`, 실패 국가 0개
- curved 전체 좌표 수: 모두 17개
- 대표 국가 및 윤곽선 스크린샷: 생성됨

그러나 아래 항목은 아직 실패 또는 미완성이다. 모두 해결하기 전에는 8A를 완료로 판정하지 않는다.

1. production build가 `e2e/fix08-8a3.spec.ts`의 `screenshotZoom` union type 오류 `TS2339`로 실패한다.
2. `.next/cache/.tsbuildinfo` 및 Turbopack cache 쓰기에서 EPERM도 발생한다. 타입 오류와 환경 오류를 분리해 둘 다 보고해야 한다.
3. `validate-fix08-curved-labels.mjs`를 재실행하면 이미 PASS였던 `fix08-curved-label-render.json`을 `pending-e2e`로, `fix08-outline-label-style.json`을 `configured`로 덮어쓴다. validator 실행 순서에 따라 완료 상태가 퇴행한다.
4. 현재 스타일은 `text-color: #fffdf2`, `text-halo-color: #263439`인 “흰 내용 + 어두운 테두리”다. 최신 사용자 요구는 **글자 내용과 테두리 모두 흰색**이다.
5. 정적 validator와 E2E 자체가 PASS 보고서를 서로 덮어쓸 수 있어 최종 감사의 재현성이 없다.

### 2026-08-14 단계 완료 원장

다음 결과는 생성된 보고서와 전용 테스트로 검증된 현재 권위 상태다.

|---|---|---|---|
| 8A-R1 | PASS | `reports/fix08-8ar1-world-state.json`, 256개국 손실 없는 초기화, synthetic ID 계산 | `CountryEntity`/`WorldState` 단일 소유 경계 |
| 8A-R2 | PASS | `reports/fix08-8ar2-artifact-pipeline.json`, 182 curved + 74 Point, 교집합 0 | `buildCountryMapArtifacts()`와 5개 `setData()` source 갱신 경계 |
| 8A-R3 | FAIL — 재작성 후 재실행 필요 | 기존 보고서는 라벨 존재와 바티칸 수치만 증명했으며 대형 curved 국가의 polygon 결합 확대를 증명하지 못함 | R1/R2 경계를 보존하고 실제 대형 국가에서 world-space 동작을 다시 구현·검증 |

R3 재감사에서 확인한 사실은 다음과 같다.

- MapLibre의 `symbol-placement: "line"` anchor 계산은 현재 줌 값만이 아니라 `text-size` 표현식 전체의 최대값인 `textMaxSize`를 사용한다.
- 상한 없는 `fontSizeWorldUnits × 2^zoom` 표현식은 줌 9 최대값 때문에 정상 baseline도 전부 배치 탈락시킬 수 있다.
- 현재 구현식 `min(25.6px, max(fontSizeWorldUnits, pointMinimum) × 2^zoom)`은 확정식이 아니라 실패 원인이다.
- 호주는 줌 2에서 약 `23.913648px`, 줌 3과 4에서 `25.6px`로 고정된다. 정상 사용 구간에서 국토만 확대되고 라벨은 고정되므로 polygon 결합 확대가 아니다.
- 바티칸 Point 폴백의 줌 7→8 수치로 대형 curved 국가인 호주의 확대 게이트를 대신 통과시킨 기존 검증은 무효다.
- 기존 보고서의 바티칸 `라벨/국토 폭 비율`은 약 `315.17`이므로 시각 품질의 정상성 근거로 사용할 수 없다.
- 초기 일반 지도는 중심 `[45, 25]`, 줌 `1`에서 USA·RUS·CHN을 모두 raw 렌더한다.
- 호주는 `showOnlyCountryLabel()` 없이 일반 지도 모드의 줌 2·3·4에서 월드 복사본당 raw 1개이며, 세 화면이 새로 캡처됐다.

기존 `reports/fix08-8ar3-world-space-zoom.json`의 `status: pass`는 폐기 대상의 과거 판정이다. 새 R3 실행은 해당 보고서를 올바른 증거로 교체해야 한다. R4는 새 R3 PASS가 나오기 전 시작하지 않는다.

현재 코드를 무조건 폐기하지 말고 재사용 가능한 구현은 유지하되, 검증을 통과시키기 위해 기준을 낮추거나 실패를 숨기지 않는다.

### 8A-R1. 단일 국가 원본과 WorldState 경계 도입

#### 목적

실제 국경 변경 기능이나 신생국 게임 이벤트를 구현하는 단계는 아니지만, 국가 이름과 geometry가 서로 다른 정적 파일의 우연한 결합으로만 유지되지 않도록 런타임 단일 원본 경계를 만든다.

#### 필수 모델

프로젝트에 맞게 이름은 조정할 수 있지만 다음과 동등한 구조를 둔다.

```ts
type CountryEntity = {
  id: string;
  iso3: string;
  names: {
    shortKo: string;
    officialKo: string;
    mapKo: string;
    english: string;
    searchAliases: string[];
  };
  geometry: PolygonGeometry;
  mapColor: string;
  playable: boolean;
  unitType: CountryUnitType;
  capital: {
    nameKo: string;
    nameEn: string;
    coordinates: [number, number];
  } | null;
};

type WorldState = {
  countries: Record<string, CountryEntity>;
  revision: number;
};
```

#### 필수 원칙

- 초기 2020 OTL JSON은 `WorldState` 초기화 입력이다. 앱 실행 후 국가의 논리적 원본은 `WorldState`다.
- 이름 변경은 `CountryEntity.names` 한 곳을 바꾸는 것으로 표현한다.
- geometry 변경은 같은 `CountryEntity.geometry`를 바꾸는 것으로 표현한다.
- 검색용 목록, 국가 Polygon, curved label, Point 폴백, capital과 metrics는 원본이 아니라 파생 결과다.
- `CountryEntity` 안에 MapLibre 객체나 React 객체를 넣지 않는다.
- 새 ID가 기존 256개 allowlist에 없어도 순수 라벨 계산 함수가 동작해야 한다.
- 이번 단계에서는 실제 전쟁, 조약, union/difference UI, 국가 생성 버튼, 저장·불러오기를 구현하지 않는다.

#### 완료 게이트

- 기존 256개 국가가 손실 없이 `WorldState`로 초기화돼야 한다.
- `countryId`, 이름, geometry의 단일 소유 관계가 테스트로 증명돼야 한다.
- 임의의 synthetic `CountryEntity` 하나가 고정 ID allowlist 없이 라벨 계산 입력으로 변환돼야 한다.
- 이름만 바꾸면 geometry hash는 유지되고 텍스트 관련 layout/cache key는 갱신돼야 한다.
- geometry만 바꾸면 해당 국가 geometry hash와 layout이 갱신돼야 한다.
- 기존 검색·선택 UI는 회귀하지 않아야 한다.

#### 산출물

- `reports/fix08-8ar1-world-state.json`

### 8A-R2. 파생 지도 산출물과 source 갱신 경계

#### 목적

국가 객체 하나에서 지도 레이어별 geometry를 파생하고, 나중에 국경 변경이나 신생국이 생겨도 같은 경계를 재사용할 수 있게 한다.

```ts
type CountryMapArtifacts = {
  countryFeature: GeoJSON.Feature;
  curvedLabelFeature?: GeoJSON.Feature;
  pointLabelFeature?: GeoJSON.Feature;
  capitalFeature?: GeoJSON.Feature;
  layout: CountryLabelLayout;
};

function buildCountryMapArtifacts(
  country: CountryEntity,
  previousLayout?: CountryLabelLayout
): CountryMapArtifacts;
```

#### 필수 원칙

- curved line과 Point 폴백은 동일 국가에 동시에 생성하지 않는다.
- 이름, geometry, font metric, layout, baseline의 연결은 `countryId`로 유지한다.
- 변경 국가만 다시 계산하는 `recomputeCountryLabels()` 계약을 유지하거나 더 명확한 동등 API로 감싼다.
- MapLibre 갱신은 정식 함수 경계를 갖고 `GeoJSONSource#setData()`로 countries, borders, curved labels, Point labels를 교체할 수 있어야 한다.
- 이번 단계에서는 실제 영토 연산은 하지 않되, upsert/remove가 가능한 직렬화 가능한 결과 타입을 둔다.

### 8A-R3. world-space 확대·축소와 초기 지도 가시성

> **현재 상태: FAIL — 재실행 대상.** 기존 `reports/fix08-8ar3-world-space-zoom.json`의 PASS 판정은 대형 curved 국가가 아니라 바티칸 Point 폴백으로 확대 비율을 대신 검증했으므로 무효다. R1/R2 구현과 사용자 변경은 보존하되 R3 구현·테스트·보고서를 다시 작성한다.

#### 목적

국가명을 화면 고정 UI 텍스트가 아니라 국가 geometry에 결합된 지도 요소로 만든다.

상한에 도달하지 않은 정상 사용 줌 구간의 기본식은 다음과 같다.

```text
fontSizePixels(zoom) = fontSizeWorldUnits × 2^zoom
```

여기서 핵심은 수식의 존재가 아니라 실제 화면 결과다. 국토의 화면 폭이 두 배가 되면 같은 국가 라벨의 실제 glyph 폭도 약 두 배가 되어야 하며, `라벨 화면 폭 / 유효 국토 화면 폭` 비율이 유지돼야 한다.

#### 현재 실패 원인

- 현재 `25.6px` 전역 상한은 호주가 줌 3부터 고정 크기가 되게 한다.
- MapLibre `symbol-placement: "line"`은 anchor 생성 시 표현식 전체의 최대 `textMaxSize`를 사용하므로 단순히 줌 9까지 지수 증가시키면 baseline 배치가 전부 탈락할 수 있다.
- 이 MapLibre 제약은 실제 목표를 낮출 근거가 아니다. renderer/source/layer 구성을 바꾸어 해결해야 한다.
- 작은 Point 국가나 순수 함수 수치로 대형 curved 국가의 화면 게이트를 대신 통과시키면 안 된다.

#### 필수 요구사항

- 같은 대형 curved 국가의 실제 렌더 glyph를 대상으로 줌이 1 증가하면 글자 크기와 화면 폭이 약 2배가 되어야 한다.
- 같은 국가에서 줌이 1 감소하면 실제 렌더 glyph 폭이 약 절반이 되어야 한다.
- 동일 국가의 `라벨 실제 화면 폭 / 유효 국토 실제 화면 폭` 비율이 연속된 정상 사용 줌에서 안정적이어야 한다.
- 최소 가독성을 위해 글자만 고정 px로 유지하지 않는다. 작으면 피처별 `minZoom` 아래에서 숨긴다.
- 안전 상한이 필요하면 일반적으로 사용하는 저·중·고 검증 줌보다 높은 구간에서만 발동해야 한다. 호주 검증 구간 안에서 상한이 발동하면 실패다.
- 특정 전역 px 상한값을 먼저 정해 테스트를 맞추지 않는다. geometry 점유율, 실제 폰트 metric, baseline 길이와 일반 카메라 사용성을 근거로 정책을 도출한다.
- 레이어 선언과 `map.load`에서 서로 다른 `text-size` 표현식으로 중복 설정하지 않는다.
- 큰 curved line과 소국가 Point 폴백 모두 같은 world-space 원칙을 사용한다.
- 특정 국가만 `showOnlyCountryLabel()`로 강제한 화면뿐 아니라 정상 초기 세계 지도에서도 주요 국가명이 읽혀야 한다.
- 확대 스크린샷은 대상 국가 geometry가 화면 전체를 단색으로 덮는 비정상 카메라가 아니라 주변 국가와 해안선이 함께 보이는 일반 사용 구도를 사용한다.
- 호주·러시아·캐나다·미국·중국 중 최소 2개 대형 curved 국가에서 실제 확대 비율을 측정한다. 호주는 필수다.
- 테스트의 `fontSize`와 `estimatedWidth`만 자체 계산식으로 산출하지 말고, 실제 렌더 glyph 또는 렌더러가 제공하는 실제 배치 bounds를 측정한다.
- 같은 줌에서 라벨의 raw 존재 여부뿐 아니라 화면상 폭이 실제로 증가하는지 검증한다.

#### MapLibre 제약 해결 절차

다음 대안을 순서대로 비교하고 선택 근거와 실패 근거를 보고한다.

1. 국가명 전용 GeoJSON source의 tile 구성, `maxzoom`, buffer와 짧은 단일 baseline을 조정해 현재 줌에 맞는 anchor가 계산되는지 검증한다.
2. 줌 구간별로 동일 국가가 정확히 한 레이어에만 속하도록 배타적인 line layer/source 구성을 검토한다. 각 구간은 그 구간에 필요한 제한된 `text-size` 범위만 가져야 하며 경계 줌 raw 중복이 없어야 한다.
3. MapLibre line symbol로 목표를 만족할 수 없으면 국가명 전용 Canvas/WebGL renderer를 사용한다. geometry-derived baseline과 glyph tangent, world-space 크기, raw 1개 계약은 그대로 유지한다.

다음 우회는 금지한다.

- 정상 사용 구간에서 발동하는 낮은 전역 px 상한
- Point 라벨 또는 `line-center`로 대형 curved 라벨 대체
- CSS transform이나 전체 문자열 `text-rotate`
- `showOnlyCountryLabel()`만 사용한 증거
- 논리적 dedupe나 opacity로 raw 중복 은폐
- 바티칸·모나코 등 소국가 수치로 호주 게이트 대체

#### 수치 게이트

- 호주 실제 curved glyph의 연속 정상 줌 `+1` 화면 폭 증가율: `1.9~2.1`
- 같은 호주 실제 glyph의 `-1` 화면 폭 감소율: `0.48~0.52`
- 호주 실제 `라벨 화면 폭 / 유효 국토 화면 폭` 비율 drift: `0.03 이하`
- 두 번째 대형 curved 국가의 `+1`, `-1`, 폭 비율 drift도 같은 기준을 만족해야 한다.
- 호주 저·중·고 스크린샷 구간에서 글자 크기가 동일한 값으로 고정된 샘플이 2개 이상이면 실패다.
- 초기 세계 지도에서 `USA`, `RUS`, `CHN` 중 정책상 표시 대상이 실제 렌더되어야 한다.
- `minZoom` 이전 raw 0개, 이후 월드 복사본당 raw 1개여야 한다.
- 각 측정 줌에서 대상 대형 국가의 raw 라벨은 월드 복사본당 정확히 1개여야 한다.

#### 검증 방식

- 관련 world-space 순수 함수 unit test
- renderer별 크기 식과 줌 구간 배타성 unit test
- R3 전용 Playwright E2E
- 실제 렌더 bounds 또는 glyph bounds 기반 수치 보고
- 초기 세계 화면과 호주·두 번째 대형 국가의 일반 카메라 스크린샷
- 테스트 후 개발 서버와 worker 종료 확인

기존 R3 테스트 중 실패 진단용 또는 중복된 임시 spec은 정리하고, 하나의 권위 있는 R3 E2E만 남긴다.

### 8A-1. 렌더 필터와 데이터 계약 복구

#### 구현 범위

- curved baseline 피처의 `placementMode`와 `WorldMap.tsx`의 초기 필터, zoom 필터, `showOnlyCountryLabel()` 필터를 하나의 일관된 값으로 통일한다.
- 문자열을 여러 위치에 직접 반복하지 말고 가능한 경우 공용 상수 또는 공용 filter builder를 사용한다.
- 큰 영토 curved line 라벨과 소국가 Point 폴백의 대상 집합이 완전히 배타적이고 합집합이 전체 국가 집합인지 검증한다.
- 기존 `country-labels-2020.geojson`에 전체 256개 Point 계산 결과를 메타데이터로 유지할 수는 있지만, 실제 렌더 레이어에서는 큰 국가 Point와 curved line이 동시에 활성화되면 안 된다.
- `map-data.test.ts`, 기존 fix07 validator와 최종 감사의 “baseline 256개” 계약을 새 구조에 맞게 명시적으로 갱신한다.

새 데이터 계약은 다음과 같아야 한다.

```text
전체 국가 ID 집합
  = curved line ID 집합 ∪ Point 폴백 ID 집합

curved line ID 집합 ∩ Point 폴백 ID 집합
  = 빈 집합
```

단순히 테스트의 기대값을 `182`와 `74`로 하드코딩하지 않는다. 현재 생성된 입력에서 각 집합과 합집합을 계산해 검증한다.

#### 완료 게이트

- 초기 줌에서 `USA`, `RUS`, `CHN`의 raw 라벨이 각각 1개 이상 존재해야 한다.
- 일반 curved 국가와 프로토타입 curved 국가가 올바른 source와 layer에서 렌더링돼야 한다.
- `showOnlyCountryLabel("DEU")`와 대표 프로토타입 국가가 각각 정상 표시돼야 한다.
- 바티칸·모나코 등 소국가는 Point 폴백 layer에서만 표시돼야 한다.
- 관련 unit test가 모두 통과해야 한다.
- 이 단계에서는 곡률 품질이나 윤곽선 픽셀 결과를 PASS로 주장하지 않는다.

### 8A-2. 곡선 계산과 전체 국가 품질 복구

#### 구현 범위

- 대표 6개국뿐 아니라 curved line 대상 전체를 검사한다.
- 모든 curved baseline은 13~25개 좌표를 가져야 한다.
- 모든 좌표는 유한한 경도·위도여야 한다.
- 실제 곡률이 0인 `NAM`, `UZB`와 그 밖의 직선 결과를 검출하고 처리한다.
- 기존 품질 기준인 `baselineInsideRatio >= 0.9`를 유지한다. 기준을 0.75로 낮추지 않는다.
- 곡률 후보가 0.9 기준을 만족하지 못하면 baseline 폭, 곡률 크기, 곡률 방향 또는 anchor 후보를 함께 재평가한다.
- 억지로 큰 곡률을 선택해 footprint 또는 가독성을 손상하지 않는다.
- `previousBaseline`이 전달되면 이전 baseline과 후보 사이의 실제 위치·진행 방향·곡률 차이를 측정해 안정성 점수에 반영한다.
- 이전 baseline 존재 여부만 확인하는 형식적 벌점은 허용하지 않는다.

#### 전체 validator 필수 항목

각 curved line 국가에 대해 다음 값을 기록한다.

- `countryId`
- 좌표 수
- signed curvature와 절댓값
- baseline 길이
- `baselineInsideRatio`
- `insideRatio`
- `shapeClass`
- 선택 component
- 이전 layout 대비 anchor 이동량
- 이전 layout 대비 angle 변화량
- 이전 baseline 대비 곡률 변화량
- 통과 여부와 실패 사유

validator는 실패 국가 목록을 생략하지 않는다. 일부 대표국만 통과했다고 전체 PASS를 출력해서는 안 된다.

#### 완료 게이트

- curved line 대상 전체의 좌표 수가 13~25개여야 한다.
- 모든 curved line 대상이 합의된 최소 곡률보다 커야 한다. 최소값과 단위를 보고서에 명시한다.
- 전체 curved line 대상이 `baselineInsideRatio >= 0.9`를 만족해야 한다.
- 기존 shapeClass별 footprint 기준을 유지해야 한다.
- 동일 입력은 결정적으로 동일한 결과를 내야 한다.
- geometry 변경 입력에서는 `geometryHash`와 관련 layout이 재계산돼야 한다.
- 국가별 곡선 좌표 override가 없어야 한다.

### 8A-5. 8A 통합 회귀 감사

#### 실행 항목

1. 전체 지도 데이터 재생성
2. 8A-1~8A-4 validator 재실행
3. 전체 unit test
4. lint
5. production build
6. 8A 관련 제한 Playwright
7. 필수 JSON과 스크린샷 존재·내용 검사
8. 개발 서버와 Playwright worker 종료 확인

#### 판정 규칙

- 모든 필수 명령의 종료 코드가 0이어야 한다.
- lint warning은 새로 추가된 것인지 구분해 보고하고 가능한 경우 제거한다.
- build의 EPERM, `.next` lock, trace 쓰기 실패는 PASS가 아니라 BLOCKED다.
- `pending-e2e`, `configured`, `requires screenshot` 상태의 보고서는 완료 산출물로 인정하지 않는다.
- 단위 테스트 하나라도 실패하면 8A는 FAIL이다.
- 실제 렌더 라벨이 0개면 정적 validator 결과와 무관하게 8A는 FAIL이다.
- 필수 스크린샷이 없거나 픽셀 감사가 없으면 윤곽선 요구사항은 미검증이다.
- 모든 게이트가 통과한 경우에만 8A 완료를 보고한다.

### 곡선 데이터와 계산 요구사항

- `country-label-baselines-2020.geojson`을 실제 큰 영토 라벨의 렌더 source로 사용한다.
- baseline 피처에는 `countryId`, `mapLabelKo`, `nameEn`, `fontSizeWorldUnits`, `letterSpacing`, `priority`, `minZoom`, `placementMode`, `insideRatio`, `baselineInsideRatio`, `geometryHash`를 포함한다.
- geometry는 점 두 개짜리 직선이 아니라 권장 13~25개 점으로 샘플링한 `LineString`이어야 한다.
- 기존 `computeCountryLabelLayout()`이 계산한 anchor, angle, width, height와 component 선택 결과를 재사용한다.
- 곡률은 영토의 가용 높이와 라벨 폭에서 자동 계산하고, baseline 내부 비율을 후보 평가에 포함한다.
- 급격한 꺾임, S자 왜곡, 뒤집힌 글자를 만들지 않는다.
- 호주·러시아 등 특정 국가의 곡선 좌표를 직접 작성하지 않는다.
- 소국가는 기존 Point symbol을 폴백으로 유지한다.
- 큰 국가 line 라벨과 소국가 Point 라벨 필터는 배타적이어야 한다.

곡선 계산은 다음과 동등한 순수 함수 경계를 갖는다.

```ts
type CurvedBaselineInput = {
  countryId: string;
  geometry: PolygonGeometry;
  anchor: Position;
  angle: number;
  width: number;
  availableHeight: number;
  previousBaseline?: Position[];
};

function computeCurvedCountryBaseline(
  input: CurvedBaselineInput
): {
  type: "LineString";
  coordinates: Position[];
};
```

단순 포물선부터 시작할 수 있지만 실제 영토 내부 비율을 측정하지 않고 고정 곡률만 적용해서는 안 된다.

### MapLibre 렌더링 요구사항

큰 영토 라벨은 baseline GeoJSON source의 line symbol로 렌더링한다.

```ts
layout: {
  "symbol-placement": "line",
  "text-field": ["get", "mapLabelKo"],
  "text-font": ["Open Sans Regular"],
  "text-size": worldSpaceSizeExpression,
  "text-letter-spacing": ["get", "letterSpacing"],
  "text-max-angle": 35,
  "text-rotation-alignment": "map",
  "text-pitch-alignment": "map",
  "text-keep-upright": true,
  "symbol-spacing": 1000
}
```

- line 라벨에서는 기존 `text-rotate: ["get", "angle"]`를 제거한다. 경로 자체가 glyph 방향을 결정해야 한다.
- 긴 LineString의 타일 분할 때문에 동일 국가명이 중복되는지 raw rendered feature로 검증한다.
- MapLibre line symbol이 월드 복사본당 단일 라벨을 보장하지 못하면 짧은 단일 baseline, 전용 source, Canvas/WebGL custom layer 등을 비교하고 증거를 남긴다.
- 눈으로 하나처럼 보이게 숨기는 것이 아니라 raw 렌더 결과에서도 논리적 중복이 없어야 한다.

### 표기 언어

- 기본 지도 표기는 기존 정책대로 `mapLabelKo`를 유지한다.
- 참고 이미지와 비슷하게 만들기 위해 모든 국가명을 영문으로 바꾸지 않는다.
- 한글 실제 폰트 metric에 맞춰 곡률·크기·자간을 계산한다.
- 추후 영문 표시 옵션을 추가할 수 있도록 `nameEn`은 baseline 피처에 포함한다.

### 시각 요구사항 — R5가 최종 권위

- 국가명 glyph 내부 fill은 완전한 흰색이어야 한다.
- 국가명의 주 테두리도 흰색이어야 한다.
- 기존의 어두운 halo를 주 테두리로 사용하지 않는다.
- 일반국, 프로토타입 국가, 소국가 레이어에 같은 원칙을 적용한다.
- 선택·hover·플레이 강조 상태에서도 텍스트가 복제되거나 내부가 채워지면 안 된다.
- 바다와 육지 양쪽에서 윤곽선이 식별 가능해야 한다.
- 확대 시 윤곽선 두께가 글자 크기에 비해 지나치게 얇아지거나 굵어지지 않아야 한다.

### 구현 주의사항

MapLibre symbol의 `text-color`와 `text-halo-color`를 모두 흰색으로 설정하는 방식부터 검토한다. 단순히 색상 문자열만 바꾸고 완료하지 말고 실제 렌더 결과를 확인한다.

MapLibre SDF 렌더 특성상 원하는 흰색 내용과 흰색 테두리가 정확히 나오지 않으면 다음 대안을 비교한다.

- 동일 위치의 두 symbol layer 조합
- outline 전용 glyph 또는 별도 glyph atlas
- 국가명 전용 Canvas/WebGL custom layer

기술 선택은 국가당 단일 논리 라벨 원칙과 raw 중복 검증을 깨면 안 된다. 시각 효과를 위해 동일 텍스트를 두 레이어에 중복 렌더한다면 raw API가 이를 논리적 1개로 숨겨서는 안 되므로, 가급적 실제 symbol 인스턴스 하나로 해결한다.

### 완료 게이트

- 호주를 포함한 대표 대형국의 glyph가 실제 곡선을 따라 배치돼야 한다.
- 단순히 전체 문자열이 한 각도로 회전한 결과여서는 안 된다.
- curved baseline과 라벨 footprint가 국가별 품질 기준을 만족해야 한다.
- 큰 국가 line 라벨과 소국가 Point 폴백이 동시에 표시되지 않아야 한다.
- 글자 내부 픽셀이 지도 배경을 실제로 투과해야 한다.

- 선택·hover·플레이 강조 전후 raw 라벨 수가 변하지 않아야 한다.

## 8B. 공식 국호 기반 지도 표시명

### 목적

다음 국가의 지도 표시명을 변경한다.

```text
CHN: 중국 → 중화인민공화국
PRK: 북한 → 조선민주주의인민공화국
USA: 미국 → 미합중국
```

### 데이터 원칙

- 지도 라벨의 원본인 `mapLabelKo`를 변경한다.
- `nameKo`도 공식 국호와 다르면 같은 공식 국호로 정렬한다.
- `nameEn`, ISO3, 국가 ID, flagCode, 플레이 가능 여부는 변경하지 않는다.
- 검색 편의를 위해 기존 짧은 이름 `중국`, `북한`, `미국`은 검색 alias로 유지한다.
- 짧은 이름을 유지하기 위해 지도 라벨만 별도 하드코딩하는 이중 경로를 만들지 않는다.
- 데이터 생성 후 metrics, Point label, baseline, layout report를 모두 재생성한다.
- 큰 영토의 baseline은 8A에서 구현한 curved `LineString`으로 재생성한다.

### 알고리즘 요구사항

이름이 길어졌으므로 기존 anchor와 크기를 그대로 재사용하지 않는다. 동일 shape-aware 함수가 새 실제 텍스트 폭을 입력으로 받아 다음을 다시 계산해야 한다.

- fontSizeWorldUnits
- targetTextWidthWorld
- letterSpacing
- anchor
- angle
- 곡률과 curved baseline
- footprint
- insideRatio와 baselineInsideRatio
- confidence와 minZoom

국가별 fontScale이나 좌표 override를 새로 추가해 맞추지 않는다.

### 완료 게이트

- 지도 화면에 정확한 공식 국호가 표시돼야 한다.
- 검색에서 공식 국호와 기존 짧은 이름이 모두 해당 국가를 찾아야 한다.
- 세 국가의 anchor가 자국 영토 내부여야 한다.
- mainland 기준 `insideRatio >= 0.85`를 만족해야 한다.
- baselineInsideRatio가 기존 기준을 만족해야 한다.
- 이름 변경 후에도 월드 복사본당 raw 라벨 하나를 유지해야 한다.
- 공식 국호가 curved baseline을 따라 렌더링돼야 한다.
- 확대 전후 라벨/국토 점유 비율이 안정적이어야 한다.
- 기존 대한민국 표기와 다른 국가 데이터가 우발적으로 바뀌지 않아야 한다.

## 8C. Southern Patagonian Ice Field 제거 및 아르헨티나 병합

### 정확한 대상

사용자가 말한 “사우던 파타고니안 아일랜드”의 실제 Natural Earth 대상은 다음 기술 지도 단위다.

```text
ADM0_A3: SPI
SOV_A3: SPI
NAME: Southern Patagonian Ice Field
한국어: 사우던 파타고니안 아이스 필드
TYPE: Indeterminate
NOTE_BRK: Claimed by Chile and Argentina; under survey
ADM0_A3_AR: ARG
```

8차 작업에서는 현재 프로젝트의 단일 2020 OTL 지도 정책으로 `SPI → ARG` 병합한다.

### 작업 범위

- 1:10m 국가 geometry에서 SPI를 ARG에 union/dissolve한다.
- 저해상도 데이터에 SPI가 별도 존재하면 같은 정책을 적용한다.
- SPI와 ARG 사이 내부 seam을 국가 경계에서 제거한다.
- SPI 독립 metadata를 생성하지 않는다.
- SPI를 검색·선택·플레이 국가·라벨·baseline·small marker·capital·Admin 1의 독립 국가로 노출하지 않는다.
- SPI 영역을 클릭하면 ARG가 선택돼야 한다.
- ARG의 shape-aware 라벨은 병합된 새 geometry로 재계산한다.
- ARG의 curved baseline도 병합된 새 geometry로 재계산한다.
- 원본 Natural Earth 파일 자체를 파괴적으로 수정하지 말고 생성 파이프라인에서 결정적으로 병합한다.

이 항목은 정적 2020 OTL 데이터 정제 작업이다. 일반적인 런타임 영토 이전 시스템으로 확대 구현하지 않는다.

### 데이터 감사 항목

- 병합 전 SPI geometry 존재 확인
- 병합 후 ARG geometry hash 변경 확인
- 최종 국가 수 감소량 확인
- SPI 독립 Point/baseline/metadata 0개 확인
- ARG 면적 증가 확인
- SPI-ARG 내부 seam 0개 확인
- 생성 보고서에 제거 이유와 병합 대상을 기록

### 완료 게이트

- 최종 생성물 어디에도 독립 국가 ID `SPI`가 남지 않아야 한다. 단, 제거 감사 보고서와 원본 데이터 참조는 예외다.
- SPI 영역의 최종 countryId는 ARG여야 한다.
- SPI 영역 클릭 결과도 ARG여야 한다.
- ARG anchor와 footprint 품질 기준이 유지돼야 한다.
- 칠레 geometry를 우발적으로 변경하지 않아야 한다.
- 기존 KAS→IND, KAB→KAZ 병합과 다른 경계 정제 기능이 유지돼야 한다.

- `screenshots/fix08-spi-after.png`

## 후속 단계 참고: 신생국 생성 파이프라인 및 순수 계산 테스트

> **8차 작업에서는 이 절과 다음 신생국 렌더링 절을 실행하지 않는다.** 아래 내용은 후속 프롬프트를 작성할 때 사용할 요구사항 초안이다. 8차 완료 게이트와 산출물에 포함하지 않는다.

### 목적

향후 전쟁·조약·분할·합병으로 기존 목록에 없던 새 국가가 생성됐을 때 라벨 시스템이 정상 동작하는지 검증한다.

실제 2020 OTL 데이터에 가짜 국가를 영구 추가하지 않는다. 테스트 중에만 synthetic country를 생성한다.

### 신생국 입력 예시

```ts
type GeneratedCountryInput = {
  countryId: string;
  geometry: GeoJSON.Polygon | GeoJSON.MultiPolygon;
  nameKo: string;
  nameEn: string;
  mapLabelKo: string;
  playable: boolean;
  previousLayout?: CountryLabelLayout;
};
```

필요하면 동등한 인터페이스를 설계하되 DOM, React, MapLibre 객체에 의존하지 않는다.

### 필수 생성 시나리오

1. 기존 국가에서 연속된 일부 영토를 분리해 새 국가 생성
2. 서로 떨어진 두 Polygon으로 된 신생국 생성
3. 가늘고 긴 신생국 생성
4. 군도형 신생국 생성
5. 두 기존 국가의 일부 영토를 합쳐 새 국가 생성
6. 긴 한글 공식 국호를 가진 신생국 생성

### 필수 검증

- 기존 256개국 또는 특정 고정 국가 ID 목록에 없어도 계산돼야 한다.
- 새 countryId가 Point label, baseline, layout report에 생성돼야 한다.
- anchor가 새 geometry 내부여야 한다.
- shapeClass가 geometry로부터 결정돼야 한다.
- 해당 shapeClass의 insideRatio 기준을 만족해야 한다.
- 실제 font metric으로 긴 한글 이름을 측정해야 한다.
- geometry hash와 cacheKey가 생성돼야 한다.
- 같은 입력은 결정적 결과를 내야 한다.
- geometry 변경 후 hash와 layout이 재계산돼야 한다.
- 변경된 신생국만 재계산하고 기존 국가 캐시를 무효화하지 않아야 한다.
- 삭제 후 Point, baseline, cache entry가 남지 않아야 한다.

### 고정 개수 의존성 제거

기존 validator가 `countryCount === 256`을 완료 조건으로 사용하더라도, 런타임 또는 테스트용 동적 경로는 `256 + 생성국 수 - 삭제국 수`를 처리할 수 있어야 한다.

2020 OTL 정적 생성물의 기준 개수와 동적 시뮬레이션 상태의 개수를 구분한다.

```text
정적 2020 OTL 검증: 기준 데이터의 기대 개수 사용 가능
동적 신생국 검증: 입력 상태에서 기대 개수를 계산해야 함
```

### 완료 게이트

- 6개 신생국 시나리오가 국가별 좌표 override 없이 통과해야 한다.
- 기존 국가 ID allowlist 없이 새 ID를 처리해야 한다.
- 생성·geometry 변경·삭제 생명주기를 모두 검증해야 한다.
- 기존 국가 layout이 불필요하게 재계산되지 않아야 한다.
- 직렬화 가능한 Worker 요청/응답으로 처리 가능해야 한다.

### 산출물

- `reports/fix08-generated-country-algorithm.json`

## 후속 단계 참고: 신생국 실제 렌더링 및 raw 중복 검증

- 표시 이름이 정확한 공식 국호여야 한다.
- 글자 내용과 주 테두리가 모두 흰색이어야 한다.
- 기존 주변 국가의 geometry와 라벨이 손상되지 않아야 한다.

## 현재 첫 실행 지시

R1/R2의 PASS 보고서와 기존 R3 실패 구현·보고서·스크린샷을 감사한 뒤 `8A-R3. world-space 확대·축소와 초기 지도 가시성`만 다시 수행한다.

기존 `25.6px` 상한과 기존 R3 PASS 판정을 권위 있는 완료 상태로 취급하지 않는다. 호주와 두 번째 대형 curved 국가의 실제 렌더 bounds를 같은 국가의 연속 정상 줌에서 측정하고, polygon 화면 폭과 함께 증가하는지 검증한다. MapLibre `textMaxSize` 제약은 source/layer 구간 분리 또는 국가명 전용 Canvas/WebGL renderer까지 비교해 해결한다.

R3가 끝나면 새 보고서와 새 스크린샷, 실제 bounds 수치, 실행 명령별 종료 코드를 보고하고 반드시 종료한다. 사용자 확인 없이 R4, R5, R6, 8B 또는 8C로 넘어가지 않는다. 실제 신생국 게임 이벤트와 런타임 국경 변경 UI는 8차에서 구현하지 않는다.
